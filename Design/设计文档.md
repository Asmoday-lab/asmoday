# Asmoday (空间执政) 产品与系统设计白皮书

**版本**：v1.9.0 (终极全量版，包含音量记忆、生态推荐、极细防坑规范)  
**定位**：专为低功耗 64 位设备（ARM64 / x86_64）设计的、单二进制的个人媒体与设备控制中枢。

---

## 1. 项目概述与核心边界

### 1.1 背景与痛点
传统的自托管（NAS / 软路由 / 开发板）通常采用 `FileBrowser + ttyd + Nginx 反代 + 聚合页` 的拼装架构，导致以下问题：
1. **维护割裂**：新增服务需同步修改 Nginx 配置、聚合页 HTML，操作繁琐。
2. **体验断层**：文件管理与终端相互独立，无法实现“在指定目录一键打开终端”。
3. **安全隐患**：公网暴露风险高，各服务缺乏统一鉴权。
4. **资源浪费**：多进程并行，占用不必要的内存与 CPU。

### 1.2 产品定位
**Asmoday** 是一个前后端分离开发、单体二进制发布的极简控制中枢。它只负责核心的文件、媒体与终端展示，拒绝任何重型功能。为了保证极致的编译与运行效率，**全面放弃 32 位架构（如 ARMv7），只专注于现代 64 位平台（ARM64, x86_64）**。

### 1.3 核心克制原则与红线
1. **绝不内置多媒体转码**：拒绝在服务端运行 FFmpeg 进行视频转码，仅依赖浏览器客户端播放能力。
2. **绝不内置刮削与 AI**：不联网抓取影视海报，不提取内封字幕，不搞任何语义/人脸识别。
3. **绝不自研同步与 App**：不自建同步协议，强制引导用户使用 WebDAV 或第三方同步工具（如 Syncthing）。
4. **绝不依赖外部 CDN**：前端所有静态资源（包括各种代码高亮语言包、终端库）全量打包进二进制，**拒绝任何形式的公网 CDN 外链**，确保在内网断网环境下的绝对可用性和毫秒级加载速度。
5. **绝不留下免密后门**：严禁在配置文件提供“关闭认证”的开关。忘记密码必须通过 CLI 命令行或物理删除数据重置，确保系统在任何配置文件泄露的情况下都不会直接裸奔。
6. **绝不接管重型任务**：不内置 BT 下载器、不内置在线办公套件，通过“生态推荐页”引导用户搭配外部工具。

### 1.4 AI 防幻觉与版本铁律（最高优先级）
1. **严禁擅自降级依赖**：遇到 API 报错，**绝对不允许**将库降级到旧版本（如把 Video.js 10 降级到 v8）。必须查阅最新版官方文档重构代码。
2. **严禁使用过时的废弃 API**：必须严格遵循新版库的架构（如 Axum 0.7+ 的 `axum::serve`，CodeMirror 6 的模块化 API，Video.js 10 的 Web Components）。
3. **严禁前端硬编码文本**：所有的界面文本、按钮、提示语，**必须**通过 `vue-i18n` 的 `$t('key')` 方式渲染。绝对禁止在 `.vue` 文件或 `.ts` 文件中直接写死中文字符串。

## 2. 技术架构与选型

### 2.1 总体架构
* **后端**：Rust 语言，基于 `axum` (0.7+) 异步 Web 框架。通过 `rust-embed` 将前端产物打包入单文件。
* **前端**：Vue 3 + Vite + TailwindCSS (v4)。
* **跨平台**：通过 Rust 交叉编译，产出主流 64 位系统（Windows x64、macOS ARM64/x64、Linux x86_64/ARM64）独立的单二进制文件。

### 2.2 核心依赖库与规范
* **Web 框架**：`axum` (0.7+)。**严禁**使用旧版 `axum::Server`，必须用 `axum::serve`。
* **PTY 终端**：`portable-pty`（跨平台拉起真实伪终端）。
* **系统目录获取**：`dirs`（用于跨平台获取主目录 `~`）。
* **数据库**：`rusqlite`（自带 `bundled` 特性，免系统依赖），**系统启动时必须开启 WAL 模式**（执行 `PRAGMA journal_mode=WAL;`）。
* **配置解析**：`toml` 库（替代 YAML，提供强类型与显式语法）。
* **网络代理**：`hyper` / `reqwest`（用于内部网关透传）。
* **前端终端**：`xterm.js` + `xterm-addon-fit`。
* **前端编辑器**：`CodeMirror 6`。**严禁**使用 v5 的 `fromTextArea` 或全局 `CodeMirror` 对象，必须按需引入 `@codemirror/state`, `@codemirror/view` 及具体语言包。
* **前端播放器**：`Video.js 10`。**严禁**使用 v8 的 `videojs()` 函数 API，必须使用基于 Web Components 的 `@videojs/html` 自定义元素（如 `<video-player>`）。
* **前端多语言**：`vue-i18n` (v9+)。用于全局文本管理。
* **CSS 框架**：`TailwindCSS v4`。通过 Vite 插件配置，废弃 `tailwind.config.js`，统一在 CSS 中使用 `@import "tailwindcss"`。

### 2.3 前端资源加载与防白屏策略
* **Vite 代码分割 (Code Splitting)**：前端在引入 `CodeMirror` 语言包、`Video.js`、`xterm.js` 等重型组件时，全面使用 ES Module 的 `import()` 动态导入语法。
* **无感内嵌**：Vite 打包出的所有 chunk 文件，均被 `rust-embed` 吸入二进制文件中。坚决不向用户提供“自定义 CDN 源”选项。
* **静态资源缓存 (Cache-Control)**：
    * 带 Hash 的静态文件（如 `main.a1b2.js`、`index-xxx.css`）设置长达一年的强缓存。
    * **`index.html` 必须设置 `Cache-Control: no-cache`**，防止前端更新后用户浏览器加载旧代码导致白屏。

### 2.4 SPA 单页应用路由 Fallback 规范
* **强制规则**：所有 `/api/*` 路由之外的无匹配请求，如果后端找不到对应的静态资源文件，**必须 Fallback 返回内嵌的 `index.html`**，绝不可直接返回 404。
* **例外**：只有 `/api/*` 的路由在找不到资源或报错时才返回 404 JSON。

## 3. 详细功能模块设计与工程细节

### 3.1 身份认证、安全与初始化 (Auth & Security)
* **初次运行初始化策略**：
    * **默认路径（交互式向导）**：首次通过浏览器访问时，强制进入极简初始化页面，引导用户自行设置管理员账号与高强度密码。
    * **自动化路径（日志一次性密码）**：在纯 CLI 或容器化脚本部署时（使用 `--init` 参数启动），程序自动生成高强度的随机密码并打印至控制台日志中。用户首次登录后强制要求修改密码。
* **密码遗忘与重置机制（防后门设计）**：
    * **严禁**在配置文件（`config.toml`）中提供“无密码/关闭认证”的静态开关。
    * 重置密码必须通过系统级操作（CLI `--reset-password` 或 Docker 环境变量 `ASMODAY_RESET_PASSWORD`）证明权限。
* **会话管理**：登录后下发 `HttpOnly` Cookie，全站 API 与 WebSocket 必须经 Auth 中间件拦截。
* **双重认证 (2FA)**：可选开启 TOTP（基于时间的一次性密码），开启后登录需输入动态码。
* **防爆破机制**：基于内存的 IP 计数器，连续 5 次密码错误封禁该 IP 15 分钟。
* **WebDAV 独立凭证 (App Token)**：严禁使用主密码挂载 WebDAV。支持生成带前缀（如 `asm_`）的 Token，可设置“有效时间”与“只读/读写”权限，数据库仅存哈希值。
* **反向代理兼容性**：
    * 支持信任 `X-Forwarded-For` / `X-Real-IP`（结合 `trusted_ips` 白名单），确保获取真实 IP。
    * 支持 `X-Forwarded-Proto` 和 `X-Forwarded-Host`，确保生成的动态 URL 协议正确。
    * 支持 `base_url` 子路径部署，前端 Router 与后端路由自动处理路径前缀。
* **双向 SSO 架构**：
    * **“座上宾”模式（被外部接入）**：信任反向代理传递的 Header（如 `X-Forwarded-User`），通过白名单限制来源，实现外部 IdP 免密跳转。
    * **“大内总管”模式（代理外部服务）**：反代时支持 `Header 注入`；或通过 `Cookie 作用域重写`，隔离多服务 Session。
* **安全纵深与 XSS 防范**：
    * 前端绝不使用 `v-html` 渲染不可信内容。
    * 后端保存文件名时，严格过滤危险字符，并强制执行 **路径穿越（Path Traversal）校验**，防止 `../` 攻击。
    * 图床/分享直链必须校验 Token 有效性。

### 3.2 文件管理 (Files - 极简无树设计)
* **视图布局（无目录树）**：彻底放弃传统的左侧常驻目录树，最大化释放横向空间，完美适配移动端。
    * **根入口**：进入“文件管理”时，主区域平铺展示所有配置的挂载点（卡片式）。
    * **层级浏览**：点击挂载点进入后，主区域展示文件列表/网格。顶部使用 **面包屑导航（Breadcrumb）** 来支持层级回退和跳转。
* **大文件流式传输与防 OOM（内存溢出）**：
    * **上传**：必须使用流式处理，**严禁将整个文件读入内存**。接收分块时直接流式落盘。
    * **下载/播放**：必须支持 HTTP Range（断点续传），使用 `tokio::io::copy` 流式响应。
* **跨平台路径安全**：后端统一使用 Rust `std::path::Path` 处理路径。前端统一传 POSIX 风格的 `/`，后端自动转换为系统原生路径。
* **大目录性能防卡死**：
    * 后端针对超过 1000 个文件的目录**强制分页截断**，返回 `has_more: true` 标记。
    * 前端配合分页加载或使用**虚拟列表（Virtual DOM）**，只渲染视口内的文件 DOM。
* **内置代码编辑器**：双击文本文件，无缝切换为 `CodeMirror 6`，按需加载高亮语言包，支持手动切换语言。
* **轻量搜索**：仅限当前目录下的文件名模糊匹配。前端防抖，后端按需遍历目录。
* **多端文件上传**：
    * **PC 端**：支持全屏拖拽出现遮罩，右下角提供实时上传进度。
    * **移动端**：不支持 HTML5 拖拽，降级为点击“上传”按钮，唤起系统原生文件选择器。
* **右键菜单**：集成“在此终端中打开”、“分享”、“复制图床直链”、“删除”等高频操作。

### 3.3 终端联动 (Terminal)
* **跨平台 Shell 与默认主目录解析（高优防坑）**：
    * **禁止前端传递 `~`**：前端在未指定具体目录时，`path` 参数传空字符串或省略。
    * **后端兜底解析**：Rust 后端接收到空 `path` 时，必须调用 `dirs::home_dir()` 获取真实主目录（Linux 下为 `/home/user`，Windows 下为 `C:\Users\user`）。
    * **Shell 唤醒策略**：
        * Unix/Linux：读取 `$SHELL` 环境变量，回退至 `bash`。
        * Windows：默认拉起 `powershell.exe`（或使用 `portable-pty` 默认支持的 ConPTY）。
    * **路径分隔符转换**：若前端传入 POSIX 风格的路径（如 `C:/Users/...`），后端需使用 `PathBuf::from()` 自动转成 Windows 原生反斜杠路径，防止拉起失败。
* **PTY 直通**：真正的系统底层 Shell（非模拟环境），支持运行 Vim、Top 等全屏应用。
* **PTY 连接数限制（防雪崩）**：后端必须维护 PTY 连接池，**限制单用户最大并发的 PTY 会话数（如最多 10 个）**。防止前端死循环重连导致设备 CPU 瞬间被 Shell 进程打满。
* **断线保活（WSS Reconnect）**：
    * 后端维护 PTY 进程池。当 WebSocket 因网络波动断开时，**PTY 进程延迟 3 分钟再销毁**。
    * 前端重连时，带上 `SessionID`，后端直接把缓冲区数据推给前端，无缝恢复现场。
* **路径深度联动**：文件管理右键文件夹，一键跳转终端，并自动 `cd` 到该目录。
* **移动端键盘适配**：PC 端自动隐藏虚拟键盘。移动端复刻 Termux 的两行布局：
    * 第一行：`ESC`, `/`, `-`, `HOME`, `↑`, `END`, `PGUP`
    * 第二行：`TAB`, `CTRL`, `ALT`, `←`, `↓`, `→`, `PGDN`
    * **粘性修饰键**：点击 `CTRL` 会高亮，此时按下软键盘字母，前端拦截并转换为 ASCII 控制字符后再发送。

### 3.4 媒体画廊与缓存生命周期 (Gallery)
* **缩略图生成防雪崩机制**：
    * 引入**信号量（Semaphore）或任务队列**，限制后端同时生成缩略图的并发数（例如最多同时处理 2-4 张图片）。
    * 超出的请求直接返回占位图或稍后重试。
* **缩略图缓存生命周期管理（LRU 淘汰）**：
    * **存储结构**：缩略图存放于 `data/thumbnails/`，需按哈希进行多级目录散列。
    * **自动淘汰机制**：后台清理任务根据 `config.toml` 中的 `thumb_cache_max_size_mb`（总容量阈值）和 `thumb_cache_max_age_days`（过期天数）执行 LRU 淘汰，防止磁盘被撑爆。
    * **失效联动**：源文件 mtime 更新，缩略图必须失效重新生成。
    * **手动清理**：前端设置页提供“清理媒体缓存”按钮。
* **照片相册 (Photos)**：
    * **时间线**：按“年-月”分组的瀑布流，标题吸顶。引入主色调模糊占位图 (ThumbHash) 防抖动。
    * **相册**：按文件夹聚合的等高网格（4:3）。
    * **交互区分**：点击相册（文件夹）必须进入下一级路由；点击图片才触发灯箱。时间线展示**必须排除音频文件**，前端需按 MIME 分流。
* **影视库 (Cinema)**：
    * 完全基于文件夹结构展示，16:9 横版海报墙。
    * 不联网刮削，依赖外部可选配置的 FFmpeg 截取首帧作为封面。
    * **播放器选择**：按需动态引入 `Video.js 10`。使用 `@videojs/html` 自定义元素。支持外挂字幕（`.srt`/`.vtt`）。
* **音乐库 (Music)**：
    * 读取内嵌 ID3 标签（专辑、歌手、封面）。
    * 支持前端解析同目录下的 `.lrc` 歌词，并随播放进度滚动高亮。
    * **全局悬浮播放条 (Global Player Bar)**（置于页面最底部，跨路由持久存在）：
        * **左侧**：歌曲封面、歌名、歌手名（超长需 `truncate`）。
        * **中间控制区**：
            * **播放模式**：支持列表循环、单曲循环、随机播放。点击图标切换。
            * **切歌控制**：上一首、播放/暂停、下一首。
            * **进度条**：支持拖拽跳转，显示当前时间与总时长。
        * **右侧功能区**：
            * **音量控制**：PC 端提供音量滑块（Hover 展开或常驻），带静音切换图标；**移动端强制隐藏音量滑块**（由手机物理按键接管）。
            * **播放列表**：点击按钮从右侧（PC）或底部（移动端）滑出抽屉，展示当前播放队列，支持点击切歌、清空列表，高亮当前正在播放的歌曲。
            * **歌词开关**：点击后，在播放条上方展开大号歌词滚动面板。
* **全局音量记忆机制（防爆音）**：
    * **安全默认值**：全局音频与视频的初始播放音量，必须强制设定为 **35%**（0.35），严禁使用浏览器默认的 100% 导致深夜爆音。
    * **状态持久化**：用户调整音量后，必须将最新的音量值写入浏览器的 `localStorage`（例如 `localStorage.setItem('asm_volume', 0.65)`）。后续无论播放任何媒体，均优先读取此缓存。
    * **静音逻辑**：点击“静音”按钮时，记住静音前的音量。再次点击“取消静音”时，恢复到静音前的数值（而不是恢复到 35% 或 100%）。如果用户手动将滑块拖到 0，图标应自动变为静音状态。

### 3.5 Web UI 配置管理与设置页 (Config Management)
* **彻底抛弃 YAML**：采用 **TOML** 作为主配置格式。
* **双模编辑**：
    * **可视化表单**：在“设置”中提供图形化增删改查界面。
    * **源码模式**：点击“源码模式”，直接调用内置的 `CodeMirror 6` 打开 `config.toml`。
* **热重载**：前端保存配置后，Rust 后端利用 `notify` 库监听文件变更，自动重载内存中的配置，**无需重启进程**。
* **设置页精细化规范（分层与优先级）**：
    * **页面布局**：按功能分 Tab，如“通用（外观/语言）”、“媒体（FFmpeg/缓存）”、“安全（2FA/Token）”、“高级（源码模式）”。
    * **FFmpeg 路径优先级与探测**：
        * 优先级 1：设置页 UI 中手动指定的绝对路径。
        * 优先级 2：环境变量 `ASMODAY_FFMPEG_PATH`。
        * 优先级 3：系统 `PATH` 环境变量自动探测。
        * 交互：提供“状态检测”显示（✅ 已检测到 vX.X / ⚠️ 未找到），输入框支持“测试连通性”按钮。
    * **恢复默认配置策略**：
        * **严禁**“一键清空所有数据”（绝对不碰 SQLite 数据库）。
        * **分区块重置**：在“通用”、“媒体”等面板底部提供“恢复当前面板默认值”按钮。
        * **配置文件隔离**：`config.toml` 中的高级配置（如 `[[services]]`、`[[system.mounts]]`）**绝不**被普通表单的重置操作覆盖，用户必须通过源码模式或直接编辑文件进行修改。

### 3.6 服务聚合面板 (Service Hub)
* **配置驱动**：支持在 `config.toml` 或 UI 中定义外部服务卡片。
* **智能反向代理 (Smart Proxy)**：
    * **零配置透传**：内置 Rust `hyper` 代理引擎，自动处理 `Host`、`WebSocket Upgrade`，并自动剥离 `X-Frame-Options` 以允许 `iframe` 嵌入。
    * **高级选项**：仅提供 `剥离路径前缀`、`重写内部绝对链接（防老旧后台白屏）` 和 `忽略 SSL 证书` 三个开关。
    * **认证注入**：支持配置 `inject_headers` 实现免登。

### 3.7 系统日志与防撑爆策略
* **日志防撑爆**：系统运行日志写入 `data/logs/` 目录。
* **自动轮转**：必须使用日志轮转库（如 `tracing-appender`），单文件最大 10MB，最多保留 5 个备份，**严禁单个日志文件无限增长**。

### 3.8 多语言国际化支持 (i18n)
1. **前端语言包管理**：
    * 默认内置简体中文 (`zh-CN`) 和英文 (`en-US`) 两个语言包，存放于 `web/src/locales/` 目录下。
    * 语言包按照功能模块分文件存储（如 `common.json`, `files.json`, `terminal.json`）。
2. **后端错误码规范**：
    * 后端 (Rust) 返回的 API 错误信息统一使用标准英文和错误码（如 `{"code": "AUTH_FAILED", "message": "Invalid password"}`）。
    * 前端根据后端返回的 `code` 字段，使用 i18n 对应的键值进行本地化翻译展示，不直接显示后端的英文 `message`。
3. **持久化与默认语言**：
    * 用户切换语言后，将选择存入 `localStorage`。
    * 首次访问时，通过 `navigator.language` 自动识别浏览器语言。如果不在支持列表中，默认回退到英文 (`en-US`)。

## 5. CLI 命令行参数设计

系统遵循 **“CLI 参数 > 环境变量 > config.toml”** 的优先级覆盖原则。二进制名称为 `asmoday`。

* `-c, --config <PATH>`：指定配置文件路径。
* `-d, --data-dir <PATH>`：指定运行数据目录（SQLite/缓存）。
* `-p, --port <PORT>`：强制覆盖监听端口。
* `-v, --version` / `-h, --help`：打印版本号 / 帮助。
* `--init`：生成默认的 `config.toml` 与 `data/` 目录，并**输出一次性高强度密码**至控制台。
* `--reset-password`：应急模式，在终端重置管理员密码。
* **环境变量前缀**：`ASMODAY_` (如 `ASMODAY_PORT=4242`, `ASMODAY_RESET_PASSWORD=xxx`, `ASMODAY_FFMPEG_PATH=xxx`)。

## 6. API 接口契约

### 6.1 文件与流式传输
* `GET /api/files/list?path=/mnt/nas&page=1`：返回文件树 JSON，包含 `has_more` 标记。
* `GET /api/files/raw?path=...`：流式返回原始文件，支持 HTTP Range。
* `POST /api/files/upload`：流式接收文件写入磁盘。
* `GET /api/files/thumb?path=...`：返回缩略图，若队列溢出返回默认占位图。

### 6.2 配置管理与系统状态
* `GET /api/config`：返回解析后的 JSON 格式配置。
* `POST /api/config`：接收 JSON 格式的配置，后端自动将其格式化为 TOML 并保存。
* `GET /api/config/raw`：返回原始 `config.toml` 字符串。
* `POST /api/config/raw`：接收字符串，覆盖写入并触发热重载。
* `GET /api/system/ffmpeg-status`：检测 FFmpeg 状态，返回 `{ "status": "ok", "version": "6.1", "path": "/usr/bin/ffmpeg" }`。
* `POST /api/system/test-ffmpeg`：测试指定的 FFmpeg 路径是否有效。

### 6.3 终端 WebSocket
* `WS /api/terminal/ws?path=/target&cols=80&rows=24&session_id=xxx`：传输 PTY 原始字节流。
* **参数说明**：`path` 为**可选参数**。若未提供或为空，后端必须使用 `dirs::home_dir()` 获取操作系统主目录，并在该目录拉起 Shell。

## 8. UI/UX 交互设计规范

### 8.1 布局与响应式
* **侧边栏**：PC 端固定 240px。移动端自动隐藏为“抽屉（Drawer）”，通过顶部汉堡按钮呼出。
* **主工作区**：沉浸式深色/浅色背景，独立滚动。
* **毛玻璃面板**：仪表盘卡片、弹窗、灯箱控制条采用 `backdrop-filter: blur` 质感。

### 8.2 主题系统
* 使用全局 CSS 变量（`:root` 与 `[data-theme="light"]`）实现无刷新级主题切换。
* 切换逻辑由原生 JS 直接修改 `<html>` 的 `data-theme` 属性，规避框架渲染延迟和首屏白屏闪烁。必须加入 `transition: background-color 0.3s, color 0.3s;` 保证视觉平滑。

### 8.3 边缘状态处理
* **加载骨架**：进入目录或加载瀑布流时，先展示骨架屏（脉冲动画）。
* **空状态**：无照片时展示插画，并引导通过 WebDAV 同步或拖拽上传。
* **无缩略图**：未装 FFmpeg 时，视频统一展示默认图形遮罩。
* **路径报错**：若用户访问无权访问的路径，后端返回明确 403，前端渲染精美的“无权限”空状态。

### 8.4 【AI 极易翻车】视觉与交互防坑规范（强制遵守）
1. **横竖屏视频自适应（严禁暴力裁剪）**：
   * **场景痛点**：手机录制的竖屏视频（9:16）如果在 16:9 的容器中强制播放，极易被裁剪成只有上半部分。
   * **强制规范**：播放器 `<video>` 标签**必须设置 `object-fit: contain`**（确保视频完整显示，接受留黑边），**严禁在未知视频比例时使用 `object-fit: cover`**。
   * **全屏/灯箱播放**：容器绝不能写死固定高度。必须使用 `max-w-full max-h-[85vh]`，并让视频保持原始宽高比居中。
   * **动态比例适配**：前端需要在 `video` 的 `loadedmetadata` 事件中，读取 `videoWidth` 和 `videoHeight`，动态调整播放器容器的宽高比，确保无论是横屏、竖屏还是方屏，都能完美居中呈现，绝不裁切。
2. **图片容器与媒体网格（防塌陷与防抖动）**：
   * 文件网格和相册网格的缩略图，必须使用 `aspect-square` 或固定的长宽比，并设置 `object-cover`（裁剪填充），防止图片比例不一导致网格错乱。
   * 瀑布流中的图片，必须配合之前的 ThumbHash 占位，并设置 `object-cover`，高度自适应。
3. **Xterm.js 终端初始化排版**：
   * `xterm.js` 实例化前，**必须确保其挂载的 DOM 容器已经渲染完毕**（如使用 `nextTick`）。
   * 必须在渲染后调用 `fit()` 方法（配合 `xterm-addon-fit`），否则终端字符会错位、无法铺满容器。窗口 `resize` 时也必须调用 `fit()`。
4. **文本溢出与长路径处理**：
   * 所有的文件名、路径面包屑、音乐标题，如果超长，必须使用 Tailwind 的 `truncate`（单行截断省略）或 `break-all`（长路径折行），**严禁撑破 UI 布局**。
5. **弹窗/抽屉/灯箱的滚动穿透**：
   * 当打开右侧预览面板、移动端抽屉或全屏灯箱时，**必须锁定底层页面的滚动**（如给 `body` 加 `overflow-hidden`），防止用户在查看大图时底层背景还在滚动。
6. **移动端安全区适配（Safe Area）**：
   * 全局底部悬浮音乐条、移动端软键盘快捷键栏，必须添加 `padding-bottom: env(safe-area-inset-bottom)`，防止在 iPhone 等全面屏手机上被底部小白条遮挡。
7. **音乐悬浮播放条的层级与适配**：
   * 悬浮播放条的 `z-index` 必须极高，绝不能被页面的其他元素遮挡。
   * 当悬浮播放条展开“播放列表”抽屉时，不能影响底部控制条的点击。
   * 播放列表抽屉在 PC 端应紧贴底部控制条上方，移动端应占满屏幕下半部分。

### 8.5 语言切换交互规范
1. **切换入口**：在“系统设置 (Settings)”页面的“通用 (General)”选项卡中，提供下拉菜单切换语言（至少包含中文、English）。
2. **即时响应**：切换语言后，**无需刷新页面**，整个界面的 UI 文本（包括侧边栏、按钮、提示语）应即刻响应更新。
3. **移动端兼容**：多语言切换在移动端抽屉菜单的底部或设置页同样要完美适配，防止长单词撑破布局。

## 10. 生态扩展与推荐策略 (Ecosystem)

Asmoday 的核心设计哲学是“极简克制”。为了保证单二进制的极致轻量和低功耗，我们**绝不**将文件同步、下载器、内网穿透等重型功能内置到系统中。相反，我们在系统设置中提供一个**不可修改的、精心设计的“生态推荐”页面**，引导用户采用最成熟的第三方组合方案。

### 10.1 UI 呈现与交互规范
1. **视觉呈现**：采用与“聚合主页”一致的毛玻璃卡片网格布局（Card Grid）。每个工具对应一张卡片，包含：工具 Logo/图标、名称、一句话简介、以及“前往官网”或“下载”的跳转外链。
2. **分类分组**：卡片按功能分类（如：同步与备份、远程下载、公网与穿透、写作与图床），使用分类标题进行视觉区隔。
3. **外部链接规范**：所有外链按钮必须设置 `target="_blank" rel="noopener noreferrer"`，确保在浏览器新标签页打开，且不影响当前 Asmoday 页面。
4. **国际化 (i18n)**：该页面的所有标题、简介文本必须接入 `vue-i18n`，提供中文和英文双语支持。
5. **纯前端数据源**：此页面的数据不需要通过后端 API 获取，直接在前端定义为一个常量数组（如 `web/src/constants/ecosystem.ts`），跟随前端打包，确保断网可用，且更新极其简单。

### 10.2 官方推荐清单（默认内置）
前端代码中需硬编码以下推荐工具及其分类：

**📁 极速同步与备份 (Sync & Backup)**
*   **Syncthing**：点对点极速增量同步。推荐将手机或办公电脑的文件夹，无缝同步至 Asmoday 挂载的目录中。
