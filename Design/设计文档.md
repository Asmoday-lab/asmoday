# Asmoday (空间执政) 产品与系统设计白皮书

**版本**：v2.0.0 (终极全量版，包含全局组件复用、WebP、全预览矩阵与极细防坑规范)  
**定位**：专为低功耗 64 位设备（ARM64 / x86_64）设计的、单二进制的个人媒体与设备控制中枢。

---

## 1. 项目概述与核心边界

### 1.1 背景与痛点
传统的自托管（NAS / 软路由 / 开发板）通常采用 `FileBrowser + ttyd + Nginx 反代 + 聚合页` 的拼装架构，导致以下问题：
1. **维护割裂**：新增服务需同步修改 Nginx 配置、聚合页 HTML，操作繁琐。
2. **体验断层**：文件管理与终端相互独立，无法实现“在指定目录一键打开终端”。
3. **安全隐患**：公网暴露风险高，各服务缺乏统一鉴权。
4. **资源浪费**：多进程并行，占用不必要的内存与 CPU。

### 1.2 产品定位
**Asmoday** 是一个前后端分离开发、单体二进制发布的极简控制中枢。它只负责核心的文件、媒体与终端展示，拒绝任何重型功能。为了保证极致的编译与运行效率，**全面放弃 32 位架构（如 ARMv7），只专注于现代 64 位平台（ARM64, x86_64）**。

### 1.3 核心克制原则与红线
1. **绝不内置多媒体转码**：拒绝在服务端运行 FFmpeg 进行视频转码，仅依赖浏览器客户端播放能力。
2. **绝不内置刮削与 AI**：不联网抓取影视海报，不提取内封字幕，不搞任何语义/人脸识别。
3. **绝不自研同步与 App**：不自建同步协议，强制引导用户使用 WebDAV 或第三方同步工具（如 Syncthing）。
4. **绝不依赖外部 CDN**：前端所有静态资源（包括各种代码高亮语言包、终端库）全量打包进二进制，**拒绝任何形式的公网 CDN 外链**，确保在内网断网环境下的绝对可用性和毫秒级加载速度。
5. **绝不留下免密后门**：严禁在配置文件提供“关闭认证”的开关。忘记密码必须通过 CLI 命令行或物理删除数据重置，确保系统在任何配置文件泄露的情况下都不会直接裸奔。
6. **绝不接管重型任务**：不内置 BT 下载器、不内置在线办公套件，通过“生态推荐页”引导用户搭配外部工具。

### 1.4 AI 防幻觉与版本铁律（最高优先级）
1. **严禁擅自降级依赖**：遇到 API 报错，**绝对不允许**将库降级到旧版本（如把 Video.js 10 降级到 v8）。必须查阅最新版官方文档重构代码。
2. **严禁使用过时的废弃 API**：必须严格遵循新版库的架构（如 Axum 0.7+ 的 `axum::serve`，CodeMirror 6 的模块化 API，Video.js 10 的 Web Components）。
3. **严禁前端硬编码文本**：所有的界面文本、按钮、提示语，**必须**通过 `vue-i18n` 的 `$t('key')` 方式渲染。绝对禁止在 `.vue` 文件或 `.ts` 文件中直接写死中文字符串。

## 2. 技术架构与选型

### 2.1 总体架构
* **后端**：Rust 语言，基于 `axum` (0.7+) 异步 Web 框架。通过 `rust-embed` 将前端产物打包入单文件。
* **前端**：Vue 3 + Vite + TailwindCSS (v4)。
* **跨平台**：通过 Rust 交叉编译，产出主流 64 位系统（Windows x64、macOS ARM64/x64、Linux x86_64/ARM64）独立的单二进制文件。

### 2.2 核心依赖库与规范
* **Web 框架**：`axum` (0.7+)。**严禁**使用旧版 `axum::Server`，必须用 `axum::serve`。
* **PTY 终端**：`portable-pty`（跨平台拉起真实伪终端）。
* **系统目录获取**：`dirs`（用于跨平台获取主目录 `~`）。
* **数据库**：`rusqlite`（自带 `bundled` 特性，免系统依赖），**系统启动时必须开启 WAL 模式**（执行 `PRAGMA journal_mode=WAL;`）。
* **配置解析**：`toml` 库（替代 YAML，提供强类型与显式语法）。
* **网络代理**：`hyper` / `reqwest`（用于内部网关透传）。
* **前端终端**：`xterm.js` + `xterm-addon-fit`。
* **前端编辑器**：`CodeMirror 6`。**严禁**使用 v5 的 `fromTextArea` 或全局 `CodeMirror` 对象，必须按需引入 `@codemirror/state`, `@codemirror/view` 及具体语言包。
* **前端播放器**：`Video.js 10`。**严禁**使用 v8 的 `videojs()` 函数 API，必须使用基于 Web Components 的 `@videojs/html` 自定义元素（如 `<video-player>`）。
* **前端多语言**：`vue-i18n` (v9+)。用于全局文本管理。
* **CSS 框架**：`TailwindCSS v4`。通过 Vite 插件配置，废弃 `tailwind.config.js`，统一在 CSS 中使用 `@import "tailwindcss"`。

### 2.3 前端资源加载与防白屏策略
* **Vite 代码分割 (Code Splitting)**：前端在引入 `CodeMirror` 语言包、`Video.js`、`xterm.js`、`marked`（Markdown 解析）等重型组件时，全面使用 ES Module 的 `import()` 动态导入语法。
* **无感内嵌**：Vite 打包出的所有 chunk 文件，均被 `rust-embed` 吸入二进制文件中。坚决不向用户提供“自定义 CDN 源”选项。
* **静态资源缓存 (Cache-Control)**：
    * 带 Hash 的静态文件（如 `main.a1b2.js`、`index-xxx.css`）设置长达一年的强缓存。
    * **`index.html` 必须设置 `Cache-Control: no-cache`**，防止前端更新后用户浏览器加载旧代码导致白屏。

### 2.4 SPA 单页应用路由 Fallback 规范
* **强制规则**：所有 `/api/*` 路由之外的无匹配请求，如果后端找不到对应的静态资源文件，**必须 Fallback 返回内嵌的 `index.html`**，绝不可直接返回 404。
* **例外**：只有 `/api/*` 的路由在找不到资源或报错时才返回 404 JSON。

## 3. 详细功能模块设计与工程细节

### 3.1 身份认证、安全与初始化 (Auth & Security)
* **初次运行初始化策略**：
    * **默认路径（交互式向导）**：首次通过浏览器访问时，强制进入极简初始化页面，引导用户自行设置管理员账号与高强度密码。
    * **自动化路径（日志一次性密码）**：在纯 CLI 或容器化脚本部署时（使用 `--init` 参数启动），程序自动生成高强度的随机密码并打印至控制台日志中。用户首次登录后强制要求修改密码。
* **密码遗忘与重置机制（防后门设计）**：
    * **严禁**在配置文件（`config.toml`）中提供“无密码/关闭认证”的静态开关。
    * 重置密码必须通过系统级操作（CLI `--reset-password` 或 Docker 环境变量 `ASMODAY_RESET_PASSWORD`）证明权限。
* **会话管理**：登录后下发 `HttpOnly` Cookie，全站 API 与 WebSocket 必须经 Auth 中间件拦截。
* **双重认证 (2FA)**：可选开启 TOTP（基于时间的一次性密码），开启后登录需输入动态码。
* **防爆破机制**：基于内存的 IP 计数器，连续 5 次密码错误封禁该 IP 15 分钟。
* **WebDAV 独立凭证 (App Token)**：严禁使用主密码挂载 WebDAV。支持生成带前缀（如 `asm_`）的 Token，可设置“有效时间”与“只读/读写”权限，数据库仅存哈希值。
* **反向代理兼容性**：
    * 支持信任 `X-Forwarded-For` / `X-Real-IP`（结合 `trusted_ips` 白名单），确保获取真实 IP。
    * 支持 `X-Forwarded-Proto` 和 `X-Forwarded-Host`，确保生成的动态 URL 协议正确。
    * 支持 `base_url` 子路径部署，前端 Router 与后端路由自动处理路径前缀。
* **双向 SSO 架构**：
    * **“座上宾”模式（被外部接入）**：信任反向代理传递的 Header（如 `X-Forwarded-User`），通过白名单限制来源，实现外部 IdP 免密跳转。
    * **“大内总管”模式（代理外部服务）**：反代时支持 `Header 注入`；或通过 `Cookie 作用域重写`，隔离多服务 Session。
* **安全纵深与 XSS 防范**：
    * 前端绝不使用 `v-html` 渲染不可信内容。
    * 后端保存文件名时，严格过滤危险字符，并强制执行 **路径穿越（Path Traversal）校验**，防止 `../` 攻击。
    * 图床/分享直链必须校验 Token 有效性。

### 3.2 文件管理 (Files - 极简无树设计)
* **视图布局（无目录树）**：彻底放弃传统的左侧常驻目录树，最大化释放横向空间，完美适配移动端。
    * **根入口**：进入“文件管理”时，主区域平铺展示所有配置的挂载点（卡片式）。
    * **层级浏览**：点击挂载点进入后，主区域展示文件列表/网格。顶部使用 **面包屑导航（Breadcrumb）** 来支持层级回退和跳转。
    * **显示隐藏文件（Toggle Hidden Files）**：
        * 默认隐藏以 `.` 开头的系统隐藏文件/文件夹。
        * 顶部工具栏提供一键切换开关。开启后，前端在 API 请求中附带 `show_hidden=true`，后端据此返回包含 `.git`、`.env` 等隐藏项的文件列表。
* **文件预览矩阵与复用机制（极度重要）**：
    * **严禁重复造轮子**：文件管理中的双击预览行为，**严禁**单独手写 `<img>` 或 `<video>` 弹窗。必须调用全局的 `MediaLightbox` 组件与全局媒体播放状态（Pinia）。
    * **传参规范**：双击图片时，前端应收集当前目录下的所有同类型图片，构成一个数组，调用 `MediaLightbox.open(images, currentIndex)`，从而在文件管理中也能享受相册级别的“左右切换”体验。
    * **纯文本/代码 (txt, js, rs, py, toml 等)**：双击无缝切换为 `CodeMirror 6` 编辑器。
    * **Markdown (.md)**：双击默认进入**渲染预览模式**（按需 `import()` 引入极轻量 `marked` + `DOMPurify` 防 XSS）。顶部提供“切换源码”按钮进入编辑器。
    * **音视频 (mp4, mp3 等)**：拉起全局媒体播放器组件。
    * **PDF 文档**：直接使用浏览器原生 `<iframe src="raw_url">` 渲染，零体积开销。
    * **表格数据 (.csv)**：按需引入极轻量解析器，渲染为只读表格。**强制限制：文件大小超 5MB 或行数超 1000 行时，截断展示并提示下载**。
    * **重型文档 (Office docx/xlsx/pptx, CAD, 压缩包等)**：**坚决不引入任何本地解析库**。弹窗提示“为保证系统轻量，暂不支持在线预览该格式，请下载后查看。”，直接触发下载。
* **大文件流式传输与防 OOM（内存溢出）**：
    * **上传**：必须使用流式处理，**严禁将整个文件读入内存**。接收分块时直接流式落盘。
    * **下载/播放**：必须支持 HTTP Range（断点续传），使用 `tokio::io::copy` 流式响应。
* **大目录性能防卡死**：
    * 后端针对超过 1000 个文件的目录**强制分页截断**，返回 `has_more: true` 标记。
    * 前端配合分页加载或使用**虚拟列表（Virtual DOM）**，只渲染视口内的文件 DOM。
* **右键菜单**：集成“下载”、“在此终端中打开”、“分享”、“复制图床直链”、“删除”等高频操作。

### 3.3 终端联动 (Terminal)
* **跨平台 Shell 与默认主目录解析（高优防坑）**：
    * **禁止前端传递 `~`**：前端在未指定具体目录时，`path` 参数传空字符串或省略。
    * **后端兜底解析**：Rust 后端接收到空 `path` 时，必须调用 `dirs::home_dir()` 获取真实主目录（Linux 下为 `/home/user`，Windows 下为 `C:\Users\user`）。
    * **Shell 唤醒策略**：
        * Unix/Linux：读取 `$SHELL` 环境变量，回退至 `bash`。
        * Windows：默认拉起 `powershell.exe`（或使用 `portable-pty` 默认支持的 ConPTY）。
    * **路径分隔符转换**：若前端传入 POSIX 风格的路径（如 `C:/Users/...`），后端需使用 `PathBuf::from()` 自动转成 Windows 原生反斜杠路径，防止拉起失败。
* **PTY 直通**：真正的系统底层 Shell（非模拟环境），支持运行 Vim、Top 等全屏应用。
* **PTY 连接数限制（防雪崩）**：后端必须维护 PTY 连接池，**限制单用户最大并发的 PTY 会话数（如最多 10 个）**。
* **断线保活（WSS Reconnect）**：
    * 后端维护 PTY 进程池。当 WebSocket 断开时，**PTY 进程延迟 3 分钟再销毁**。
    * 前端重连时，带上 `SessionID`，后端直接把缓冲区数据推给前端，无缝恢复现场。
* **移动端键盘适配**：PC 端自动隐藏虚拟键盘。移动端复刻 Termux 的两行布局，支持粘性 `CTRL` 和 `ALT` 键。

### 3.4 媒体画廊与缓存生命周期 (Gallery)
* **缩略图生成防雪崩机制**：引入信号量限制并发数（最多 2-4 张），超出的请求返回占位图。
* **缩略图多格式自适应与降级（WebP 优先）**：
    * **存储优化**：后台生成缩略图/视频首帧时，**优先编码为 WebP 格式**（利用 FFmpeg 的 `libwebp`），节省 30% 以上空间。
    * **强制降级机制**：捕获 FFmpeg 错误。若环境不支持 WebP，自动降级回退到 JPEG。
    * **MIME 识别**：根据实际文件后缀，准确返回 `Content-Type: image/webp` 或 `image/jpeg`。
* **缩略图缓存生命周期管理（LRU 淘汰）**：存放于 `data/thumbnails/`，多级哈希散列。根据 `config.toml` 中的 `thumb_cache_max_size_mb` 和 `thumb_cache_max_age_days` 自动淘汰。设置页提供“清理缓存”按钮。
* **照片相册 (Photos)**：
    * **时间线**：按“年-月”分组的瀑布流。引入 ThumbHash 模糊占位防抖动。
    * **交互区分**：点击相册（文件夹）进入下一级；点击图片触发全局 `MediaLightbox`。时间线展示**必须排除音频文件**。
* **影视库 (Cinema)**：
    * 基于文件夹结构展示，16:9 横版海报墙。不联网刮削。
    * **播放器选择**：按需动态引入 `Video.js 10`。支持外挂字幕（`.srt`/`.vtt`）。
* **音乐库 (Music)**：
    * 读取内嵌 ID3 标签。解析 `.lrc` 歌词滚动高亮。
    * **全局悬浮播放条**（跨路由持久存在）：包含封面、歌名、播放模式（列表/单曲/随机）、切歌、进度条。点击播放列表从右侧（PC）或底部（移动端）滑出抽屉。
* **全局音量记忆机制（防爆音）**：初始音量强制 **35%**，用户调整后写入 `localStorage`。静音时记住原音量，取消静音恢复。

### 3.5 Web UI 配置管理与设置页 (Config Management)
* **彻底抛弃 YAML**：采用 **TOML** 作为主配置格式。
* **双模编辑**：可视化表单 + 源码模式（调用内置 `CodeMirror 6`）。保存后利用 `notify` 库触发热重载。
* **设置页精细化规范（分层与优先级）**：
    * **页面布局**：按功能分 Tab（通用、媒体、安全、高级）。
    * **FFmpeg 路径优先级**：UI 手动指定 > 环境变量 `ASMODAY_FFMPEG_PATH` > 系统 `PATH`。提供状态检测与 `libwebp` 支持探测。
    * **恢复默认配置策略**：**严禁**“一键清空所有数据”（绝对不碰 SQLite）。分区块重置，且 `config.toml` 中的高级配置（如 `[[services]]`）**绝不**被普通表单重置覆盖。

### 3.6 服务聚合面板 (Service Hub)
* **配置驱动**：支持在 `config.toml` 或 UI 中定义外部服务卡片。
* **智能反向代理 (Smart Proxy)**：内置 `hyper` 自动处理 `Host`、`WebSocket Upgrade`，剥离 `X-Frame-Options`。提供 `剥离路径前缀`、`重写绝对链接`、`忽略 SSL` 三个开关，支持 `inject_headers`。

### 3.7 系统日志与防撑爆策略
* 日志写入 `data/logs/`。必须使用轮转库（如 `tracing-appender`），单文件最大 10MB，保留 5 个备份，**严禁无限增长**。

### 3.8 多语言国际化支持 (i18n)
* 内置中英语言包（分模块存储）。后端返回标准英文错误码，前端根据 `code` 使用 i18n 翻译。用户选择存入 `localStorage`，首次访问通过 `navigator.language` 识别。

## 4. 数据库与配置结构

### 4.1 数据库设计 (SQLite)
* **【强制要求】开启 WAL 模式**：系统启动时执行 `PRAGMA journal_mode=WAL;`。

```sql
-- 1. 用户表
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    username TEXT UNIQUE,
    password_hash TEXT,
    totp_secret TEXT,
    is_totp_enabled BOOLEAN DEFAULT 0,
    created_at DATETIME
);

-- 2. 访问令牌表 (WebDAV / 图床)
CREATE TABLE access_tokens (
    id INTEGER PRIMARY KEY,
    user_id INTEGER,
    token_name TEXT,
    token_hash TEXT UNIQUE,
    is_readonly BOOLEAN DEFAULT 1,
    expires_at DATETIME,
    created_at DATETIME
);

-- 3. 分享记录表
CREATE TABLE shares (
    token TEXT PRIMARY KEY,
    file_path TEXT NOT NULL,
    is_folder BOOLEAN NOT NULL,
    password_hash TEXT, 
    allow_download BOOLEAN DEFAULT 1,
    expires_at INTEGER,
    created_at INTEGER
);

-- 4. 媒体状态记录
CREATE TABLE favorites (
    file_path TEXT PRIMARY KEY,
    created_at INTEGER
);

CREATE TABLE play_history (
    file_path TEXT PRIMARY KEY,
    last_played_at INTEGER,
    progress INTEGER 
);
```

## 6. API 接口契约

### 6.1 文件与流式传输
* `GET /api/files/list?path=xxx&page=1&show_hidden=false`：返回文件树，含 `has_more`。
* `GET /api/files/raw?path=xxx`：流式返回，支持 Range。
* `POST /api/files/upload`：流式接收。
* `GET /api/files/thumb?path=xxx`：返回缩略图（优先 WebP）。

### 6.2 配置管理与系统状态
* `GET/POST /api/config` 与 `/api/config/raw`：配置读写与热重载。
* `GET /api/system/ffmpeg-status`：检测 FFmpeg 状态及 `webp_support`。

### 6.3 终端 WebSocket
* `WS /api/terminal/ws?path=xxx&cols=80&rows=24&session_id=xxx`：`path` 为空默认 `~`。

## 8. UI/UX 交互设计规范

### 8.1 布局与响应式
* **侧边栏**：PC 端固定 240px，移动端抽屉。主工作区独立滚动，毛玻璃面板。

### 8.2 主题系统
* 全局 CSS 变量实现切换。由原生 JS 直接修改 `<html>` 的 `data-theme` 属性，避免首屏白屏闪烁。加上 `transition` 保证平滑。

### 8.3 边缘状态处理
* 加载骨架（脉冲动画）、空状态引导、无缩略图遮罩、403无权限空状态。

### 8.4 【AI 极易翻车】视觉与交互防坑规范（强制遵守）
1. **横竖屏视频自适应（严禁暴力裁剪）**：播放器 `<video>` 必须 `object-fit: contain`。前端监听 `loadedmetadata` 动态调整容器比例，绝不裁切竖屏视频。
2. **图片容器与媒体网格**：必须用 `aspect-square` 等固定比例并 `object-cover`，防图片错乱。瀑布流用 ThumbHash 占位。
3. **Xterm.js 终端初始化排版**：必须在 DOM 渲染完毕后（`nextTick`）调用 `fit()`，窗口 `resize` 时也要调用。
4. **文本溢出与长路径处理**：超长文本（文件名、路径、歌曲名）必须使用 `truncate` 或 `break-all`。
5. **弹窗/抽屉/灯箱的滚动穿透**：打开任何遮罩层，必须锁定底层 `body` 滚动。
6. **移动端安全区适配（Safe Area）**：底部悬浮条、虚拟键盘必须加 `padding-bottom: env(safe-area-inset-bottom)`。
7. **音乐悬浮播放条的层级与适配**：`z-index` 极高，绝不能被遮挡。抽屉滑出需适配移动端/PC端。
8. **文件预览的防崩溃处理**：
    * **Markdown 安全**：必须通过 `DOMPurify` 进行 XSS 过滤。
    * **大文件截断**：前端解析 CSV 等必须做体积/行数截断（如 1000 行），防浏览器假死。
    * **隐藏文件兜底**：隐藏文件无标准后缀，请求缩略图时前端需捕获错误，用默认图标占位。
    * **降级友好度**：无法预览的 Office 文件，提示框要精美，强调“为了极速体验选择下载”。
9. **全局媒体组件的内存与生命周期管理（防内存泄漏）**：
    * **单实例原则**：图片灯箱和视频播放器作为单例（Teleport 到 body），严禁在列表循环中生成大量隐藏 DOM。
    * **彻底销毁**：关闭视频预览时，**必须**手动销毁 `<video>` 元素（`pause(); src=''; load();`），防止后台缓冲下载导致严重卡顿。

### 8.5 语言切换交互规范
* 设置中支持中英切换，即时生效无需刷新。

## 10. 生态扩展与推荐策略 (Ecosystem)

Asmoday 的核心设计哲学是“极简克制”。我们**绝不**将文件同步、下载器、内网穿透等重型功能内置到系统中。在设置中提供一个**不可修改的、精心设计的“生态推荐”页面**。

### 10.1 UI 呈现与交互规范
1. **视觉呈现**：采用与主页一致的毛玻璃卡片网格布局（Card Grid），含图标、名称、简介、跳转外链。
2. **分类分组**：按功能分类（如同步与备份、远程下载、公网与穿透等）区隔。
3. **外链规范**：`target="_blank" rel="noopener noreferrer"`。
4. **国际化 (i18n)**：必须接入 `vue-i18n`。
5. **纯前端数据源**：数据写在前端常量数组中，随打包发布，断网可用。

### 10.2 官方推荐清单
**📁 极速同步与备份**
*   **Syncthing**：点对点极速增量同步。
*   **PhotoSync / FolderSync**：通过 WebDAV 备份手机相册。

**⬇️ 远程下载**
*   **qBittorrent / Aria2**：下载路径设为 Asmoday 挂载目录。

**🌐 公网与穿透**
*   **Caddy / Nginx**：提供专业反代与 SSL。
*   **Tailscale / ZeroTier**：组建虚拟局域网，安全访问。

**✍️ 写作与图床**
*   **PicGo / Typora / Obsidian**：配置 Asmoday 图床直链，打造本地写作流。
