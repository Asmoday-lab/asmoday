# Asmoday 产品与系统设计文档（定稿版 v4.9.50）

**定位**：专为低功耗 64 位设备（ARM64 / x86_64）设计的、单二进制的个人媒体与设备控制中枢。前后端分离开发，单体二进制发布。**单用户模型**（一个设备一个账号，v4.9.28）+ 内置 aria2 兼容下载引擎（HTTP v4.9.26，BitTorrent v4.9.27）。

**本版修订（v4.9.50，密码首尾空白一律忽略）**：粘贴密码时多带一个空格、中文输入法留下的全角空格，
曾让人「密码明明是对的却一直 401」且无从排查。现在写入侧 `create_user` / `update_password` 先 `trim()`
再哈希，校验侧 `verify_password_lenient()` 先比 trim 后的值、再比原样（兼容规则落地前的存量密码），
前端 `PasswordInput` 在失焦 / 回车时抹掉首尾空白；中间的空格照留（3.5）。

**前版修订（v4.9.49，撤掉「首启自动开浏览器」）**：v4.9.45 那条隐式行为（首启打印一次性密码 + 经典 conhost 就替用户拉浏览器）
在双击场景下自己触发，用户看到的是「控制台莫名弹出浏览器」，甚至撞上提权实例冲突——Edge 弹
「现有实例正在以提升的权限运行，是否用普通权限重启」（2026-11-06 实机反馈）。改为**只有显式 `--open` /
`ASMODAY_OPEN=1` 才拉浏览器**；Windows 上改用 `explorer.exe <url>` 交回登录用户 shell（降权），
不再让浏览器继承本进程的 token（3.1）。

**前版修订（v4.9.48，一个框 + 方式切换）**：登录页保持一个输入框，默认密码形态；开了 2FA 时框下方多一行
「使用动态验证码登录」，点一下同一个框换成居中的 6 位动态码样式（输满自动提交），再点换回密码——
这是通行做法：**方式可选，框始终一个**。后端按「哪个字段有值」分派（`{password}` / `{totp}` /
两者都给 = 严格双因子），不再靠猜填的内容（3.5）。

**前版修订（v4.9.47，单框三凭证）**：密码 / 6 位动态码 / 恢复码填同一格都能登，开 2FA 不关密码路径。

**前版修订（v4.9.46，登录页只剩一个输入框）**：去掉「使用动态验证码（已开启 2FA）」那颗开关，`GET /api/auth/status` 未登录也回设备级 `totp_enabled`（3.5）。

**前版修订（v4.9.45，控制台地址按社区惯例给两条 + 双击 exe 也能进页面）**：启动日志改成 `local:` / `network:` 两行——绑 `0.0.0.0` 时把探测到的局域网地址一并打出来（只打 localhost 的话，用户改完监听地址也不知道手机该填什么）；新增 `--open` / `ASMODAY_OPEN=1` 用系统默认浏览器打开入口，并在「首启打印一次性密码 + 检测到经典 conhost」时自动开一次（conhost 不实现 OSC 8，链接点不动，这是唯一可靠出路）（3.1 / 9）。

**前版修订（v4.9.39，BT Tracker 可管理）**：Tracker 列表进了数据库与页面（3.11）——`settings.download_trackers` + `POST /api/downloads/trackers`，语义对齐 aria2 的 `bt-tracker`（追加到新任务的 announce 列表；已在跑的不追溯）；`getGlobalOption` 回 `bt-tracker`、`changeGlobalOption` 对它真生效，其余键不再「假装 OK 什么也不做」（逐条 WARN）。`[download].bt_trackers` 降级为一次性种子。

**前版修订（v4.9.38，下载页改名「下载引擎」+ 设置搬出弹窗）**：入口与页面标题统一为「下载引擎」；`/downloads` 页内改成 `任务` / `引擎设置` 两个视图，设置从弹窗移到页内卡片（宽屏左「引擎参数」、右「允许的保存目录 + RPC 接入」），草稿跨视图保留（3.10）。

**前版修订（v4.9.37，保存目录改挂载点子路径 + 热生效）**：保存目录白名单从「裸绝对路径」改为「挂载点 id + 相对子路径」，存 `settings.download_roots`，新增 `POST /api/downloads/roots` 写库 + 热替换、**立即生效**；页面只显示 `挂载点名 / 子路径`，不再印服务器绝对路径（3.10）。

**前版修订（v4.9.36，下载密钥入库 + 前端刷新）**：RPC 密钥从 `<data>/download_rpc_secret` 文件搬进数据库 `settings.download_rpc_secret`（3.10）——启动不再打印明文，只在前端下载页可见（显隐 / 复制），并新增 `POST /api/downloads/secret` 刷新密钥：写库 + 换内存，旧 `token:` 下一次请求即 401，**不需要重启**。页面按钮两段式确认，防止误触踢掉已配置的客户端。`[download].rpc_secret` 降级为一次性种子（数据库还没有值时导入，之后忽略并 WARN）。

**前版修订（v4.9.35，访问日志降噪）**：下载页快照轮询不再记访问日志（3.7）——`/downloads` 页开着时前端每秒 `GET /api/downloads` 拉进度快照（与 AriaNg 默认轮询口径一致），之前每条都落 INFO 造成刷屏；现在豁免只限这个只读 GET，任务动作与 `/api/downloads/engine` 照常记录（3.7）。**前版修订（v4.9.34，删除初始化页）**：初始化回归「一次性密码登录 → 弹窗设新密码」两步（3.1）——首启照旧在控制台打印一次性密码；`/login` 永远是普通登录页（只有密码框，无用户名），用它登录后弹「设置新密码」对话框完成建权。v4.9.32/v4.9.33（均本地未发布）曾做过「网页初始化页」，本版撤回：`POST /api/auth/setup` 端点与 `status.needs_setup` 字段删除，改密弹窗不再重复要「当前密码」（v4.9.33）这条保留。

## 1. 核心红线（不可协商）

1. 不内置多媒体转码，仅依赖浏览器解码。
2. 不内置刮削、AI、同步、App、BT 下载、在线办公。
3. 不依赖外部 CDN，前端静态资源全量打包进二进制。
4. 不提供关闭认证的配置开关。忘记密码仅通过 CLI 或删除数据重置。
5. 不提供回收站。删除一律物理硬删。`shares` 的 410 tombstone 仅服务分享链接。
6. 单次 `copy / move`：**选中条目数** > 100 **或** 递归总字节 > 2GB（任一超限即拒绝，引导至终端用 `cp`/`mv`）。阈值可配（`[server.limits]`，0 = 不限）。两条判定口径必须分清：
   - 条目数只数**用户选中的条目**，不数目录里套了多少文件 —— 选中一个装一万张照片的目录算 1 项；
   - 字节数才递归统计（上限靠它兜住），且**同挂载点内的移动不做统计**（原子 `rename` 不搬数据、不占空间），复制与跨挂载点移动才统计;
   - `delete` 只校验本批选中条目数，绝不为了拒绝先去 `remove_dir_all` 前扫全树（删除本身是 O(1) 元数据操作）；
   - `rename / mkdir / touch / stat / hash` 不受此限。
7. 目录冲突时 `on_conflict=overwrite` 直接拒绝（`E_DIR_CONFLICT`），只接受 `rename / skip`。严禁合并目录内容。
8. 不内置 ACME。证书由用户手动指定或前置 Caddy/Nginx。
9. 禁止 iframe 内嵌第三方外部服务。本地 PDF 的 `<iframe src="raw_url">` 预览不受此限。
10. 严禁降级依赖。必须使用本文锁定的版本与 API。
11. 严禁前端硬编码界面文本，一律 `vue-i18n`。
12. 严禁“先检查再操作”代替原子落盘。防覆盖依赖平台原子 no-replace 操作。
13. 严禁对不存在的完整路径直接 `canonicalize`。必须 `canonicalize` 父目录并校验归属。
14. 严禁在列表循环中生成隐藏的 `<video>` / `<audio>`。全局媒体组件单实例。
15. 严禁将 ThumbHash 保存为碎文件。必须存入 SQLite。
16. 严禁覆盖用户 EOL。保存时原样写回 `LF` / `CRLF`。
17. 严禁使用仅支持反序列化的 TOML 库重写配置。必须 `toml_edit` AST 局部修改。
18. 严禁向宿主机全局环境变量注入污染。额外变量在 `CommandBuilder` 中临时注入。
19. 终端必须进入交互式登录模式，打包 Nerd Font 与标准 ANSI 色板。

## 2. 技术架构与锁定依赖

### 2.1 总体架构

- **后端**：Rust，`axum = "0.8"`，`axum::serve`。`rust-embed` 打包前端。
- **前端**：Vue 3 + Vite + TailwindCSS v4（`@tailwindcss/vite`，CSS 中 `@import "tailwindcss"`，无 `tailwind.config.js`）。
- **跨平台**：Windows x64、Linux x86_64/ARM64 musl，单二进制（macOS 可源码自行编译，不再提供预编译包，见 17 章）。

### 2.2 锁定依赖

| 用途 | 依赖 | 版本/要求 |
|---|---|---|
| Web 框架 | `axum` | `0.8`，严禁 `axum::Server`。路由必须用 `{param}` / `{*wildcard}` 语法 |
| 会话 | 自研（`core/auth.rs` + `sessions` 表） | **不引入 `tower-sessions`**：滑动续期 / 绝对上限 / `verified_at`（二次验证）都要直接改行，store 抽象只会挡路 |
| 密码哈希 | `argon2` | Argon2id，`m=19456 KiB, t=2, p=1`（OWASP 2025 最低） |
| Token/恢复码 | `sha2` / `hmac` | SHA-256/HMAC + 常量时间比较 |
| PTY | `portable-pty` | 必须实现 5.3 的 Windows ConPTY 缓解 |
| 数据库 | `rusqlite`（`bundled`） | 启动执行 `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000;`。CI 必须缓存 `target/`，否则 ARM64 musl 的 bundled 编译可能超时 |
| 配置 | `toml_edit` | AST 局部修改，源码模式禁止格式化 |
| 文件监听 | `notify`（**不用** `notify-debouncer-full`） | 自己写 500ms 防抖（`RELOAD_DEBOUNCE` + `recv_timeout`）；见 7.2 的 macOS `Remove` 风险 |
| 网络代理 | `reqwest` | `default-features = false`；Linux 用 `rustls-tls`（musl 环境没有 OpenSSL 可链），其余平台用 `native-tls` 落系统实现（SChannel / Security.framework）。特性放 target 节，避免并集把两边都拉进来 |
| 前端终端 | `xterm.js` + `xterm-addon-fit` | 必须打包 JetBrainsMono Nerd Font woff2 |
| 编辑器 | CodeMirror 6 | 按需引入 `@codemirror/state`, `@codemirror/view` 及语言包 |
| 播放器 | Video.js | **`10.0.0` GA**，`@videojs/html` Web Components，严禁 v8 API；禁止 `latest` 或未锁定的 `^10.x` |
| i18n | `vue-i18n` | v9+，**必须 `createI18n({ legacy: false })`** |
| Markdown | `marked` + `DOMPurify` | 动态 `import()` |
| CSV | 轻量解析器 | 动态 `import()`，5MB/1000 行截断 |
| 传输层压缩 | `tower-http` | `compression-br` + `compression-gzip`，判定见 2.4 |
| 音频标签 | `lofty` | ID3v2 / FLAC / Ogg / MP4 / WAV / AIFF / APE / WavPack；**必须关 `read_properties`**（否则扫描音乐库时每首歌都要把音频流走一遍算时长） |
| 单实例锁 | `std::fs::File::try_lock` | Rust 1.89 稳定；Unix `flock`、Windows `LockFileEx`。**不要再用 SQLite 排他锁**（`BEGIN EXCLUSIVE` 在回滚日志模式下只拿 RESERVED，实测挡不住第二个实例） |
| WebDAV 协议 | `dav-server`（`localfs` feature） | RFC 4918 全套实现，见 12。**不手写协议**：`PROPFIND` 属性、`If` 头、多段 Range 这些边角错一个客户端就加不上 |
| schema 版本 | `rusqlite_migration`（`1.3`，兼容 rusqlite 0.32） | `PRAGMA user_version` 记进度，见 13。加列只追加 `M::up`，**不要回头改 v1** |
| 全局分配器 | `mimalloc` | 见 9.1。**musl 目标排除**（静态链接下 pthread TLS 对不上，运行时崩），其余平台生效 |
| 前端状态 | `pinia`（setup 语法） | store 在组件外用时显式传实例 `useStore(pinia)`，见 `web/src/stores/pinia.ts` 的约定 |
| 前端工具 | `@vueuse/core` | `useStorage`（偏好持久化）/ `useMediaQuery`（系统主题）/ `useEventListener`（成对挂卸监听）。手写 `addEventListener` + `removeEventListener` 只允许出现在 vueuse 覆盖不了的场景 |
| 工程基线 | `rustfmt` / `clippy`（本地门禁） | 提交前在本机跑 `cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`、`web` 下 `pnpm run build`。**GitHub Actions 只负责发版**（`.github/workflows/release.yml`，`v*` tag 触发），不跑 push/PR 的编译测试——本地已经编译过，云端再装一遍依赖纯属重复 |

### 2.3 前端资源与 SPA Fallback

- 带 Hash 静态文件：`Cache-Control: immutable`，一年。
- `index.html`：`Cache-Control: no-cache`。
- Fallback 仅当请求无文件扩展名 **且** `Accept` 含 `text/html`，且路径不在 `/api/*`、`/dav/*`、`/proxy/*` 下。带扩展名静态资源缺失直接 404。
- `base_url` 前缀在路由、Cookie Path、WebSocket URL、静态资源、分享链接、重定向中统一剥离/拼接。

### 2.4 传输层压缩

- 统一在响应最外层挂 `tower-http` 的 `CompressionLayer`（br 优先、gzip 兜底）。
  **不手写 `Content-Encoding`**：分块编码、`Vary: accept-encoding`、移除 `Content-Length`、
  协商顺序这些细节社区实现已经兜住，自己写漏一个就是线上事故。
- 判定用**白名单**而不是 `DefaultPredicate`：后者只排除图片 / gRPC / SSE，剩下的什么都压，
  `video/mp4`、`application/zip` 会被白白过一遍 CPU（还可能变大）。白名单只放
  `text/*`、JSON、JS、XML、SVG、wasm。
- 三条硬性排除：`206 Partial Content`（`/api/files/raw` 的字节区间按未压缩文件算，压完
  `Content-Range` 失真、视频拖动花屏）、已带 `Content-Encoding` 的响应、
  `Cache-Control: no-transform` 的响应。小于 1 KiB 的也不压。

## 3. 认证、会话与安全

### 3.1 初始化

- **控制台一次性密码 → 登录 → 弹窗设新密码（v4.9.34）**：首启自动生成 `admin` +
  一次性随机密码 `println!` 到**控制台**（**不进日志文件**——日志会轮转/采集，明文凭据
  不能落盘），并置 `must_change_password=1`。网页**没有初始化页**：`/login` 永远是普通
  登录页（单个输入框、无用户名），用户拿控制台打印的一次性密码登录（`POST /api/auth/login`，
  `username` 可省略）→ 会话 `must_change_password=1`，中间件只放行改密/me/logout，
  前端弹「设置新密码」对话框（v4.9.33 起不再重复要「当前密码」）→ 改密成功直达主界面。
  一次性密码就是所有权凭证——**证明请求来自守在控制台前的人**，没有它，先打开页面的
  路人就能抢注成主人；账号换成正式密码后一次性密码即告失效（登录 401）。
  错误一次性密码计入防爆破池（IP + IP|用户名双维度）。
- **没记下一次性密码：重启即补发（v4.9.44）**：密码只打印一次且明文不落盘，用户看一眼
  就把进程关掉的话，重启后既没有密码也没有任何提示——账号永久锁死（用户反馈）。
  现在只要账号仍停在 `must_change_password=1`（即从没用一次性密码登录过），**每次启动
  都重新签发一个**并在横幅里注明「上一个已作废」；置过正式密码的账号永不走这条路径。
  理由与凭证语义一致：能重启进程的人本来就守在控制台前。补发只改 `password_hash`，
  **不清会话、不动 `must_change_password`**（用 `update_password` 会顺手把人踢下线）。
  `--init` 遇到待改密账号同样补发；正式密码已设则只提示「不覆盖，要新的用 `--reset-password`」。
- **首启只监听回环（v4.9.42）**：默认 `[server] host = "127.0.0.1"`（此前是 `0.0.0.0`）。
  刚建好账号就默认暴露到整个局域网没有收益——要局域网访问就显式改 `0.0.0.0` / `::`
  （此时照旧输出「全接口 + 未启用 SSL」WARN）；`-H` / `ASMODAY_HOST` 仍然覆盖。
- **控制台横幅（v4.9.42 / v4.9.45）**：一次性密码不再混在日志行里——68 列等宽边框围起来
  （`ASMODAY - ADMINISTRATOR CREDENTIAL`），密码单独成行、TTY 下反显高亮，下面直接给
  **带 scheme 的完整地址**（终端才认得出可点击链接）：本机那条是
  `Open: http://localhost:4242`，绑 `0.0.0.0` / `::` 时另给一行
  `LAN:  http://192.168.1.35:4242`（局域网里别的设备照着填）。整段只走 stdout、
  正文字符全 ASCII（GBK 代码页的 cmd 也不乱码），颜色沿用日志系统同一个 TTY 判据，
  重定向到文件时是纯文本。
- **真超链接（v4.9.43）**：地址与启动日志里的 `local:` / `network:` 都用 **OSC 8** 包一层
  （`ESC ] 8 ; ; <url> ST <text> ESC ] 8 ; ; ST`），支持的终端里 Ctrl/⌘+点击即可打开；
  不支持的终端只看到普通 URL。放行判据是「能不能安全吐转义序列」而不是终端白名单：
  非 TTY、`SetConsoleMode` 拿不到 VT、Apple Terminal、Unix 下的 `TERM` 空/dumb 一律回落
  成纯文本（不认识 OSC 8 的终端按规范会静默跳到终止符，最差只是不可点）。日志文件与
  JSON 通道在渲染前剥掉 CSI/OSC，文件里永远只有 UTF-8 正文；启动时 DEBUG 记一行
  `console: tty=… vt=… color=… hyperlink=…`，用于判断「没颜色/没链接」是被主动关掉
  还是终端本身不支持。
  *历史方案*：v4.9.20 曾有「一次性初始化令牌 + 三项 setup 表单」；v4.9.23~v4.9.31 为
  「一次性密码登录 + 强制改密」两步（与本版一致，但当时登录页还有用户名）；v4.9.32
  错误改成「无凭证、先到先得设密码」；v4.9.33 改为网页初始化页收一次性密码 + 新密码
  ——两者都已撤回（只在本地提交过，未推送），`/api/auth/setup` 端点与
  `status.needs_setup` 字段一并删除。
- `--init` 仍可用：效果同首启自动引导（生成 admin + 随机密码打印 + 强制改密），供脚本化
  部署在启动前预建账号。`--reset-password` 见 3.2。
- **单用户（v4.9.28 起）**：`users` 表只认一行（3.9），网页端没有用户名概念——登录页
  只出现一个输入框，默认密码；开了 2FA 时框下方可切到动态码形态（见 3.5）。
  `POST /api/auth/login` 的 `username` 可省略，后端按唯一账号解析；
  显式带用户名仍兼容脚本/WebDAV 调用。首启创建 `admin`，之后没有增删账号的
  入口；存量多账号实例由迁移 v18 收敛、v19/v20 物理删除其余账号（v4.9.29 / v4.9.30）。

### 3.2 密码与重置

- 密码 Argon2id，参数见 2.2。
- `--reset-password` 交互式重置；`ASMODAY_RESET_PASSWORD` 仅在配合 `--reset-password` 时一次性生效，生效后写 `must_change_password=1`（登录后强制改密），同变量再次出现拒绝并 WARN。日志不打印密码。
- 一次性密码会话（`must_change_password=1`）改密**不再要求「当前密码」**（v4.9.33）：登录那一刻已用一次性密码验过身份，`POST /api/auth/password` 的 `current` 可省；正式密码会话仍必须带 `current` 且校验失败 400 `PASSWORD_WRONG`。
- `--reset-2fa` 清除 `totp_secret` 并关闭 2FA，需当前密码或走重置流程。
- 重置成功后清空全部服务端会话（`DELETE FROM sessions`；库里只有一个账号）。表里没有 `session_version`：删行即失效，逻辑更短也没有「忘了递增值」的坑。
- **密码可见性（v4.6.4）**：浏览器自带的「显示密码」按钮不可用——Edge 的 `::-ms-reveal`、Chromium 的内置装饰按钮都只在**输入框聚焦且非空**时才出现，失焦即消失，位置还会被 `padding-right` 与圆角裁掉一截，用户点它之前得先猜它在不在。全局关掉原生控件（`style.css` 的 `::-ms-reveal` / `::-webkit-textfield-decoration-container`），统一用 `PasswordInput.vue`：按钮常驻右侧 40×40、`type="button"`（不能误触发表单提交）、`@pointerdown.prevent`（切换时 input 不失焦、移动端小键盘不收起）、`aria-label` + `aria-pressed` 随状态同步。初始化/登录/强制改密/设置安全页/分享提取口令全部走这个组件，不再出现裸 `type="password"`。

### 3.3 会话（自研 `sessions` 表）

- 表结构由 `core/auth.rs` 的 `SCHEMA` 建（不再由第三方 store 建表）：`token`（PK）、`created_at`、`expires_at`（v4.9.30 起不再记 `user_id`）。Cookie 里放的 `token` 就是主键。`HttpOnly`、`SameSite=Lax`、`Secure` 仅 HTTPS 或可信 `X-Forwarded-Proto=https`、`Path` 与 `base_url` 一致。
- **token 只存摘要（v4.9.20）**：`sessions.token` 列存 SHA-256 摘要，明文只存在于浏览器
  Cookie——数据库文件被拷走（备份外泄 / 挂载点被读）也拿不到可直接使用的会话。
  查库 / 续期 / 删行全部按摘要走；token 本身 256 位随机，索引等值查询与明文同速。
- 滑动续期：闲置 7 天过期，绝对上限 30 天（`created_at + 30d`，续期不得越过）。登录与 2FA 通过后轮换 `token`。
- **`verified_at` 高敏确认（v4.6.13 复用 v4.4.1 遗留列）**：v4.4.1 的「5 分钟一次全局闸门」因太扰人被整体移除，终端、令牌、配置写入依旧**不做**任何二次验证；只有备份下载（`POST /api/system/backup`）要求 15 分钟内输过一次密码（`POST /api/auth/verify-password`，与登录共用限流池），窗口内免重复输入。
- 登出删除服务端会话行。改密、2FA 开关、`--reset-password` 后删除该用户全部会话。
- **CSRF**：Cookie 认证的写操作（POST/PUT/DELETE/PATCH）校验 `Origin` / `Referer` 与 Host 同源，`Origin: null` 拒绝；两者都缺失（curl、老网关）放行，由 `SameSite=Lax` 兜底（与实现的既有口径一致，此前文档误写为「缺失即拒」）。`Authorization: Bearer asm_...` 请求豁免 CSRF Origin 校验。公开的 `POST /api/auth/logout` 单独走同一套同源判定（v4.6.13）。
- **WebSocket**：`/api/terminal/ws` 与 `/proxy/{id}` 的 WS 透传（v4.6.13）无条件校验 Origin 与 Host 同源；无 Origin 的非浏览器客户端放行。

### 3.4 Bearer Token 认证

- Auth 中间件优先检查 `Authorization: Bearer`。命中则按 `access_tokens` 校验哈希与过期，映射 `is_readonly` 为请求级权限。未命中回退会话 Cookie。
- WebDAV Basic Auth 复用同一 Token 校验：用户名 = `token_name`，密码 = `asm_` 明文。`access_tokens.token_name` 必须 `UNIQUE`。
- **密码直连（v4.4.0 引入，v4.9.24 放宽）**：Token 校验失败后回退校验 `users` 表（用户名 + 登录密码，Argon2 + 进程内缓存），
  解决「首次部署无令牌可用」的冷启动问题。v4.9.24 起任何 active 用户都可直连（不再限管理员），
  放行 = 全量权限（读写、全部挂载点）；`must_change_password`、TOTP 已开启与停用账号拒绝
  （Basic Auth 表达不了第二因子）。缓存键是「用户名+密码」的 SHA-1（不落明文），
  值存验证时的 Argon2 哈希快照——改密后即时失效。

### 3.5 2FA

- TOTP 可选。开启时生成 10 个恢复码，仅存哈希，展示一次。**每个恢复码验证成功后立即从存储移除**。关闭 2FA 需当前密码 + TOTP 或未使用恢复码。
- **一个框 + 可切换的登录方式（v4.9.48）**：单用户没有用户名，登录页永远只有**一个输入框**，
  默认是密码框；账号开了 2FA 时框下方多一行文字入口「使用动态验证码登录」，点一下**同一个框**
  变成动态码样式（居中、字距拉开、`autocomplete="one-time-code"`、输满 6 位自动提交），
  再点「使用密码登录」换回来。这是 GitHub / Vercel 那类站点的通行做法：**方式可选，框始终一个**。
  没开 2FA 时切换入口不出现，页面上也没有任何「动态验证码 / 恢复码」字样。
- 后端按**哪个字段有值**分派（`credential_mode()`），不猜内容：
  | 请求 | 含义 | 校验 |
  | --- | --- | --- |
  | `{password}` | 密码模式 | 先按一次性码试一次（有人会把码填进密码框），不中再比密码 |
  | `{totp}` | 动态码模式 | 只认一次性码：6 位数字 → TOTP，其余 → 一次性恢复码 |
  | `{password, totp}` | 严格双因子（脚本 / 客户端） | 密码与码都要对，密码错就不碰恢复码表 |
  | `{}` / 两个都空 | 零凭证 | 401 |
  没开 2FA 时只认 `{password}`（`{totp}` 一律 401）。
- **首尾空白不算密码的一部分（v4.9.50）**：写入侧 `create_user` / `update_password` 先 `trim()`
  再哈希；校验侧 `verify_password_lenient()` 先比 `trim` 后的值、再比原样（后者兼容这条规则
  落地前设的「带首尾空格」密码；网页端已 trim，这类存量密码需 `--reset-password`）。
  被抹掉的是**粘贴时多带的空格**与中文输入法留下的全角空格（`U+3000` 也属 `char::is_whitespace`）；
  **中间的空格照留**，`my pass phrase` 是合法密码。纯空白输入直接判失败（不白跑 Argon2）。
  前端 `PasswordInput` 在失焦 / 回车时抹掉首尾空白，**不在 `input` 事件里改**（否则每敲一个空格
  光标就跳一下、中间的空格也打不进去）。`{totp}` 走 `normalize_recovery_code`，分享口令
  同样走 `verify_password_lenient`，三条路径一个口径。
- 校验失败统一回 401 `AUTH_INVALID`（「密码或动态验证码不正确」），**不区分是密码错还是码错**：
  分开报等于给爆破者一个「密码已对」的确认信号。失败计入防爆破池（IP + IP|用户名），5 次封 15 分钟。
- 一次性码的归一化顺手把 `I/L → 1`、`O → 0`、符号与空格剥掉（`normalize_recovery_code`），
  手抄验证码写错字母也能过；分界判据是「归一化后是否 6 位纯数字」（`looks_like_totp()`）。
- **`status` 未登录也回设备级 `totp_enabled`**：只说明「本机账号开没开 2FA」，不涉及密钥，
  前端据此决定要不要给切换入口（不影响框的个数）。
- **安全口径说清楚**：开了 2FA 之后**密码单独仍能进站**——TOTP 在这里是「可替代密码的第二种
  凭证」，不是强制的第二因子。要强双因子只能走 API 侧带 `totp` 字段那条路（网页端没有这个开关，
  用户明确要求「一个框」）。「手机丢了 + 恢复码也没留」仍然走 `--reset-2fa`（3.2），
  动态码模式下方的提示行写明恢复码这条出路。

### 3.6 防爆破

- 独立池：主登录按 `IP + username` + 纯 IP；分享按 `share_token + IP`；WebDAV 按 `token_name + IP`。成功认证重置对应计数。白名单 IP 仅豁免主登录。计数器后台定时 GC。

### 3.7 代理与 SSO

- `X-Forwarded-*` 仅当源 IP 命中 `trusted_ips` 时采信。
  **v4.9.20 更正取值方向**：XFF 是「客户端 → 各跳代理」从左往右追加的，**最左是客户端自己写的
  （可任意伪造）**。取值必须从右往左跳过命中 `trusted_ips` 的代理跳，取第一个不可信地址；
  整条链全可信时（局域网客户端在白名单里）回落最左值。旧实现 `split(',').next()` 取最左，
  反代场景下每次换一个伪造 IP 就能换一个防爆破计数桶、访问日志来源也全是假的。
  代理网关转发前同样重建 `X-Forwarded-For` / `X-Real-IP` 为真实来源，不再原样透传伪造链。
- `proxy_trust.enabled=true` 时，仅当源 IP 命中 `trusted_ips` 才采信 Header；白名单为空拒绝启用并 ERROR。Header 用户名必须等于 `users.username`，否则拒绝登录。`skip_2fa=true` 启动 WARN。
- 本站会话 Cookie 绝不下发给上游；上游同名 `Set-Cookie` 丢弃。

### 3.8 安全响应头

- 默认：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、收紧 `Permissions-Policy`、HTTPS 下 HSTS。CSP 禁止 `unsafe-eval`，`frame-ancestors` 按需。
- **`/proxy/` 不再是安全头真空（v4.9.20）**：旧实现对代理路径整段跳过、代理层又把上游 CSP
  整条丢弃，第三方页面运行在本站 origin 上却零防线。现在中间件对 `/proxy/` 只豁免 CSP
  （其余头照常下发）；代理层把上游 CSP **只剥 `frame-ancestors` 指令后透传**（XSS 防线保留），
  上游没有 CSP 时补 `frame-ancestors 'self'` 兜底防点击劫持。

### 3.9 单用户模型（v4.9.28 回归）

- **一个设备一个账号**：全新安装首启建 `admin` + 一次性密码打印控制台，用户拿它登录
  后在强制改密弹窗换正式密码（v4.9.34，3.1），此后系统里只有这一个账号——它就是这台设备的主人，
  **能登录 = 能做全部动作 = 能看到全部挂载点**。没有角色、没有权限位、没有挂载点收权，
  设置页也不再出现用户管理面板；网页端也不再展示用户名，登录只问密码。
- **为什么回归**：v4.9.24 / v4.9.25 曾按社区通行做法补齐「多用户 + 9 位权限位 +
  挂载点 scope」，但 asmoday 的定位是「一个人的 NAS / 设备中枢」——单二进制、低功耗、
  自己用。多用户带来的是持续的解释成本（谁能看见哪个挂载点、哪个位管哪个按钮），
  而真实使用中几乎只有一个账号。下载引擎更典型：队列、密钥、做种都属于设备主人，
  按用户切开既没有语义也没有收益。
- **Schema 收口（v4.9.30）**：alpha 阶段不再保留多用户遗留，库结构里没有任何
  「归属列」——`users` 只有账号本身（id / 用户名 / 密码哈希 / TOTP / 强制改密），
  `favorites` / `play_history` 主键是 `(mount_id, file_path)`，
  `shares` / `access_tokens` / `sessions` 都不记 owner。会话表也不记 user_id：
  一个库只有一个账号，`find_user` / `first_user` 查到的就是登录者。
- **升级迁移（v20）**：存量库启动时一次性收口——① 多余账号（连同其会话 / 令牌 /
  分享 / 收藏 / 播放历史）物理删除，保留「启用中 id 最小」的那一行，没有启停信息时取
  id 最小；② `favorites` / `play_history` 重建表去掉主键里的 `user_id`
  （SQLite 不允许删主键列），同一路径多行时按时间取最新；③ `users` 的
  `role` / `is_active` / `permissions` / `mount_scope` 与其余表的 `user_id` 直接
  `DROP COLUMN`；④ `<data>/terminal_history/u<id>`（id ≠ 保留账号）目录同步清理。
  日志打印删除的账号数与行数，重复启动幂等。
  **不承诺回滚**：`user_version` 过了 20 之后回到旧版本会因 schema 对不上而失败，
  alpha 阶段接受「删库重建」。v16~v19 四条多用户迁移保留为空占位，只为对齐存量库的
  版本号。
- **登录语义**：库里只有一行，`find_user` 命中即登录者；没有「停用账号」这种状态，
  也就不存在「能查到但拒绝」的分支。
- **管理端点**：`/api/users*` 全部删除。配置、系统维护、备份等端点仍挂 `AdminUser`
  提取器——名字沿用，语义已等价于「已登录」（单用户下登录者即管理员）。
- **WebDAV**：两种凭证——`asm_` 令牌（可只读、可限定单个挂载点）、
  账号 + 登录密码直连（全量）。令牌边界只有它自己的 `readonly` 与 `mount_scope`，
  不再叠加「归属用户权限位」。
- **终端**：不再有 `terminal` 位；登录即可用，会话归属仍是主账号，列表/关闭不再按 owner 过滤。
- **已知限制**：`--reset-password` 固定作用于主账号；前端 localStorage 偏好不分账号
  （本来也只有一个）。

### 3.9.1 权限位与挂载点收权（v4.9.25，已于 v4.9.28 退役）

v4.9.25 的模型（`users.permissions` 9 位位掩码 + `users.mount_scope` 挂载点 JSON 数组、
`mounts_for_user` 统一过滤、写路径逐位 403、WebDAV 位与 scope 交集）随单用户回归整体移除。
保留这段记录是为了让读过旧文档的人知道**为什么代码里还有这些列、却不再有这些行为**：
列留着只为升级/回滚的兼容性，判定逻辑已在 v4.9.28 删除。

### 3.10 aria2 兼容下载引擎（v4.9.26）

**为什么自研**：目标「装 asmoday 就不必再装 aria2」。社区同类（FileCat 托管 aria2、
路由器固件反代 RPC）都依赖外部二进制，与单二进制分发冲突；嵌入 aria2c 又会被杀软判为
自解压载荷。结论：**自己实现引擎 + 讲对 aria2 的 RPC 协议**——客户端只认契约，不关心
背后是谁在下载。

- **端点**：`/jsonrpc`，三种形态同一套分派：
  - `POST`：JSON-RPC 2.0，支持顶层批量数组
  - `GET ?method=…&params=`（params 是 percent-encoded 的 JSON 数组，`+` 视为空格）
  - `WS /jsonrpc`：双向——请求帧 + `aria2.onDownload*` 通知推送（事件来自引擎
    `broadcast`，`params` 只带 GID，与 aria2 一致：客户端随后自己 `tellStatus`）
- **鉴权**：`params[0]` 必须是 `token:<secret>`，否则 `{"code":1,"message":"Unauthorized"}`。
  密钥存在数据库 `settings.download_rpc_secret`（v4.9.36）：首启自动生成，**只在前端下载页
  可见**，刷新也在那里（见下）。与 Cookie 会话体系完全解耦——`/jsonrpc` 不走登录中间件。
- **方法集**（诚实声明能力，见 `getVersion.enabledFeatures`）：
  - 任务：`addUri`（HTTP / magnet 自动分流）/ `addTorrent`（base64）/ `remove` /
    `forceRemove` / `pause` / `forcePause` / `unpause`
  - 查询：`tellStatus`（支持 keys 过滤，`gid` 恒返回）/ `tellActive` / `tellWaiting`
    （offset+num，num=0 表示全部）/ `tellStopped` / `getGlobalStat` /
    `getFiles` / `getUris` / `getPeers` / `getServers`
  - 选项：`getOption` / `changeOption`（`dir` 仍过白名单；`dir`/`out` 仅未开跑时生效）/
    `getGlobalOption` / `changeGlobalOption`（v4.9.39 起 `bt-tracker` 真生效，其余键
    接受但逐条 WARN，仍返回 OK）
  - 维护：`purgeDownloadResult` / `removeDownloadResult` / `saveSession` / `changeUri`
  - 元信息：`getVersion` / `getSessionInfo` / `shutdown`（**不真的关进程**，返回 OK）/
    `system.multicall`（内层 params **不含** token，鉴权只在 multicall 层做一次）/
    `system.listMethods` / `system.listNotifications`
- **`tellStatus` 字段齐全**：`gid/status/totalLength/completedLength/uploadLength/
  downloadSpeed/uploadSpeed/connections/errorCode/errorMessage/dir/files/bittorrent…`
  缺数据填 0 或空（客户端直接绑字段，缺键会渲染成 NaN）。
- **能力声明**：`enabledFeatures` 恒列 `Asmoday / Async DNS / GZip / HTTPS /
  Message Digest / Multi-Connection / Resumable`；BT 会话真的起来时才追加
  `BitTorrent`（见 3.11），否则客户端会自动隐藏磁力/种子入口，不留假可用。
- **引擎**（`core/download.rs`）：
  - 任务状态机：`waiting`（排队，受全局并发信号量限制，默认 5）→ `active` →
    `complete` / `error`；`paused` 属于 waiting 族（aria2 语义），`removed` 进 stopped。
  - 分段：HEAD 探测 `Content-Length` + `Accept-Ranges`；支持 Range 时按
    `[download].segments`（默认 8）均分闭区间并发，每段独立 `seek + write`；不支持
    Range 或无长度时单流（不发 Range 头，收尾比长度）。
  - 断点续传：暂停时把 `{total, etag, segments}` 写成 `<文件名>.aria2` 控制文件；
    恢复要求总长与 ETag 都对得上且目标文件还在，否则从头来（防换文件续传写花）。
    完成即删控制文件。
  - 速度：500ms 窗口增量采样（客户端高频轮询不抖），非 active 恒 0。
  - 重试：单段网络错误/提前断流最多 3 次，退避 1/2/3 秒后从 `done` 处续。
- **落盘安全（v4.9.37）**：RPC 的 `dir` / `out` 必须落在「允许的保存目录」白名单内。
  白名单不是裸绝对路径，而是「挂载点 id + 相对子路径」（`m0` + `downloads`）——下载目录
  必须是文件管理里看得见的目录，否则下完的文件在 asmoday 里找不到；挂载点同时提供只读与
  在线状态，不需要另一套判定。路径 canonicalize 后做前缀比较（Windows 大小写不敏感、
  剥离 `\\?\` verbatim 前缀），越界直接 JSON-RPC fault，不做「夹到根里」的兜底。
  `out` 禁路径分隔符与 `..`。回给客户端的 `dir` / `files[].path` 一律剥离 verbatim 前缀
  （否则客户端用 `/` 拼路径会 open 失败）。
- **开关**：`[download].enable=false` 时端点直接 404（连协议面都不暴露），引擎不创建任务。
- **归属**（v4.9.28）：下载队列、`.aria2` 控制文件、RPC 密钥都属于**设备主人**——唯一账号。
  单用户模型下不存在「谁能用下载」的问题；密钥存数据库（`settings` 表），只在前端下载页
  可见，AriaNg 等客户端凭密钥接入即视为该账号的操作。
- **Web 页面与 REST（v4.9.31）**：内置引擎是一级功能——侧边栏「下载」与文件管理 /
  媒体库同级，`/downloads` 用登录态直接读写任务，不必为了看进度另装客户端。
  同一份 `DownloadManager` 两条通道并存：`/jsonrpc` 保持 aria2 契约给外部客户端，
  `/api/downloads*` 给页面。
  - **页面结构（v4.9.38）**：入口与页面标题统一叫「下载引擎」（不再叫「下载」——
    它既是任务队列也是一个 aria2 兼容的服务端引擎，只叫下载会让人以为是客户端）。
    页内只有两个视图：`任务`（进度列表 + 新建下载）与 `引擎设置`。**设置不再是弹窗**：
    字段一多，弹窗只能在固定高度里滚，也没法对照着任务列表改；改成页内视图后宽屏
    左列「引擎参数」、右列「允许的保存目录 + RPC 接入」，草稿在视图切换之间保留
    （只有首次进入才拉 `/api/config` 与挂载点清单）。
  - **未保存保护与返回（v4.9.40）**：设置视图里参数 / 保存目录 / Tracker 是三个独立
    接口，任一改动过即视为「有未保存改动」——页头标一枚「有未保存改动」、
    「返回下载列表」与路由离开（侧边栏、浏览器后退）都先弹确认，逐条列出会丢的东西；
    「继续编辑」留在原地且草稿不丢，「放弃改动并返回」才回滚三块草稿并切回任务列表。
    **回滚是真的回滚**：参数按进页面时的 JSON 基线还原，目录与 Tracker 按
    `engine.roots` / `engine.trackers` 还原——留着脏草稿下次进来还以为已保存。
    页面底部再给一颗同样的「返回下载列表」，免得滚到 Tracker 卡就找不到出口；
    切视图后滚回顶部，不把人留在上一屏的滚动位置。
  - **系统返回键（v4.9.41）**：设置是页内视图、不在路由里，不接管的话 Android 物理
    返回 / 浏览器后退 / 边缘滑动手势会一步跳过任务列表，直接退回进入下载页之前那页
    （通常是聚合主页）——用户视角就是「点返回掉到首页，设置白改了」。用
    `useBackClose` 在设置视图期间压一条同 URL 哨兵：返回键等价于点「返回下载列表」，
    有未保存改动同样先确认；弹窗里选「继续编辑」时视图不变，哨兵自动重挂，再按一次
    仍能拦住。只有任务视图下按返回才是真的离开本页（哨兵此时已退掉，不会多留一步）。
  - `GET /api/downloads`：`{enabled, bt, global, tasks:{active,waiting,stopped}}`；
    任务沿用 `tellStatus` 字段，另补 `name`（BT 种子名 / HTTP 落盘名，magnet 未解析时为
    空串）与 `kind`（`http` | `bt`）。页面 1s 轮询，标签页不可见时停轮询。
  - `GET /api/downloads/engine`：`segments` / `max_concurrent` / `roots` / `bt_port` /
    `rpc_path` / `rpc_secret` 与 `restart_required`。`roots` 是对象数组
    `{mount_id, mount_name, rel, label, path, online}`：页面只渲染 `label`
    （`电影 / downloads`），`path` 仅用于新建下载的 `dir` 默认值，**不展示完整绝对路径**；
    掉线条目保留但标 `online=false`，下拉里禁用。密钥只在这条管理端点返回（可显隐、
    可复制），供设置视图的「RPC 接入」卡填 AriaNg；前端不落 localStorage。
  - `POST /api/downloads/secret`（v4.9.36）：**刷新 RPC 密钥**——自动生成新值写
    `settings` 表再换内存，旧 `token:` 下一次请求即 401，**不需要重启**。页面按钮为两段式
    （第一次点击变「确认刷新？」，3 秒内再点才执行），避免误触把已配置的客户端全踢下线。
    没有手填入口：密钥一律由服务生成，`[download].rpc_secret` 只在数据库还没有值时
    作为一次性种子导入（之后忽略并 WARN 一次）。
  - `POST /api/downloads/roots`（v4.9.37）：**改「允许的保存目录」**——body
    `{roots:[{mount_id, rel}]}`，写 `settings.download_roots` 再换内存白名单，**立即生效**，
    不需要重启；返回解析后的条目与逐条 `warnings`（未知挂载点 / 只读 / 非法子路径）。
    只接受挂载点 + 相对子路径（`..`、盘符、UNC 一律 400），子目录不存在时自动创建。
    前端在这一块有独立的「保存目录」按钮，不走 `POST /api/config`。
  - `POST /api/downloads`（`{uri, dir?, out?}`，magnet 与 40 位 info hash 自动分流）、
    `POST /api/downloads/torrents`（base64 `.torrent`）、
    `POST /api/downloads/{gid}/pause|unpause`、
    `DELETE /api/downloads/{gid}`（运行中=停掉并移除，已停止=清掉记录）、
    `DELETE /api/downloads/stopped`（等价 purgeDownloadResult）。
  - **引擎参数多数是启动快照**：`enable` / `segments` / `max_concurrent` / BT 端口与
    DHT 开关都由 `DownloadManager::new`（或路由注册）在启动时抓走，改配置不会热生效；
    页面只回显并用 `restart_required` 标注「重启生效」，保存仍走 `POST /api/config`
    （只改 `[download]`，其余段原样回传）。**唯一例外是保存目录**——它走
    `POST /api/downloads/roots` 热替换，`restart_required` 里也不含 `roots`
    （v4.9.37 之前是启动快照，页面只能读、只能改 config.toml，是个死角）。
  - **`paused` 只属于 waiting 族**（v4.9.31 修正）：早先 `pause` 顺手把 GID 塞进
    `stopped` 清单，同一个任务会同时出现在 `tellWaiting` 与 `tellStopped` —— 客户端的
    「已停止」页会多出一条还能继续的条目。
  - **`getGlobalStat.uploadSpeed` 对所有任务求和**（v4.9.31 修正）：BT 完成后的做种
    状态是 `complete`（属 stopped），只统计 active 会让「做种上传」恒为 0。
- **已知限制**：Metalink / FTP / SFTP 未实现（features 里不声明）；无上传限速、无更细的
  传输选项；`shutdown` 不真的关进程。BT 见 3.11。

### 3.11 BitTorrent 下载（v4.9.27）

**为什么引依赖而不是自研**：HTTP 是线性协议，自己写分段够用；BT 不是——要 bencode、
metainfo 校验、HTTP/UDP tracker、DHT、PEX、peer wire（含 choking/interest 状态机）、
分块调度、SHA-1 校验、做种与上传。自研能跑通「两个自己做种/下载」的演示，但私有
tracker、magnet、IPv6、uTP 这些互操作细节会长期补不完，而这正是 aria2 的护城河。
结论：**用纯 Rust 的 librqbit 编进同一个可执行文件**——不起外部进程、不落地第二个
二进制，单文件分发不受影响（与 3.10 拒绝「托管 aria2 进程」的理由不冲突）。

- **版本钉 8.1.1**：9.x 改用 reqwest 0.13，其 `rustls` 特性强制 aws-lc-rs，
  等于再拉一份 TLS 栈 + 一个必须 cmake/perl 的 C 构建，musl 交叉编译（9.3）直接废。
  8.1.1 仍是 reqwest 0.12，与主程序**共用同一份 TLS 与连接池**。
- **SHA-1 实现替换**（`vendor/librqbit-sha1-wrapper`）：上游只提供 `crypto-hash`
  （unix 落 openssl-sys）与 `aws-lc-rs`（C 构建）两种后端，两者都要外部工具链。
  本地 crate 用 RustCrypto `sha1`（已在依赖树里）实现同一个 `ISha1` / `Sha1` 接口，
  feature 名保持不变，`[patch.crates-io]` 顶替。校验算法不变，只是去掉 C 依赖。
- **会话**：进程级一个 `librqbit::Session`（`core/bt.rs`）。DHT 状态落
  `<data>/bt/dht.json`；**不启用 UPnP**（不替用户开路由器端口）；**不启用会话持久化**
  （重启后恢复出来的任务不在 RPC 任务表里，会出现「磁盘在涨、列表里没有」的幽灵下载）。
  入站监听端口取 `[download].bt_listen_port_min..max`（上下界都为 0 = 只出站）。
- **任务模型**：`TaskKind::Http | Torrent` 共用一套队列与状态机（3.10）。差别只在进度：
  - HTTP：进度 = 自己写入的字节（`segments[].done` 之和）；
  - BT：进度 = **校验通过的字节**（`ManagedTorrent::stats().progress_bytes`），
    不能自己累加——librqbit 启动时会把已有文件重新校验一遍，自己计数会重复。
  - `tellStatus.files` 对 BT 逐条列出（`index/path/length/completedLength/selected`，
    AriaNg 的「文件选择」直接绑这个数组）；`bittorrent` 子对象给
    `info.name` / `announceList` / `mode`（单文件 single / 多文件 multi）。
  - `infoHash` / `pieceLength` / `numPieces` / `uploadLength` / `uploadSpeed` /
    `verifiedLength` 都来自 stats，不再恒 0。
- **生命周期**：`add_torrent` 立即返回 GID，真正的 `Session::add_torrent` 在后台协程里做
  （magnet 要先解析元信息）。协程每 800ms 同步一次 stats：完成 → `complete` +
  `onBtDownloadComplete` + `onDownloadComplete`；失败 → `error`。**暂停不退出协程**
  （用户随时可能恢复），`unpause` 只调 `Session::unpause`。删除 / 清空已完成任务时
  一并 `Session::delete(delete_files=false)`——已完成的任务仍在做种，不释放会一直传数据。
- **RPC 增补**：`addTorrent`（base64 种子上传）、`addUri` 自动识别 `magnet:` 与 40 位
  裸 info hash、`getFiles` / `getUris` / `getServers` / `getPeers` / `changeUri` /
  `saveSession`；`getVersion.enabledFeatures` 在会话真正起来时才追加 `BitTorrent`。
  `select-file` 选项按 aria2 语义解析（1 基、"1,3-5" 区间）后转 0 基传给 `only_files`。
  `getPeers` 返回空数组：librqbit 不暴露 peer 明细，返回伪造地址比空列表更糟。
- **Tracker 管理（v4.9.39）**：librqbit 只认「种子里带的」和「加种子时给的」两处
  announce，没有运行时增删接口；而用户换私有 tracker、补公开 tracker 是常态，之前
  只能把 `tr=` 拼进 magnet，等于没有入口。现在：
  - 列表存 `settings.download_trackers`（JSON 数组，页面 / RPC 可改，重启仍在），
    `[download].bt_trackers` 只在库里还没有值时当一次性种子。
  - 语义**对齐 aria2 的 `bt-tracker`**：追加到每个**新**任务的 announce 列表，不替换
    种子自带的那份；已在跑的任务不追溯（librqbit 在 `add_torrent` 时就建好 tracker
    轮询流，改动只对之后添加的种子生效——aria2 的全局选项同样是这个口径）。
  - 两种来源分别落地：`.torrent` 走 `AddTorrentOptions::trackers`；magnet 只能改 URI
    （librqbit 8.1.1 的 magnet 分支**忽略** `AddTorrentOptions::trackers`，只读 `tr=`），
    所以追加前先解析已有 `tr=` 去重，再按 RFC 3986 百分号编码补 `&tr=`。40 位裸 info
    hash 先补成完整 magnet 再追加。
  - 归一化（`normalize_trackers`）：换行 / 逗号 / 空格混写都能吃下；只放行
    `http(s)/udp/ws(s)`，空主机名与其它 scheme 逐条回 `rejected` 给用户看；
    上限 200 条（防一次粘贴几万行把 UI 和加种子拖死）。
  - RPC 侧同时补上契约：`getGlobalOption` 回 `bt-tracker`（逗号分隔），
    `changeGlobalOption` 对 `bt-tracker` **真的生效**（写库 + 换内存），其余键仍按
    aria2 语义回 OK 但逐条 WARN —— 以前是「一律 OK 什么也不做」，AriaNg 改完看不出来。
- **落盘安全**：沿用 3.10 的 `roots` 白名单，`dir` 越界直接 fault；多文件种子由 librqbit
  在目标目录下建子目录（与 aria2 一致）。`out` 对 BT 仅作展示名，不参与路径拼接。
- **配置**（`[download]`）：`enable_bt`（默认 true）、`bt_listen_port_min/max`
  （默认 6881-6999）、`bt_disable_dht`（默认 false，开启后只走 tracker）。
  会话起不来只降级成 HTTP-only 并记 WARN，不让整个服务跟着挂。
- **已知限制**：不做 Metalink / FTP；`getPeers` 无明细；单密钥单队列（与 3.10 相同，
  BT 任务尚未按用户隔离）；上传不限速、不做种比率自动停止。

## 4. 文件管理

### 4.1 视图与过滤

- 仅网格视图与列表视图。偏好写 `localStorage`。
- 后端硬编码过滤垃圾文件（列表、媒体扫描、WebDAV PROPFIND 均生效）：精确匹配 `desktop.ini`、`Thumbs.db`、`.DS_Store`、`lost+found`、`.Trashes`、`.Spotlight-V100`、`.fseventsd`、`$RECYCLE.BIN`、`System Volume Information`；前缀 `~$`、`._`；后缀/包含 `*.crdownload`、`*.part`、`*.!ut`、`*.tmp`。普通隐藏文件受 `show_hidden` 控制。
- 路由：每次 `/files` 拉取 `/api/files/mounts`。零挂载点空状态；单挂载点在线 `router.replace` 至 `/files/:mountId/`；单挂载点离线停留卡片；多挂载点卡片列表。
- **目录导航进历史栈（v4.6.16）**：进目录 / 面包屑 / 返回上级一律 `router.push`——浏览器返回键必须回到上一个目录而不是掉出文件管理（v4.6.15 用户反馈）；`replace` 只保留给 boot 落地、单挂载点跳转、操作后的原地刷新。后退/前进由路由监听器接管：先贴会话快照（免骨架）再静默刷新。
- **目录快照键带挂载点路径（v4.6.16）**：挂载点 id 是配置序号（m0/m1），改挂载点指向后 id 不变，只按 id 存取会把旧位置目录的上一帧当新位置的缓存贴回来；快照键改为 `files:{id}:{mountPath}/{segments}|flags`，且 boot 拉到挂载点清单与上一帧不一致（增删/改名/改路径/掉线变化）时立即丢弃贴回的旧帧进骨架态。
- 面包屑：多挂载点 `[🏠] / 挂载点 / 目录`；单挂载点 `[🏠 挂载点] / 目录`。

### 4.2 预览矩阵

- 图片/视频/音频：全局 `MediaLightbox` / 全局播放器，单实例。图片收集同目录同类型数组，支持左右切换。
- 文本/代码：CodeMirror 6。Markdown 默认渲染预览（`marked` + `DOMPurify`），可切换源码。PDF `<iframe src="raw_url">`。CSV 超 5MB 或 1000 行截断。Office/CAD/压缩包提示下载。
- 编辑器：后端返回 `eol_type: "lf"|"crlf"`、`has_bom`。保存原样写回 EOL 与 BOM。状态栏展示编码与 EOL，可手动切换。读取默认 UTF-8，失败尝试 GBK，UTF-8 BOM 剥离并记录。
- 语言自动识别：按扩展名映射，无后缀/特殊后缀正则兜底，未知降级纯文本。语言包动态 `import()`。顶部下拉框可手动切换。
- **编辑器整屏接管（v4.4.5）**：点开文件即铺满整个浏览器（`Teleport` 到 `body` 的
  `fixed inset-0`），侧边栏与顶栏全部让位——代码编辑器挤在 240px 侧边栏 + 工具栏右侧的
  窄条里，行一长就得横向滚动，手机上更是只剩两三行。选 `Teleport` 而不是就地 `fixed`：
  文件页在 `#app-scroll` 里，路由过渡期祖先带 `transform`，就地 `fixed` 会变成相对祖先
  定位而错位。列表不卸载，关掉编辑器立刻回到原目录与滚动位置，不重新拉一遍。
- 顶栏顺序与我们其他页一致：关闭（×）→ 文件名（未保存加点）→ 字号步进器
  （`− 14px +`，点中间回默认，值存 `asmoday.editor.fontSize`）→ 语言下拉 → 保存（带 `Ctrl+S`）。
  窄屏只留关闭 / 文件名 / 语言 / 图标版保存，字号控件隐藏（默认 13px）。下方一行是
  虚拟路径面包屑（挂载点名 › 目录 › 文件名，可横向滚动），与列表面包屑同一口径，
  绝不摊开真实盘符路径。
- 保存前关闭不再用原生 `confirm`：弹「取消 / 保存更改 / 放弃修改」三选一。
  原生只有两态，想「存一下就关」得先取消再存再关，而且样式在移动端完全不可控。
  `closeEditor()` 因此变成 `async`，调用方（换目录、开预览、面包屑、路由守卫）
  一律 `await` 结果——用户点取消或保存失败就中止后续动作，不再「关了编辑器却换了目录」。

### 4.3 流式传输与性能

- 上传单文件上限 `upload_max_size_mb`，上传前检查剩余空间。上传同名冲突沿用 `on_conflict`。
  小文件（≤ `upload_chunk_size_mb`）整包 PUT；大文件走 tus 分块（见 4.3.1）。
  **v4.6.14 起整包 PUT 与 tus init 共用同一套目标校验**（路径 / 只读 / 空间 / 授权根），
  只读挂载点此前可被整包上传写入的口子一并堵上。
- **整包 PUT 流式化（v4.9.20）**：旧实现 `body: Bytes` 把整个请求体（上限 0 = 4 GiB）
  先整包缓冲进内存再写盘，并发几个大上传就是成 GiB 的堆占用。现在逐帧
  `body.frame()` 落盘，内存占用恒为单帧 chunk；`Content-Length` 可用先做空间预检，
  没带就边写边累计、超限即停并清临时文件。落盘走 `path_guard` 的原子改名
  （`no_replace` 消除「检查后被人抢先创建」的 TOCTOU，`replace` 兼顾 Windows），
  目标路径纳入 per-path 锁（上传与删除/移动同名文件互斥）。
- **临时文件名唯一化（v4.9.20）**：整包上传与文本保存的 `.tmp` 旧名是固定的，
  同名并发上传 / 两标签页同时保存同一文件会互相覆盖再 rename，产物是两次写入
  交错的字节汤。现在都带 `random_token()` 后缀。

#### 4.3.1 tus 分块上传与断点续传（v4.6.14，参照 FileBrowser Quantum）

- **协议**（tus 1.0.0 子集，`/api/files/upload/tus`）：
  `POST` 建会话（`Upload-Length` 声明总长，query 带 `dir` / `name` / `conflict=fail|overwrite|rename`）
  → `HEAD` 查偏移 → `PATCH` 追加分片（`Upload-Offset` + `application/offset+octet-stream`）
  → `DELETE` 取消。收满即自动落位，不需要单独的 complete 请求。
- **偏移的权威是临时文件长度**：HEAD 直接 stat `<data>/uploads_tmp/<id>.part`。
  客户端断线 / 换标签页 / 刷新后，凭 localStorage 里的会话地址问一次偏移即可续传；
  分片 PATCH 也是流式追加落盘，服务端内存占用恒为缓冲区（顺手修正了整包上传
  `body: Bytes` 全量进内存的历史矛盾——整包路径仍保留给小文件）。
  **PATCH 内的推进不用 stat（v4.9.22）**：偏移 = `Upload-Offset` + 本次收到的字节数，
  且收字节数必须在 `write_all_buf` **之前**取（它会推进 `Buf`，写完 `len()` 恒为 0）。
  以前写完立刻 `metadata`，Windows 上小分片会读到旧长度：传完 5 字节回 `upload-offset: 0`
  且不落位，客户端再 PATCH 同一 offset 就吃 409 —— 小文件分块上传卡在一个永远填不满的环。双错叠加，
  只有「几百 KB 以上」的冒烟能过，5 字节必然失败。
- **会话状态只在内存**（与 FileBrowser 的 MemUploadCache 同级取舍）：服务重启时
  无条件清空 `uploads_tmp/`（半成品必然无人认领）；运行期按 24 小时 TTL 兜底清理
  会话表之外的孤儿 `.part`。客户端拿 404 就重新 init 从头传。PATCH 有 120 秒**空闲**超时
  （只要还在出数据就不会被打断）：半开连接会一直握着会话锁，用户点取消毫无反应（v4.9.22）。
- **落位**：优先原子改名（同设备瞬时）；数据目录与挂载点不同盘时走
  `fs_ops::copy_file_to` 的「按**已解析的 final_name** 复制 + 长度校验 + 删源」。
  **不能用 `move_entry`（v4.9.22）**：它按源文件名落位，而源是暂存文件——改名后叫
  `.asmoday-tus-<name>`，结果就是接口回 204、目录里只有一个隐藏的暂存名文件，
  `conflict=fail|rename` 也一并失效。冲突语义在落位时执行：`fail` → 409
  `E_CONFLICT`；`overwrite` → 覆盖（目录仍拒）；`rename` → `名称 (n).扩展名`。
  复制失败时源文件不动，会话保留可重试；落位整体 `spawn_blocking`，不占 runtime。
- **配额**：init 时按 `Upload-Length` 校验 `upload_max_size_mb` 与剩余空间；
  PATCH 收到的总量超过声明长度 → 400 并销毁会话（防计数器漂移无限增长）。
  `upload_chunk_size_mb = 0` 关闭分块，全部走整包 PUT（前端行为随之退化）。
- **会话操作锁（v4.9.20）**：同一 id 的 PATCH / DELETE 由 `TusStore` 的 per-session
  异步锁串行——两个并发 PATCH 同一 offset 是典型 TOCTOU，`O_APPEND` 只保证单次
  write 不覆盖、不保证多个 chunk 不交错，长度凑满时会静默产出损坏文件。锁覆盖
  「校验偏移 → 流式写 → 落位/删除」整段；抢到锁后重新 get 会话（等待期间可能已
  被并发 DELETE 落位删除）。finalize 失败**保留会话**（临时文件完好，客户端修掉
  冲突后再 PATCH 一次即可重新落位），落位目标纳入 per-path 锁。
- **前端**：`upload_chunk_size_mb` 随 `GET /api/files/mounts` 下发；超过阈值走 tus，
  否则整包。失败任务在进度面板出「重试」按钮，同一文件重新拖入也会命中
  localStorage 凭证从断点续传（目录+名字+大小+mtime 全一致才算同一文件）。
- 下载/播放支持 Range、HEAD、`ETag`、`Last-Modified`、`Accept-Ranges: bytes`。中文文件名 RFC 5987。
- **下载必须走 `?download=1`（v4.4.9）**：`raw` 带这个参数时回 `Content-Disposition: attachment`
  （`filename` ASCII 兜底 + `filename*=UTF-8''…`）与 `application/octet-stream` + `nosniff`。
  以前前后端都用 `window.open(raw)`，浏览器会就地渲染：TOML / 日志变成一页乱码（
  `mime_guess` 给 `text/plain` 但不带 charset，中文 Windows 按 GBK 解码），目录则直接报错。
  非下载的文本响应统一补 `charset=utf-8`。
- **目录下载 = store 模式流式 ZIP（v4.4.9）**：`/api/files/archive` 不压缩、不落临时文件，
  边读边发（数据描述符承载 CRC 与长度，只读一遍文件）。媒体库里 99% 是已压缩的
  JPEG / WebP / MP4，deflate 只换来 CPU 与等待。两条硬边界：单文件 ≥4GiB 与条目数 >65535
  直接拒绝（不实现 Zip64），提示单独下载。不跟随软链接——指向 `/` 的链接会把整机塞进 zip。
- **触发下载必须用隐藏 iframe，不能用 `<a download>`（v4.6.0）**：点 `<a>` 等于顶层文档导航，
  浏览器要拿到 `Content-Disposition` 才会把它转成下载；而浮层关闭会触发 `useBackClose` 的
  `history.back()` 退哨兵，这一退恰好把「还没转成下载」的导航中止（CDP 里是 `net::ERR_ABORTED`），
  表现就是**右键菜单里的下载毫无反应**。改成同源隐藏 iframe 后顶层文档不动，下载照常落盘。
- **多选下载 = 一个 zip，不是 N 个下载（v4.6.0）**：同一次手势连开多个下载，浏览器按「多文件下载」
  拦截（Chrome 只放行第一个，手机上连提示都没有），所以多选改走 `/api/files/archive?paths=[…]`。
  **目录也一起打包**（旧实现只挑文件，选中文件夹等于被静默忽略）。zip 内每个目标以自身名字为顶层，
  跨目录同名（搜索结果多选）补序号 `name (2).ext`；包名取「共同父目录名」，跨目录时回落 `download.zip`。
- **稳定排序键 + 游标分页**，禁止 offset。游标键：名称 `(name, path)`、时间 `(mtime, path)`、大小 `(size, path)`。切换排序清空列表重新请求。单页 **200 条**（v4.6.23，原 1000）：一万张图的目录一次回 1000 条 EntryInfo 就是几百 KB 的 JSON + 一轮长列表渲染，首屏出图被拖慢；分页是游标续接，降页大小不影响「能看到最后一条」。
  **名称键的分量是 `(小写名, 原名)`（v4.9.22）**：Linux / macOS 上同一目录可以同时存在 `A.txt` 与
  `a.txt`，只按小写比较时两者完全相等，`position(|> 游标|)` 会把其中一条判成「不在游标之后」
  而永久跳过 —— 列表凭空少一条且无任何报错。游标里也存原名（小写名不足以区分）。
- **目录没有扫描上限**（v4.2.4）：文件管理要和本地管理器一样能翻到最后一条，任何排序下 `total` 都等于目录真实条数。性能靠两件事而不是截断：排序键并发补全（24 路，等价于把「串行两万次 stat」压到百毫秒级）、条目容器只留 `i64` 排序键（不再为每条常驻一整个 `Metadata`）。`truncated` 字段随上限一起移除。
- **键盘与拖拽**（v4.2.4）：`F2` 重命名、`Delete` 删除（均复用已有弹窗，不新增 UI）、`Ctrl/⌘ + C/X/V` 内部剪贴板、`Ctrl/⌘ + A` 全选、`Shift + 点击` 范围选择、`Esc` 逐层关闭弹层；把条目拖到文件夹 = 移动，按住 `Alt` 拖 = 复制。快捷操作一律先按 `skip` 落盘，命中同名再回退到移动/复制对话框让用户明确选择——**绝不静默覆盖**。焦点在输入框/富文本里时不抢键，移动端不挂键盘（长按多选保持原样）。
- 单个 `stat` 失败逐项容错，标记 `stat_error`。

- 全局 `ContextMenu` 复用于文件、相册、影视库、音乐列表。菜单含下载（文件与目录都支持）、在此终端中打开、分享、复制直链、重命名、移动、复制、删除、属性。
- **媒体库与文件管理是同一套变更能力（v4.6.6）**：菜单里的重命名 / 移动到 / 复制到 / 删除 / 属性
  一律由 `components/FileOpsDialogs.vue` 承载，媒体库不再有「只能看不能改」的孤岛。相册卡片、
  影视文件夹卡片、音乐库分区标题同样可右键（长按）——它们就是目录。库根（挂载点本身）只给
  「打开」与「复制」，只读挂载点的变更项按 `/api/files/mounts` 置灰并给原因。
  媒体库里的「在此终端中打开」不提供：终端要的是一个目录，媒体条目是文件，路径语义对不上。
- **空白处右键 = 对「当前目录」动手（v4.6.7）**：条目右键管的是那一条，列表空白处右键管的是
  这个目录本身——新建文件夹 / 新建文件 / 上传 / 粘贴（内部剪贴板非空时才出现）/ 在终端中打开 /
  刷新 / 显示隐藏文件 / 全选。空目录的空状态也吃同一套事件（它铺满内容区）。判断用
  `event.target.closest('[data-entry]')`：条目的 handler 不 `stopPropagation`，冒泡到容器时必须
  认出来放行，否则一次右键会弹两层菜单。空白处右键同时清掉条目高亮，避免「以为接下来操作的是那一行」。

- **浮层里的动作只要会引发顶层导航，就必须「先导航、后关浮层」（v4.6.7）**：浮层关闭会触发
  `useBackClose.disarm()` 的 `history.back()`，若此时目标页还在加载（终端是懒加载 chunk），
  这条 back 会把 in-flight 的导航取消掉（vue-router 回 `NavigationFailure=cancelled`），表现是
  「点了完全没反应、URL 原地不动」。v4.6.0 的下载、v4.6.7 的「在终端中打开」都是这个坑。

- **窄屏（≤639.98px）自动切成底部动作面板（v4.6.0）**：触屏没有右键，同一个组件在 `isSheet` 下设

  （定位逻辑不变）。文件页/相册/影视库/音乐列表因此都获得同一套移动端操作入口。

  只保留有实际用途的「复制图床直链」。`relativePathOf` / `copyPath` 一并删掉，不留死代码。
- 复制绝对路径：`/api/files/stat` 的 `real_absolute_path`（`canonicalize` 结果）。仅管理员控制台可用；分享访客 API 不返回物理路径字段。

### 4.5 变更操作

- 通用：校验 `mount_id` 与 `path` 归属；`path` canonicalize 后必须在挂载点 `canonical_root` 下。只读返回 `E_READONLY`。挂载点根启动时 canonicalize 存 `canonical_root`。不存在目标 canonicalize 父目录并校验。
- **网络驱动器（UNC）两类形态必须都认**：Windows 上 `canonicalize("Z:/")` 得到
  `\\?\UNC\srv\share\`（Prefix + RootDir 两个组件），而 `canonicalize("\\srv\share")` 得到
  `\\?\UNC\srv\share`（只有 Prefix）。只差一个 RootDir，`Path::starts_with` 会把共享下**所有**子路径
  判成越权，表现为「挂载点在线、点进去每个目录都报 `E_PATH_TRAVERSAL`」。归属判定统一走
  `path_guard::within()`（`starts_with` 或段比较），不允许各 handler 自己写。
  展示路径一律还原成 `//srv/share`（verbatim UNC 直接剥 `\\?\` 会得到 `UNC/srv/share`，丢了 `//`
  锚点就是相对路径，前端回传必然 404）。
- **挂载点集合带 10 秒缓存（v4.9.21）**：`path_guard::load` 对每个挂载点都要 `canonicalize` + `is_dir`，
  本地盘几毫秒、SMB 上 100ms~1.8s；而前端 `GalleryView` 每 10s 轮询一次 `/api/files/mounts`
  （`FilesView` 30s 探活），等于常驻一条网络往返。现在 `mounts_for` 结果在进程内缓存 10 秒，
  `mounts_revision` 一变立即失效（配置热重载不滞后），在线/掉线状态最多滞后一拍 —— 与轮询粒度一致。
- 新建/重命名：名称校验非法字符、控制字符、结尾空格/点、Windows 保留名、`.`/`..`。目标存在一律拒绝。
- 移动/复制：同挂载点移动原子 `rename`；复制流式 `tokio::io::copy`。跨挂载点：流式复制到 `原名.asmoday-part.<8位[a-z0-9]随机码>` → 比对字节数（可选 SHA-256，仅 <100MiB）→ 原子改名 → 移动删源。源删除失败返回 `E_SOURCE_DELETE_FAILED`，UI 提示手动清理。目标空间不足拒绝。目录冲突 `overwrite` 拒绝（`E_DIR_CONFLICT`）。
- 自动命名：`基础名 (n).扩展名`，n 从 1 到 999，超出 `E_CONFLICT_RETRY_EXHAUSTED`。
- **`.asmoday-part.<8位>` 是唯一的临时文件命名（v4.9.22）**：整包上传、文本保存、复制/跨盘移动
  全走 `path_guard::part_name()`（自带 8 位随机后缀，同名并发不会互相覆盖）。这个标记同时是
  列表过滤、启动清理、`/raw` 拦截、ZIP 打包排除的共同依据 —— 此前上传/保存自造
  `.xxx.asmoday-upload.tmp` / `.asmoday-save.tmp`，进程被强杀后那半截文件永远留在用户目录里：
  默认看不见、清理任务不认、还会被 `archive::plan` 打进用户的下载包。
- **目录复制中途失败要回滚（v4.9.22）**：`create_dir` 成功即证明目标是我们建的，`copy_dir_contents`
  任一步失败就 `remove_dir_all` 再上报。半截目录的名字与层级跟完整复制一模一样，用户看不出少了什么；
  重试还会被 `NameBook` 当成已占用，`rename` 策略下变成「相册 (1)」「相册 (2)」越试越多。
- **删除**：物理硬删。单目录需 `confirm_name`；批量需 `delete-token`。删除后级联清理 `favorites / play_history`；`shares` 软删，访问返回 410。
  **`DELETE /api/files/raw` 走同一套级联（v4.9.22）**：这条老路由此前只清缩略图缓存，留下
  「DB 说有、磁盘没有」的死记录——分享不转 tombstone（访客拿到 404 而不是 410，30 天清理也永不触发）、
  收藏点开即 404。
  **前缀匹配一律 `substr(file_path, 1, length(?1) + 1) = ?1 || '/'`（v4.9.22）**：SQL 的 `LIKE`
  里 `_` 是任意单字符、`%` 是任意串，删 `IMG_1234.jpg` 会连带清掉 `IMG-1234.jpg` 的收藏与分享，
  且不发生任何错误提示（文件名的 `_` 极常见）。
- **应用数据目录是「保留目录」**：`data/`（SQLite / 日志 / 缩略图缓存）在启动时登记，列表不返回、
  `/api/files/*` 与 WebDAV 一律 403（`E_FORBIDDEN`），媒体扫描与搜索跳过。默认「未配置挂载点时挂 cwd」
  + 「数据目录 `cwd/data`」天生重叠，不拦的话缩略图缓存会作为普通图片被再次缩略图，产物写回同一目录、
  下一轮又成为新的「图片」，按宽度倍数指数增殖。显式把数据目录挂出来时该挂载点整体不可见，启动日志 WARN 提示。
- 并发：按规范化路径字典序获取 per-path 内存锁，冲突立即 `E_BUSY`，不排队。
- 软链接：链接类条目（符号链接 + Windows junction / 挂载点重解析点）统一识别，
  `tokio::fs::metadata` 跟随判定目标类型，返回 `is_symlink`、`target_is_dir`、`symlink_target`。
  **逃逸策略由 `[system].follow_symlinks` 决定**（默认 `true`，与 FileBrowser 行为一致）：
  - `true`：挂载点内的链接指向挂载点外时照常浏览 / 预览 / 上传 / 改名，**寻址始终以链接路径为前缀**
    （接口返回的路径不替换成目标真实路径，否则下一次请求会带着挂载点外的绝对路径回来被拒绝）；
    列表不再标断链。**直接传挂载点外的绝对路径依旧 403** —— 放开的只有「链接解析」，不是「任意路径」，
    判定条件是「路径字面上在挂载点内 + 沿途至少有一段是链接」；
  - `false`：维持严格边界，target canonicalize 不在 `canonical_root` 下返回 `E_SYMLINK_ESCAPE`
    （跨挂载点链接同样拒绝），列表按断链置灰。
- 复制软链接不跟随（复制的是链接本身）；`follow_symlinks=false` 时拒绝复制指向挂载点外的链接
  （避免把这个「洞」搬到新位置）。删除只删链接本身，绝不递归删目标。
- 挂载点热移除：前端中断请求，重定向 `/files` 提示。离线直达子目录阻断回卡片页。

### 4.6 搜索（v4.2.6）

- `GET /api/files/search?q=&path=&recursive=&limit=&cursor=`：文件名**包含**匹配（大小写不敏感），
  `recursive=false`（默认）只搜当前目录第一层，`true` 搜整棵子树。**没有结果条数上限**，
  只有「单页多少条」（`limit` 默认 200、上限 1000）与「单页扫描预算」（50 000 条目）。
- **确定序 DFS + 栈游标**：每层目录内按「目录优先 + 名称升序」排序（`readdir` 顺序不可依赖），
  深度优先遍历；游标记录 `[(目录相对路径, 下一个待访问条目名), …]`，base64url(JSON) 交给前端。
  续页只重开栈里的那几个目录，代价与页数近似无关；目录中途增删最多重复一条（前端按路径去重），
  不会像 offset 分页那样整体错位。坏游标按「从头开始」处理，不报错。
- **游标是输入不是凭证（v4.6.13 安全收紧）**：`open_frame` 拼出的每层路径必须仍在
  搜索根内（词法 `starts_with` 断言），带 `..`、绝对路径或 Windows 盘符/UNC 段的游标
  一律按「该层已失效」放弃——绝不去读挂载点外的目录。
- **扫描预算不是截断**：一页访问满 `budget` 条就把游标交出去，前端看到的是「继续加载」，
  而不是「只搜到这里」——十万条目的极窄关键词也能逐页翻到底。
- 跳过口径与列表完全一致（共用一个 `skip_listing_name`）：`.asmoday-part*`、系统垃圾、
  应用数据目录一律不出现；但**搜索不理会 `show_hidden`**（用户敲了关键词就是明确想看）。
- 链接目录默认不递归（与列表「指向目录的链接不冒充目录」同口径）；`follow_symlinks=true` 时才进，
  用 `canonicalize` 结果去重防环，另有 `MAX_DEPTH = 32` 兜底。无权限目录直接跳过，不让整次搜索失败。
- 响应带 `scanned`（本页扫过多少条）、`has_more`、`next_cursor`，每条命中带 `rel`（相对搜索根的
  POSIX 路径）——结果可能来自任意子目录，不标出来用户不知道它藏在哪。
- **前端触底判定在虚拟列表内部**：`VirtualList` / `VirtualGrid` 自己就是滚动容器
  （`h-full overflow-y-auto`），放在它们外面的 1px sentinel 永远处于可见状态，
  `IntersectionObserver` 只会在首屏响一次（1000 条以上的目录翻到第二页就停）。
  现在组件自己在 `scroll` 里判断「距底 < 240px」并 emit `bottom`（同一底部窗口去重），
  追加后重新打量一次，一页填不满视口会自动补下一页。搜索结果复用同一条通道。

### 4.7 目录快照缓存（v4.3.0）

递归搜索原来每走一层都要 `readdir`，五万条目的树翻一页就要几百毫秒，翻到底等于把整棵树
重读几遍。这里加一层**目录快照缓存**（`core/dir_cache.rs`，落在同一个 SQLite 里）：

- 表 `dir_snapshots(path PRIMARY KEY, stamp, entries BLOB, entry_count, used_at)`：
  一个目录一行，`entries` 是自定义紧凑二进制（12 字节/条，5 万条约 600 KB），
  只有 `name` 与 `kind`（文件 / 目录 / 链接）。命中时继续用这套顺序，不再重排。
- **判定靠目录 mtime**：目录内容的名字集合只在创建 / 删除 / 改名时变化，这三种操作都会推进
  父目录 mtime；mtime 对得上就说明名字集合没变（大小 / mtime 这类「原地会变」的字段一律不入缓存，
  命中条目要展示时现 `lstat`）。
- **只收留「落定」的目录**：目录 mtime 距现在不足 **2 秒**一律不入库。时间戳分辨率是系统时钟粒度
  （Windows 约 15.6 ms），留 2 秒余量才能保证「入缓存之后发生的任何变化」得到一个**严格更大**的
  mtime，从而失配重扫——同一 tick 内的两次操作不会被误判成「没变过」。正在上传 / 解压的目录
  本来也一直在变，不缓存它们正好。
- 缓存是**尽力而为**：任何 SQLite 错误都当 miss，库被删、表被改、路径换挂载点，最坏退回
  「每次 readdir」，绝不让搜索失败。`MAX_DIRS = 4096` 按 `used_at`（+ rowid 兜底，同一秒内也能
  分出先后）做 LRU 裁剪。
- 实测（5 万文件 / 201 目录 / 关键词只命中 10 条，release）：首次 406 ms（建缓存），
  之后 57–77 ms（含**重启进程后**的首次，缓存是持久的），约 5–7×。
- 顺带一处与缓存无关的优化：**只为命中的条目付一次 `lstat`**。`readdir` 自带名字与类型，
  大小只有要展示的那几条才有意义——原来十万条目录要打十万次 `stat` 只为显示一个 size。
- 媒体库是同一套思路的**第二张表**（`media_snapshots`，条目多带 `size` / `mtime`），
  见 6.5。

### 4.8 系统返回键与浮层层级（v4.4.4）

编辑器、灯箱、预览面板、确认弹窗都不在路由里，此前按 Android 物理返回 / 浏览器后退 /
移动端边缘手势 = **直接离开当前页面**：有未保存修改也只是静默丢弃，用户可能只想关掉
一个大图或一个编辑器，却把整个目录位置一起退掉了。Esc 早有分层关闭（`closeTopLayer`），
系统返回却没有对应物，两条入口的行为必须对齐。

实现（`web/src/composables/useBackClose.ts`）：

- **一层浮层 = 一条历史记录**。浮层打开时压一条**同 URL** 的哨兵记录
  （`history.pushState`，state 里打 `__asmodayBack` 标记，同时保留 vue-router 的
  `position` / `scroll` 字段），不随层数增长——多层并存也只有一条。
- **popstate 先关最上层**：收到返回后关掉 `layers` 栈顶，若还有层开着就重新支起哨兵，
  逐层退出；全部关完才把返回让给路由。
- **UI 自己关掉时退哨兵**：若哨兵仍停在当前历史位置就 `history.back()` 把它消费掉，
  保证历史深度始终等于「用户感知的层数」，不留按了没反应的空步。
- **取消要重新武装**：`close()` 可能被用户取消（「有未保存的修改，确定关闭？」点取消），
  这时浮层仍开着，必须等一轮响应式更新后重新支起哨兵，否则下一次返回就漏到路由层。
- **不改 URL**：文件管理把目录同步进 URL（4.1 / 3.2.1），给浮层染色会污染深链接与刷新语义。
- **退哨兵必须让开正在进行的导航（v4.5.7 修）**：点抽屉里的导航项时「关浮层」和
  `router.push` 在同一个 tick 里发生，`history.back()` 会**打断还没落地的路由导航**
  （vue-router 的 push 是异步的，即使延后一个宏任务也来不及），表现是手机上点左侧菜单
  毫无反应、页面停在原处。两道修法：① 导航项不再自己收抽屉（只对「点的是当前页」才收），
  由 `watch(route.fullPath)` 在导航完成后收；② `disarm()` 延后一个宏任务并重新判定
  `isTrapEntry()`，历史已不在哨兵上就放弃退栈。留下的**孤儿哨兵**在下次返回落到它上面时
  再退一步吃掉（`skipOrphan`），用户按一次返回就是一次真正的后退，不出现空步。

接入点：文件管理的编辑器 / 预览 / 全部弹窗（`closeOverlayForBack`，**编辑器排在弹窗之前**——
返回键的意图是退出编辑，而 Esc 在 CodeMirror 里有补全等自身用途，不能顺手关编辑器）、
全局灯箱、相册详情与视频全屏、移动端侧边栏抽屉与账号菜单。

另外两道兜底：`onBeforeRouteLeave` 拦「有未保存修改时点侧边栏 / 面包屑离开」，
`beforeunload` 拦刷新 / 关标签页（现代浏览器只认有无未保存编辑，不展示自定义文案）。

v4.4.5 起，这层关闭确认从原生 `confirm` 换成站内三选一弹窗（取消 / 保存更改 / 放弃修改，
见 4.2）。它是浮层栈之上的一层：Esc 与系统返回都按「取消」处理，关掉弹窗后编辑器仍在，
哨兵照旧重新武装——不会出现「按返回等于连编辑器一起关掉」的意外。

## 5. 终端

### 5.1 Shell 探测

- 禁止前端传 `~`。`dirs::home_dir()` 获取主目录；前端合法挂载路径则设为 cwd。
- 优先级：`[terminal].shell` > `$SHELL` > 平台回退。Termux：`$PREFIX/bin/zsh` → `$PREFIX/bin/bash` → `/system/bin/sh`（严禁硬编码 `/bin/bash`）。Linux：`/bin/zsh` → `/bin/bash` → `/bin/sh`。macOS：`/bin/zsh` → `/bin/bash`。Windows：`pwsh.exe` → `powershell.exe` → `cmd.exe`。
- `[terminal].args` 配置则完全覆盖。未配置时强制追加交互/登录参数：Linux/macOS `-l` 或 `-i`；Windows PowerShell `-NoExit`。严禁裸 Shell 名。
- 继承 `std::env::vars()`。`CommandBuilder` 临时注入 `TERM=xterm-256color`、`COLORTERM=truecolor`。Windows 优先发送 `chcp 65001`。

### 5.2 PTY 与尺寸

- 尺寸钳制：列 `max(20, min(val, 500))`，行 `max(5, min(val, 200))`，严禁 0 或负数。
  行下限必须是 5 而不是 20：手机横屏分屏、桌面窄侧栏真的会只剩五六行，按 20 夹会把 PTY 撑到比画布还高（表现为光标跑到可视区外）。列下限 20 是 80 列宽度的四分之一，再窄 TUI 也没法用。
- 单用户并发上限默认 10（`[terminal].max_sessions`）。超限拒绝时前端提供“查看活动会话列表”和“强制关闭”入口。
  强制关闭必须联动关闭占用该会话的标签页：只清 `session_id` 是假关闭——服务端仅杀掉 shell 进程，标签的 WebSocket 仍挂在已死的 PTY 上（不产生 close 帧），用户下次敲键写入失败便退避重连、按同一 cwd 新建等价 PTY，既没释放并发名额，也和“强制结束”的语义相反。
- 断线 PTY 延迟 3 分钟销毁（`[terminal].idle_kill_seconds`）。环形缓冲 1MB，超出丢最旧。
- **写 PTY 必须离开 async 线程（v4.9.22）**：`writer.write_all` 是阻塞调用，前台进程不读 stdin
  （`sleep 600`、卡在提示符的交互程序）时写满 64KiB 主端缓冲就会一直等。以前直接在 WS 的
  `select!` 分支里写，等于钉死一个 runtime worker —— 同会话的 resize / Ping 全部排队，
  多标签同时触发就能吃掉所有 worker。现在走 `spawn_blocking`。
- **重连接入与回收互斥（v4.9.22）**：`TerminalManager::attach` 在 map 锁内完成「查会话 + 计数 +1」，
  回收侧用 `take_if_idle` 在同一把锁内复核 `clients == 0`。此前是 `get` 之后再 `fetch_add`，
  定时器恰好落在中间就把刚连上的会话收掉（重连即黑屏）。另外每次断线都会推进 `reap_epoch`，
  回收定时器排队时记住当代代数、醒来对不上就放弃 —— 否则刷新两次页面后，
  第一个定时器会在「最后一次断线」之前就把会话杀掉，所谓「保活 3 分钟」名不副实。

### 5.3 Windows ConPTY 死锁缓解（强制）

- `openpty()` 后立即向输入管道写入 `ESC[1;1R`（仅 `#[cfg(windows)]`）。
- 拆除顺序：drop writer → drain reader（500ms）→ 后台线程 drop master（`recv_timeout` 2s）。
- `openpty` 加 5 秒超时。

### 5.4 前端渲染

- xterm.js 渲染区强制深色，不跟随全局浅色主题。标准 16 色 ANSI（VS Code 暗色系），`background: '#1e1e1e'`, `red: '#cd3131'`, `green: '#0dbc79'`, `blue: '#2472c8'`, `brightGreen: '#23d18b'` 等。
- `fontFamily: '"JetBrainsMono Nerd Font", monospace'`。
- `attachCustomKeyEventHandler` 拦截 `Tab`，发送 `\t` 并 `return false`。
- `nextTick` 后 `fitAddon.fit()`；`ResizeObserver` 监听容器；移动端监听 `window.visualViewport` 的 `resize` 重新 `fit()`。
- **非活动标签绝不 `fit()`**：标签用 `v-show` 隐藏，容器是 0×0，此时 fit 会算出 2 列 1 行（后端再钳到 20×5），把这条会话的 PTY 压扁；切回来时 shell 按 20 列重画提示符，表现为「另一个终端被重置」。统一走 `refit()`：`props.active` 且容器真的有宽高才 fit，切回来时由 `active` watcher 在 rAF 里补做一次。
  同理，自动聚焦（`autoFocus`）只给活动标签——页面重进时一次挂载多个 pane，后挂载的隐藏标签会把焦点从正在看的终端抢走。
- 外壳卡片跟随全局主题，渲染区内层 `padding: 8px 12px`。禁止直接贴边铺满视口。

#### 5.4.1 移动端触屏（v4.4.3）

- **触屏滚动自己换算**：xterm 6 把滚动交给内部虚拟滚动条（`SmoothScrollableElement`），只认滚轮事件，触摸拖动没有任何路径能驱动它。画布上挂 `touchstart/touchmove/touchend`（`touchmove` 必须 `passive: false`），按 `单行像素 = .xterm-screen 高度 / rows` 把位移折成行数：
  - 普通缓冲区 → `term.scrollLines()`（公开 API，ydisp 与滚动条同步）；
  - 备用缓冲区（vim / htop）→ 合成 `WheelEvent` 丢给 `term.element`，由 xterm 自己决定发方向键还是走鼠标上报。
  - 手指离开后按最后的速度做指数衰减惯性（`FRICTION = 0.94`，每帧按实际 `dt` 折算）。
  - `touch-action: none`（仅 `pointer: coarse`）：不声明的话浏览器先自己滚一段，`touchmove` 就再也拦不住了。
- **快捷键条在文档流里**：曾是 `absolute bottom-0`，而 `section` 没有定位祖先 → 实际是相对初始包含块（视口）定位，软键盘一弹出就被压在下面。现在是 `flex` 子项（`shrink-0`，高 72 + `safe-area-inset-bottom`），终端区 `flex-1` 自动让位。
- **软键盘遮挡 = `padding-bottom`**：键盘只缩 `visualViewport`（布局视口与 `100dvh` 都不变），所以 `useKeyboardInset` 持续测「section 底边 − 可视区下沿」，把差值补成 `padding-bottom`（`>100px` 才算键盘，挡掉 Safari 地址栏收放的抖动；双指缩放直接归零）。键盘收起后归零。
- **按键不抢焦点**：触屏点 `<button>` 会把焦点从 xterm 的隐藏 textarea 抢走，输入法当场收起。快捷键条全部改成 `@pointerdown.prevent`（动作也在 pointerdown 里执行，不等 click），按键前若焦点在终端内则按完补一次 `focus({preventScroll: true})` —— `preventScroll` 是因为 textarea 被 xterm 放在 `left: -9999em`，不拦的话浏览器会为「露出焦点」把整页横向滚一下。
- **不自动聚焦**：`pointer: coarse` 下不主动 `term.focus()`。iOS 对脚本 focus 不弹键盘、Android 会弹，一进页面就顶掉半屏且行为随平台而异，统一交给用户点。

### 5.5 历史与容错

- 严禁写入系统 `AppData` 或 `~/.bash_history`。强制将 `PSReadLine` 历史路径指向 `data/terminal_history/`。前端不弹权限 Toast。
- Profile 错误原样透传，不中断环境变量注入。提供“纯净模式（NoProfile）”逃生舱：Windows `-NoProfile`，Linux `--noprofile --norc`。
- PTY 探活超时或异常退出，前端提示并提供“以纯净模式重启”。
- **子进程必须 wait 回收（v4.9.20）**：portable-pty 的 `Box<dyn Child>` Drop 不做 waitpid，
  类 Unix 上无论 `exit`、优雅关闭还是强杀都会留僵尸，守护进程长期驻留会单调积累 defunct
  项直到 spawn 失败。现在 EOF（读线程唯一的「进程已结束」信号源）与所有 kill 路径统一走
  专用 reaper 线程「短轮询 2s + 兜底阻塞 wait」；`close_graceful` 的 700ms 宽限窗口里轮询
  `try_wait`，正常退出的 shell 不再补一刀 SIGKILL。

## 6. 媒体画廊

### 6.1 缩略图

- 信号量并发上限按 CPU 数自适应（2–8），拿不到许可 1.5 秒内回占位图，不排队；同一源文件另有
  per-key 异步锁，160 / 400 两个宽度同时请求只解码一次。
- `mtime` 距今 <1 分钟且体积 ≥4MiB 时跳过缩略图。
- 优先 WebP，降级 JPEG。FFmpeg 路径 `Arc<RwLock>` 热重载与探活；未配置返回 404 占位图。
- **缓存布局（v4.4.9，FileBrowser master 的做法）**：`<cache>/<sha1(path)[..2]>/<sha1(path)>/<指纹>-<有效宽度>-<codec>`，
  指纹 = `v<版本>-<长度十六进制>-<mtime 秒十六进制>`。四条硬约束：
  - **指纹进文件名，不再有 stamp 文件**：命中与否只看文件在不在，不存在「戳写了图没写」的窗口；
  - 改图 = 指纹变 = 新文件，同目录里旧指纹的文件由 `prune_stale` 写后顺手删掉（不同步留孤儿）；
  - 缓存名**不带图片扩展名**（`v5-1b956-6ae446c8-400-jpg`）：即使缓存目录被误暴露，
    媒体扫描 / 列表也不会把它当图片再缩略图一遍；
  - 落盘走「同目录临时文件（`.tmp-*`）+ rename」原子替换，且**不在响应链路上**——
    字节已经在手上了就先回客户端，写盘交给后台线程（FileBrowser 的 `createPreview` 同思路）。
- **有效宽度入键（v4.6.3）**：文件名里的宽度是 `min(请求宽度, 源图长边)`，不是请求宽度。
  `render_thumbnail` 早已不放大，可文件名一直按请求宽度取，于是 200×150 的图在 160 / 320 / 400
  三档各存一份**字节完全相同**的副本 —— 这是「thumbnails 里一堆重复图」的主因。归一后小图只有一份，
  ETag 也按有效宽度算（同一实体不能有两个 ETag）。宽度档位同时收到两档：`160`（灯箱缩略条）/
  `400`（瓦片、灯箱打底、卡片封面、文件网格），前端统一从 `THUMB_WIDTH` 取，不许再写魔法数字。
- **命中的宽档归并 + 清理任务收尾**：`.tmp-` 残片按「10 分钟」判死（正在写的那份不能删，否则
  rename 找不到源文件）；单元目录里若存在**多组指纹**（升级换键格式、改图后没赶上 `prune_stale`），
  只保留 mtime 最新的那组。这一条是必须的：命中缓存会 touch mtime 参与 LRU，所以活跃单元的旧副本
  **永远不会**被容量淘汰，只能靠清理任务按组回收。
- **路径摘要归一**：sha1 前先 `normalize_display`，Windows 上再 `to_lowercase`（文件系统大小写不敏感，
  同一文件可能以 `C:/Photos/A.JPG` 与 `c:/photos/a.jpg` 两种形态进来），口径与 `path_guard` 一致。
- **浏览器侧**：缩略图 URL 带 `r=<渲染版本>` + `v=<源文件 mtime>`。`v` 与当前 mtime 一致时
  响应 `Cache-Control: private, max-age=31536000, immutable`（URL 变即内容变，浏览器不必回头问）；
  不一致（老链接、文件刚改）回 `private, no-cache` + `ETag`，每次校验但命中只花一次 304。
  **这条是「改了缩略图规则浏览器还抱着旧图」的唯一解**——只改服务端缓存键没用，URL 不变浏览器永远不会重新请求。
- 删除 / 改名 / 移动源文件时按路径 `purge` 整个缓存单元并删除对应 ThumbHash 行
  （FileBrowser 的 `delThumbs` 同语义），不留只能等 LRU 的孤儿。
- 淘汰单位是「一个源文件的缓存单元目录」：命中即 `set_times` 把 mtime 顶到当前时间（**真正的 LRU 续期**），
  按**闲置天数**（`thumb_cache_max_age_days`，取单元内最新 mtime）与 LRU 容量（`thumb_cache_max_size_mb`）
  整目录删除；升级时旧版扁平布局（`<hash>-320.webp` / `<sha>.th`）一次性清空。
- **失败负缓存**（v4.9.19）：同一指纹解码/截帧失败后 30 分钟内直接回占位图；
  解码设 16384 边长上限挡尺寸炸弹；一次「解码 + 编码」限时 15s，FFmpeg 探测 5s / 截帧 15s / 编码 10s。
- **外部删除的缓存立刻回收**（v4.9.18）：索引扫描本来就比对出「这个条目没了」，
  `replace_dir` / `prune` 把消失的路径带出来，`sync_index` 在数据库锁之外批量 `purge_paths`。
  读不动的目录（挂载点掉线 / 权限不足）单独记进 `unreadable`，它和整棵子树既不重写也不清除 ——
  否则网络抖一下就会把索引和缓存全当「用户删除」清掉。
- **清理与生成互斥 + 重建可取消（v4.9.20）**：三个清理入口（手动清理 / 30 分钟 janitor /
  清空缓存）全部抢 `ThumbJobSlot`，与重建/预生成互斥——清理会 `remove_dir_all` 整个
  单元目录，撞上正在 `write_atomic`/`rename` 的生成任务会把「解码成功」变成「落盘失败 +
  负缓存 30 分钟」。全量重建支持取消（`POST /api/system/thumbnails/rebuild/stop`）：
  取消标志每张之间检查一次，候选扫描每 64 个条目检查一次；状态里的 `cancel_requested`
  让前端能显示「正在停止」。台账（`preheated`）只在清理成功时清——失败时「图还在、
  台账没了」会让候选永远漏补。
- **换挂载点连派生数据一起收（v4.9.20）**：`retain_roots` 删行之前先收集旧根条目的展示
  路径（含 `media_assets` 孤儿），调用方在数据库锁之外批量回收缩略图缓存单元
  （`purge_paths`）与 ThumbHash 行——否则垃圾只是从索引挪进了缓存目录，照样计入
  `limit_bytes` 挤掉当前挂载点的活跃缓存。
- ThumbHash（20–30 字节字符串）存入 SQLite `thumb_hashes` 表，键为路径 sha1（**稳定，不随编辑次数增长**），
  列表 API 从数据库读取。
- **解码三层（v4.9.11）**：`image` crate（jpeg / png / gif / webp / bmp / tiff / ico）
  → 注册 `heifer` 的 image hook（纯 Rust HEVC，补 heic / heif / hif，零外部依赖）
  → 外部 FFmpeg（`-vf scale='min(N,iw)':-2`，解码即降采样，兜住 avif 与畸形容器）。
  顺序固定：前两层解出整幅位图并统一转 RGBA，第三层产出的直接就是目标尺寸以内。
- **缩放用 fast_image_resize（v4.9.11）**：Lanczos3 + SIMD，比 `imageops::thumbnail`
  的标量 box filter 快 3~5 倍且不糊成一片。源缓冲以 `&mut [u8]` 借给 `from_slice_u8`，
  4000×3000 的图少拷 48MB —— 一次渲染要缩两次（32px ThumbHash + 目标档），
  旧写法那两幅整图的拷贝正好落在峰值上（v4.9.12）。
- **缓存版本升到 v5（v4.9.12）**：换了缩放算法，键里的 `v` 跟着升；旧 `v4-*` 文件由清理任务收走。
- **预生成（v4.9.11 引入，v4.9.12 修键）**：候选直接从 `media_assets` 取（不再遍历文件系统），
  左连 `media_dims` 带上已知宽高，按 **`min(400, 长边)`** 入键 —— 与浏览端同一个口径，
  否则 200×150 的小图会被预生成成一份 `-400-jpg` 的副本，浏览时永远命中不到，等于白跑。
  宽高未知时现读图头（扔线程池，不阻塞 runtime）。3 路 worker、每张间让出 25ms，
  全局信号量只借三份，浏览请求仍有许可。手动全量按 `thumb_preheat_days` 取时间窗，
  索引后小批受 `thumb_preheat_per_scan` 限制，两者共用同一份进度状态与同一个停止标志。
- **预生成与全量重建互斥（v4.9.12）**：`ThumbJobSlot`（原子位 + RAII 凭证）保证两者
  **全进程一次只跑一个**。此前各自只看自己的 `is_running`，两个开关同时点下去就是两份任务
  抢同一个解码信号量：浏览请求被挤到队尾，两份任务也谁都不更快。凭证在 `Drop` 里释放，
  任务 panic 或被取消都不会把互斥位卡死。
- **生成成功不再触发全树扫描（v4.9.22）**：`get_prepared` 落盘后只 `prune_stale` 自己这一格，
  全树淘汰回到 `count_generated` 的「每 25 次一次」。此前每成功一张就 spawn 一个
  `cleanup_cache`，一次翻页 120 张 = 120 个并发全树 stat（3 万文件时是几百万次），
  把 blocking 池占满后上传、浏览、DB 查询一起停摆。
- **超时不算失败、许可不提前归还（v4.9.22）**：`spawn_blocking` 不可取消，超时只是放弃等待。
  以前超时点一到就 `drop(permit)` 并写 30 分钟负缓存——慢盘上被放弃的解码持续累积（并发闸
  形同虚设），而那张图会「恒为占位图半小时」。现在许可移进持有任务、真正结束才归还，
  超时回 503 由前端退避重试；只有渲染真的失败/panic 才进负缓存。

### 6.2 照片库

- 双视图：时间线（默认）与文件夹。
- 文件夹：卡片墙展示直接含图片的目录（含挂载根），剔除无图文件夹。数量只数第一层，点进去也只列第一层。封面取该文件夹最新图片缩略图。
- 时间线（v4.6.19 重做，对齐 Immich）：扁平化穿透所有子目录、按时间倒序，**按「天」分段**（标题 `2025年4月30日 周三`，星期走 `Intl.DateTimeFormat` 跟语言走），每段里是**等高行**——同一行每张图按自己的真实宽高比占宽，行高由「排满容器宽度」反推，横图竖图都完整、不裁成方格；末行不拉伸，保持目标行高左对齐（否则一两张图会被放成巨幅）。右边缘一条**年份刻度尺**（v4.6.21 对齐 Immich）：列的是**连续年份区间**（最早..最晚，中间没有照片的年份也占一格，只列有内容的年份会让刻度忽长忽短），滚动时跟随高亮当前年份、点击跳到该年第一天，没有内容的年份点了不跳；只有一年也显示（不再要求 >1，否则「只有一年照片」的用户右侧是空的），窄屏（<md）隐藏。年份多时压缩行距与字号（>24 年）。行宽依赖容器实测宽度，两个滚动区各挂一个 `ResizeObserver`；图片真实宽高由 `GET /api/media/browse?dims=1` 附带（后端 `image::image_dimensions` 只读文件头，按「路径 + mtime + 大小」进程内记忆，默认不返回，只有时间线这类按比例铺的视图才要）。
- **文件夹墙与分组选择（v4.6.18 收敛）**：v4.6.16 试过「平铺 / 分层」二选一，分层（面包屑 + 逐层下钻 + 当前目录自己也画成卡片）实际用起来方位感更差，已整体删除。铺法只留一种：**文件夹墙**——全库含图目录按目录路径升序铺一面墙（同父目录自然相邻，不再按「册内最新照片时间」打散，v4.6.18 用户反馈），卡片是 **Immich 式封面卡**（v4.6.23 改版）：封面铺满 4:3 圆角、ThumbHash 打底，下方两行是「名称」与「时间范围 · N 项」（如 `2020/4 – 2022/5 · 1030 项`）；不再叠文件夹图标、模糊底纹与数量角标（那是文件管理器的语言）。同名文件夹靠 `title` 悬停看完整路径。时间范围由相册内**最早/最晚**一张图的 mtime 得出（`first_modified` / `modified`，同日只写一次）。点卡片进册、Esc 退回墙。相册接口新增 `sort=path` 排序口径（游标只带路径，分页键与排序键同源）。顶栏在「按文件夹」视图里多一个**排序下拉**（按文件夹路径 / 按修改日期，v4.6.23），收藏筛选、原生播放器、重新扫描、分页进度收进右侧「更多」菜单 —— 顶栏只留每次都要用的控件。
- 可选的只剩媒体流分组：时间线「按时间 / 按文件夹」、影视「全部影片」按时间 / 按文件夹；影视顶层视图「全部影片（默认）/ 文件夹」，与照片库同构（同一套等高行 + 年份刻度）。偏好记 localStorage；v4.6.19 换过默认值，键名升到 `*.v2`，老偏好不会把人按回旧视图。
- 点击图片触发全局 `MediaLightbox`。
- **缩略图装载调度（v4.6.21）**：不再把 `<img loading="lazy">` 直接甩给浏览器。浏览器给每张图独立发请求，服务端缩略图又是按需生成，首屏几十个请求一拥而上时完成顺序基本随机——观感是「东一块西一块亮起来」，而且被限流打回的占位图是 200，`<img>` 认为已加载，那块灰就永远不走。现在的策略：`IntersectionObserver`（提前 600px）只让快到视口的格子发请求；请求进一个**按渲染顺序排序、并发 6** 的队列，前排先出图；失败按 250/800/1800ms 退避重排，用尽才落图标。服务端配合：解码队列打满 / 源文件仍在写入时回 **503 + `Retry-After`**（`ThumbOutcome::Busy`），真失败（解码不了、类型不支持）才回 200 占位图。

### 6.3 灯箱

- 渐进式加载：先展示已有缩略图占位，后台加载原图平滑替换。严禁黑屏。
  - 占位层 `object-scale-down`（**只缩不放**）：`object-contain` 会把小图放大成比原图大一圈的模糊块，
    原图淡入后撤下时露出边框；容器用 `bg-black/90 backdrop-blur-xl`（v4.4.7，Telegram 式半透明 +
    背景模糊，隐约透出下面页面），进场一次性 180ms 淡入——**不能包 `<Transition>`**：
    关闭时 items 已被清空，离场帧里 `item` 是 null，模板满屏的 `item.name` 会炸。
  - 缩略图生成的 `render_thumbnail` 也按原图长边封顶，`image.thumbnail` 不再把小图放大。
  - 原图 `@load` 后占位层 `opacity-0` 淡出（300 ms 与原图淡入同步），最终画面只剩原图本身。
  - **原图 `@load` 必须守卫 `event.target === imgEl`（v4.4.7）**：`:key` 换了元素，快速翻页时
    旧图的 load 会晚到——不守卫就把 `ready` 写成新 path，还没解码完的新原图被提前淡入，
    画面闪一帧空白。
- 静默预加载上一张/下一张：**原图和 960 打底图都要预**（v4.4.7）——打底 URL（960）与网格的
  320/480 不同源，只预原图的话翻页瞬间连打底都没就绪，整屏黑一下。图片 `z-index` 高于遮罩。
  换条目时 `zoom.reset(true)` 瞬时复位（跳过 220ms 回中动画），旧画面不趁着换图动一下。
- **媒体是主角，UI 是浮层（v4.4.6）**：交互骨架对齐 Telegram，工程细节参考 FileBrowser
  `views/files/Preview.vue`。舞台 `absolute inset-0` 铺满视口，顶栏与缩略图条 `absolute`
  浮在画面上（带渐变压暗），媒体不再被 48px 顶栏 + 76px 底条挤掉一百多像素。
  闲置 2.6 秒自动隐去，鼠标移动 / 滚轮 / 任意按键 / 触摸立刻唤回；指针停在顶栏或底条上、
  信息层或右键菜单打开时不隐（`holding`），离开时重新计时。
- **顶栏**：左 `×` → 文件名 → 计数 chip → 下载 / 新窗打开 / 分享 / 信息。触屏没有右键菜单，
  这些动作必须上工具栏；右键菜单保留（复制直链只在菜单里）。
- **图片缩放（`composables/useImageZoom.ts`）**：滚轮以光标为锚点缩放（1.12 步进，1–4 倍，
  放大后光标下那一点不动）、放大后拖动平移（按媒体布局尺寸夹取）、双击 1↔2、双指捏合；
  未放大时左右滑切图、下滑关闭（阈值 60 / 110 px，未到阈值回弹）。
  变换写成 `translate3d(x, y, 0) scale(s)`，translate 在缩放前作用，所以 x/y 是屏幕像素，
  夹取范围是 `尺寸 × (s - 1) / 2`；锚点换算用「内容坐标不变」推导，
  **不能拿 `getBoundingClientRect()` 当参照**——那个矩形本身带着位移，越缩放越偏。
- **缩放胶囊（v4.4.7）**：图片模式常驻底部居中（未放大 100% 淡显、放大后变亮），点一下复位，
  不随 chrome 隐藏。stage 内控件（左右箭头、缩放胶囊）在 `onTap` 里按
  `closest('button, a')` 豁免——它们的 `pointerup` 先于自身 `click` 冒泡到 stage，
  不豁免就会被「点黑边关闭」当场关掉灯箱，按钮永远收不到 click（v4.4.6 上下页失效的真凶）。
- **黑边点击关闭按 contain 几何判定（v4.6.16）**：原图 `<img>` 是 `size-full` 铺满舞台的，
  `object-contain` 的黑边也在元素盒子里，`target !== imgEl` 永远判不中黑边（用户实测
  「只能用左上角按钮关闭」）。改为按下时记坐标，抬起时按 `naturalWidth/Height` 与舞台尺寸
  算出实际渲染矩形，点在矩形外 = 黑边 → 关闭；信息不足（原图未解码）按「在画面内」保守处理。
- **双击与长按（v4.4.8）**：`dblclick` 同样要按 `closest('button, a')` 豁免——连点两次
  「下一张」会在按钮上凑出一次 dblclick，冒泡到 stage 就把刚翻过去的那张放大到 200%。
  键盘 auto-repeat 分两类：离散动作（Esc / 空格 / k / 0 / ±）**只认首次按下**（按住空格会在
  播放与暂停之间狂闪、按住 + 会顶到上限），翻页允许连发但节流到 ~110ms 一次（原速 30ms
  翻页时解码跟不上，观感是一串跳帧）。
- **缩略图缓存格式版本（v4.4.9，v4.6.3 升到 4）**：版本号同时进缓存文件名（`v4-…`）和前端 URL（`r=v4`）。
  v4.4.2 之前 `render_thumbnail` 会把小于请求宽度的图放大（300×200 生成成 960 宽），灯箱用
  960 缩略图打底时画面先按放大版铺开、原图一到又缩回去——就是「打开预览先大后小」。
  两条一起改才治本：服务端换名让旧图不再命中，前端换 URL 让浏览器不再拿自己的旧副本
  （响应头以前是 `max-age=86400`，URL 不变就一天不会重新请求）。视频海报用自己的版本号
  `p1`，不跟着图片升版，避免几千个视频白跑一遍 FFmpeg。v4.6.3 升版是为了让「按请求宽度命名的
  重复副本」一次性失效。
- **打底与原图共用一套布局（v4.4.9）**：两层都是 `size-full object-contain`——几何只由
  宽高比决定，缩略图和原图宽高比相同 ⇒ 渲染矩形完全重合，交叉淡入只变清晰度、不变尺寸。
  旧实现打底用 `object-scale-down`（按缩略图自身像素渲染）、原图用 `max-w/h-full + contain`
  （按可用框渲染），两套模型像素尺寸一不等就必然跳。「先大后小」是这两条原因叠加的结果。
  同时去掉实时 `backdrop-blur`：它每帧重算整个视口背后的内容，1080p 翻页明显掉帧，
  观感上就是「糊一下／闪一下」，比不糊更糟。
- **视频铺满**：`MediaPlayer` 新增 `fill`（容器不再按比例收窄，`object-contain` 吃掉黑边）与
  `showClose`（灯箱自己有工具栏，不再出现第二个 ✕）。视频不给缩略图条——Video.js 控制条就在
  视口底部，两条会叠在一起。`←/→` 在视频上做 ±5 秒快进而不是切条目
  （FileBrowser 特意做了这个放行），空格 / `k` 播放暂停。
- 信息层就地展开（尺寸 / 时长 / 体积 / 修改时间），`LightboxItem` 的 `size` / `modified` 由调用方带进来；
  图片尺寸取 `naturalWidth/Height`，视频取 `loadedmetadata`。

### 6.4 影视与音乐

- 影视库固定 16:9，无图占位。动态引入 Video.js 10。`<video>` `object-fit: contain`，监听 `loadedmetadata` 调整容器比例。关闭时 `pause(); src=''; load();`。
- **影视库与图片库同构（v4.4.8）**：此前影视库是在前端拿「已加载那几页里每个视频的 `folder`」
  现场分区，而图片库走 `/api/media/albums?kind=image`（后端统一算「直接含图片的目录」、count 只数
  第一层）——同一棵树，图片是一张卡片，视频却按完整相对路径各占一区，深目录还会把同一部剧拆成
  好几段。现在影视库同样走 `albums?kind=video` 出文件夹卡片（封面取册内最新视频首帧），点进去用
  `browse?kind=video&depth=0` 列本层影片；卡片抽成 `components/VideoCard.vue`，两层渲染共用一份模板。
- 音乐库解析音频标签（ID3v2 / FLAC / MP4 / Ogg，`lofty`）与 LRC。底部全局悬浮播放条（不播放不显示）。默认音量 35%，写 `localStorage`。
- **标签编码兜底（v4.9.21）**：国产抓轨/转换工具常把中文按 GBK 写进 ID3v2 文本帧，编码字节却填
  `0x00`（规范含义 ISO-8859-1），严格解码得到「ÁÖ¿Ï¹«Ô°」。`audio_tags` 在 `clean()` 里做一次
  有把握的回退：原串不含 CJK、字符全在单字节范围、非 ASCII 段能按 GBK 双字节成对消费，才按
  UTF-8 → GB18030 重解。`Motörhead` / `Café` 这类真·西欧文本过不了成对校验，不会被误伤。
  解码口径变了必须清一次缓存（迁移 v11）—— 缓存键是 `path+mtime+size`，文件没变就永远读不到新结果。
- **播放驱动只有一个入口（v4.6.8）**：换曲、暂停、续播全部走 `MusicBar.syncPlayback()`，且
  **换源必须等 `<audio>` 的 `src` 真的写进 DOM 之后再 `play()`**（`nextTick`）。此前「watch(playing)
  播一次 + watch(path) 播一次」两处各写一遍，path 那次打在旧音源上、被新源的 load 打断抛
  `AbortError`，而 catch 又把失败一律写成 `playing = false` —— 表现就是「一首放完就静音、界面停在
  暂停键，列表循环 / 单曲循环 / 随机全都像没生效」，只能手动点一下悬浮条才继续。现在只把
  `AbortError`（换源打断）当成「不算失败」，其余真失败（编码不支持 / 自动播放被拦）仍把状态收回
  暂停，让界面和「没有声音」保持一致。队列只有一首时 `next()` 的目标还是自己、`path` 不变，换曲
  watcher 不会触发 → 由 `onEnded` 自己 `restartTrack()`，否则单曲队列下列表循环 / 随机同样会停住。
- **列表行单击 = 播放 / 暂停（v4.6.8）**：点正在放的那一行是暂停，再点继续；点别的行才换曲。
  此前无脑调 `player.play()`（它只把 `playing` 置 true），正在放的那行点下去毫无反应，想暂停只能
  去摸底部的悬浮播放条。

  顶起，底部状态条离开窗口底边**，看起来就是「一放歌底部信息就上浮」，极简形态还多出一条
  96px 的空带。

  窗口底边；让位改由页面内部的滚动区承担（`lib/player-layout.ts` 的 `playerClearance()`）——
  终端给标签容器补 `lg:pb-[112px]`（最后一行的底边落在经典条上方约 6px），文件管理把同样的
  padding 挂在虚拟列表的滚动节点上（最后一行能滚到播放条上方）。极简形态不预留：
  64px 角标像 FAB 一样浮在右下角，只压住底栏背景的一角，不挡文字。
  普通文档页（聚合页 / 媒体库 / 设置 / 分享）仍保留 `lg:pb-[132px]`，否则滚到末尾时最后一行
  会被悬浮卡片压住。

### 6.5 索引与分页（v4.2.5）

- 媒体列表与相册清单都走**游标分页**：`limit` 默认 300、上限 1000，`cursor` 记的是上一页最后一条的
  `(mtime, 展示路径)`。与文件管理同一套 keyset 口径——排序稳定（mtime 降序 + 路径升序兜底），
  扫描期间新增/删除文件也不会让下一页重复或漏项。
- **没有扫描上限**：原来的 `SCAN_LIMIT`（媒体 4000 / 相册 20000）与 `truncated` 字段一并删除，
  多大的库都能翻到最后一条；响应里的 `total` 与 `counts`（image / video / audio）是真实总数，
  前端「已加载 N / 共 M」直接用它们，不需要等全部翻完。
- 扫描分两段：第一段只 `readdir` + 分类 + 一次 `metadata`（`RawMedia`）；第二段只对**当前页**做
  「贵」的事——音频 ID3 解析、视频外挂字幕探测、图片 ThumbHash 批量查询。原来这些对目录里每一条
  都执行，几千首歌的库首屏要开几千个文件句柄。
- **封面与歌词都有缓存（v4.9.21）**：`/api/media/cover` 以前每个请求都把整首音频打开解析 APIC，
  SMB 实测 p50 6 秒、最差 12.7 秒（一屏十几行 = 十几个并发读，把共享打满）。现在是进程内 LRU
  （键 = 展示路径 + mtime + size，预算 96 MiB / 4096 条，**负结果也缓存**），读盘前先过 4 路信号量；
  源文件一改指纹就变，不需要 TTL。歌词的存在性则在分页探测阶段和字幕**共用同一次目录 `readdir`**
  判定，结果写 `media_lyrics`（负缓存 7 天保鲜），响应里带 `has_lyrics`；前端只在为真时才请求
  —— 以前每换一首歌就是一次注定 404 的 SMB 往返（实测 0.3~3.8 秒）。
- **缓存键统一用展示路径（v4.9.21）**：`media_tags` / `media_durations` / `media_subtitles` /
  `media_lyrics` 的键必须是 `RawMedia.display`（`C:/x/y.mp3`、`//srv/share/y.mp3`），不能拿
  `entry.path`（Windows 上是 `\\?\C:\…` / `\\?\UNC\…`）。混用会造成同一首歌两行、其中一行
  永远读不到（开发机上「标签表行数 = 歌曲数 × 2」就是这个）。迁移 v12/v14/v15 清掉旧键。
- 前端触底续接：媒体库是普通滚动容器，列表末尾放一个 1px sentinel + `IntersectionObserver`
  （`rootMargin: 800px` 预取一屏），按当前视图决定续哪条流（媒体列表 / 相册卡片 / 册内图片），
  追加时按路径去重。**文件管理与搜索结果不走哨兵**：那两处是虚拟列表，哨兵在容器外永远可见，
  判定必须落在组件自己的滚动事件上（见 4.6 最后一条）。
- **目录快照缓存（v4.3.1）**：`media_snapshots` 表，一个目录一行，条目带
  `name / kind / size / mtime`（约 32 字节/条）。命中判定与搜索同一套——目录 mtime 对得上就用，
  且只收留「mtime 至少 2 秒前」的目录。命中时**零 `readdir`、零逐条 `stat`**（只剩目录自己那一次，
  用来取 stamp），翻页不再从根目录重走整棵树。
- 能缓存 `size` / `mtime` 的前提与搜索是同一个：目录内容的**名字集合**只在创建 / 删除 / 改名时变，
  这三件事都会推进父目录 mtime。
- **唯一漏网的是「原地覆盖」**：同名替换、编辑器保存这类写不改变名字集合，目录 mtime 不动，
  缓存里就还是旧的体积与时间（排序会停在老位置）。两条补充：应用自己的覆盖写
  （`/api/files/upload` 同名覆盖、`/api/files/write`）落盘后**主动 `forget` 该目录**；
  其余情况（外部程序原地改写同一文件）由前端「重新扫描」按钮带 `?refresh=1` 强制穿透 ——
  穿透之后照样写回，下一次又走缓存。用「写 .tmp 再 rename」的外部工具会推进目录 mtime，自动失效。
  这是「一次 `stat`/目录」换「零次 `stat`/条目」的必然取舍，宁可写清楚也不假装没有。
- 结果集与整树重扫**完全一致**：单测与基准都断言冷/热的 `total`、`counts`、`scanned` 三者相等；
  `scanned` 仍按「读到的目录项数」计，命中缓存时也是同一个数（快照里存的是完整条目，不是过滤后的）。
- `refresh` 是真的穿透而不是「清库」：所有目录照常重扫并写回，多页连续翻页时前缀页也会被刷新，
  不会出现「第一页新、第二页旧」。
- 查询串里的布尔值统一走 `api::boolish`（`1/0`、`true/false`、`yes/no`、`on/off` 都认）：
  `Option<bool>` 直接反序列化遇到 `?refresh=1` 会让**整条查询串**解析失败，报一个跟参数无关的 400。

### 6.6 媒体索引（v4.7.0，v4.8.0 补后台轮询，v4.8.1 补旧挂载点清理）

目录快照把「每个目录里有什么名字」缓存住了，但**每次请求仍然要把整棵树走一遍**：两万条媒体
重新构造成 `RawMedia`、全量排序，只为了给前端 120 条。网盘上真正贵的是 per-directory 的
`stat`（实测 250ms/次，64 个目录就是十几秒），所以「翻页越翻越木」在 6.5 之后依旧存在。

v4.7.0 把扫描结果落成一张**扁平的 SQLite 索引**（`core/media_index.rs`），此后：

| 请求 | 之前 | 之后（窗口内） |
|---|---|---|
| 首屏 120 条 | 走全树（22k 条目）+ 排序 + 单页重活 | 走一次全树，然后纯 SQL |
| 同页再取一次 | 再走一遍全树 | 0.6s（只查库 + 当前页重活） |
| 续页（第 2 页） | 再走一遍全树 | 纯 SQL，只多花「新一页图片读图头」 |
| 相册墙 | 再走一遍全树 + 按目录聚合 | `GROUP BY dir`，毫秒级 |
| 切分区 / 音乐库计数 | 再走一遍全树 | `GROUP BY kind`，毫秒级 |

**三张表**（迁移 v5）：

- `media_assets`：一个媒体文件一行，`path` 是展示路径（`//server/share` 锚点原样保留，前端所有
  回传都用它）、`real` 是扫描时的真实路径（算缩略图键 / `open` 用；UNC 上两者不是同一个串）、
  外加 `dir / depth / kind / ext / size / mtime`。索引里全是**绝对展示路径 + 绝对段数**，
  所以同一份索引可以服务任意子目录，不必按根重复存。
- `media_dirs`：目录行，只记「这个目录是哪一版 mtime 的扫描结果」。命中就不写库
  （连条目都不重建），失效口径与 `dir_cache` 的快照完全一致。
- `media_roots`：每个浏览根的「同步深度 + 同步时刻」，见下面的窗口期。

**新鲜度由后台轮询维护，不由请求维护（v4.8.0）**

`spawn_media_indexer` 在启动 3 秒后跑第一轮，之后每 `[media].index_scan_interval_secs`
（默认 300 秒，0 = 关闭）跑一轮；每轮对每个挂载点做
`resolve_mount_root`（canonical 口径与 `path_guard::load` 一致，否则 UNC 会写成
`\\server\share`，与前端传的 `//server/share` 永远对不上）→
`sync_index(Background)`：

- **第一轮就是预建**：挂载点一进配置就开始建索引，用户第一次点开媒体库不必等整棵树；
- 之后每轮只核目录 mtime，戳一致就整目录跳过 —— `read_dir_entries` 命中的是
  `media_snapshots` 快照，**连 readdir 都不做**，一轮只剩「每目录一次 stat」；
- 热重载新加的挂载点，下一轮自动纳入（不需要重启，也不需要用户点一次）。

`FRESH` 因此从 60 秒改成 **600 秒**（两个周期），它只决定「请求要不要自己动 IO」，
不再代表数据新鲜度：**外部新增的可见延迟 = 轮询周期**。应用自己的写操作照旧立刻作废索引
（`forget_parent_snapshot`），`?refresh=1` 照旧穿透。

**后台用独立连接**（不是 `state.media_index`）：走一棵两万条的树，NAS 上实测 187 秒，
共用那把 `Mutex` 会让期间所有浏览请求排队等锁。第二条连接靠 WAL + `busy_timeout=5000`
与前台共存 —— 实测预建期间浏览请求 232–734ms，`POST /api/auth/login` 313ms。

**写事务不含读盘（v4.8.0 修）**：`walk_into_index` 以前把 `read_dir_entries` 包在
`unchecked_transaction` 里，首次建库时写锁被持有整轮，`auth/login` 等 5.9 秒后直接报
`database is locked`。现在循环只读盘，攒够 `CHUNK`（16）个目录才开一个只做
`DELETE`+`INSERT` 的短事务，写锁时长从「一轮扫描」降到「几毫秒」。

**代价与实测**（NAS，21898 条 / 114 个目录，depth=3）：首轮预建 187 秒（一次性，
期间不阻塞浏览），之后每轮 **3.0–4.1 秒**（快照命中，无 readdir）。

**口径必须与内存扫描一致**：junk（`Thumbs.db` / `.DS_Store`）、`svg`、`SKIP_DIRS`、隐藏目录、
深度上限、`classify_name` 全部照搬（`walk_into_index` 与 `scan_raw` 是同一套判定），单测
`index_pages_the_same_tree_as_memory_scan` 直接对比两边的顺序与计数。索引打不开 / 表坏了时
`browse` 与 `albums` 回退到内存扫描，功能不降级，只是慢。

**顺带修掉两个「每页都要付」的老账**：

- **图片像素宽高进库**（`media_dims`，键 = 路径 + mtime + 大小）：时间线的等高行要真实宽高比，
  以前每页 120 张图各 `open` 一次读文件头（网盘上几百毫秒一张）。现在跨会话命中，
  只有新出现的图片才读，读完写回。
- **字幕探测会话缓存**（`SUBTITLES`）：`find_subtitle` 是每视频两次 `is_file()`，一页七个视频
  就是十几次往返。同一路径 + mtime 只探一次。

**索引是派生数据**：删掉 `media_assets` / `media_dirs` / `media_roots` 或整个库，最坏结果只是
回到「每次请求重扫」；不需要任何修复动作。

**持锁只碰数据库，网盘 IO 全在锁外（v4.9.22）**

一页 120 条的「贵字段」（ID3、图头、字幕/歌词目录枚举）在 SMB 上是几十秒的量，而
`MediaIndex` 用的是 `std::sync::Mutex` 单连接。以前 `build_items` 整段跑在 `with_conn` 里，
等于**持着索引锁做网络 IO**：期间缩略图、相册、计数、保存配置全排在同一把锁后面；
再叠加 async handler 直接同步抢锁（缩略图的宽高查询、ThumbHash 写库），几个核就被钉死，
表现是「打开一个大相册，整个站点打不开」。

现在拆成三段（`PageMeta`）：

1. `prefetch`（锁内）：批量查 `media_dims` / `media_tags` / `media_durations` /
   `media_subtitles` / `media_lyrics`，只读库；
2. `build_items`（锁外）：所有读盘与目录枚举，新结果攒进 `MetaWrites`；
3. `flush`（锁内）：五张表各一次批量写。

同一批改动里，缩略图的宽高查询与 ThumbHash 写库、播放进度与收藏的写库也都挪进
`spawn_blocking` —— 它们都要新开 SQLite 连接，`busy_timeout` 是 5 秒，不该占 runtime。

**挂载点扫描不再每请求一遍（v4.9.22）**：`roots_for` / `mount_of` / `files_mutate::mounts_of`
统一复用 `mounts_for` 的 10 秒缓存（`mounts_revision` 变即失效）。`path_guard::load` 对每个
挂载点做一次 `canonicalize` + `is_dir`，离线 SMB 上单次可达十几秒，而缩略图、raw Range、
播放进度都是每请求一次 —— 一个挂载点掉线就能让整个站点打不开。

**换挂载点后的清理（v4.8.1）**

索引行按根存放，旧根一旦从配置里消失，就再没有请求会走到它 —— 那些目录、条目、新鲜窗口
标记会永久留在库里（实测换过一次挂载点后留下 450 个目录行）。平时不碍事，但配置回落到
「挂载点全部离线 → cwd 隐式根」时，上一次挂载留下的相册会原样冒出来，这是「换了挂载点
图片库还显示旧目录」的后端那一半。

`spawn_media_indexer` 每轮开始前调 `media_index::retain_roots(conn, &keep)`：`keep` 是当前
挂载点的展示路径集合（没有显式挂载点时取 cwd）。凡是不落在任何 `keep` 下面的 `media_dirs`
整行删掉（连带 `media_assets`），`media_roots` 里对应的窗口标记也删。判定走 `under()`：
忽略大小写 + 严格段边界（`/mnt/a` 不吃 `/mnt/ab`），盘符根 `C:/` 与 UNC `//srv/share`
同一套规则。**挂载点全部离线时不清** —— 那通常只是网络还没起来，清掉等于把索引白扔。

**索引同步不再整树持锁（v4.9.20）**：`MediaIndex` 是单连接 + `std::sync::Mutex`，
旧版 `sync_index` 把「窗口判定 → 走整棵树（NAS 上秒到分钟级）→ prune + mark_synced」
全部包在 `with_conn` 里，扫描期间所有查询（浏览分页 / 相册 / 上传失效）都排在后面，
async 上下文的调用点还会卡住 runtime 线程。现在走树与构建 `Asset` 全程不碰索引连接，
每批 16 个目录只拿两次短锁（批量查戳 + 写行），末尾一个短事务收尾；两轮扫描的互斥
改由专用 `SYNC_SERIAL` 闸保证（旧版靠 DB Mutex 天然串行）。锁外失败语义与旧版一致：
任何一步打不开库就回退内存扫描。

前端那一半：相册墙 / 影视墙与时间线**并行**拉取（以前排在时间线之后，NAS 上时间线要走
两分钟树，文件夹视图就一直停在上一帧）、切视图一律静默刷新、视图快照带「挂载点集合指纹」，
对不上立刻作废。缓存只决定第一帧画什么，不能拿它当答案（见 `web/src/lib/view-cache.ts`
的三条纪律）。

## 7. 配置管理

### 7.1 TOML 编辑

- 可视化表单使用 `toml_edit` AST 仅替换目标 Value，保留注释、空行、顺序。源码模式直接写盘，仅语法校验，禁止格式化或 AST 重写。
- **段序：合并后必须重编号 `doc_position`（v4.9.13）**。段落顺序由每张表的 `doc_position`（解析时按文本顺序给的序号）稳定排序决定；补进来的新表是从「新配置序列化结果」克隆的，**带着另一套编号**，两套编号混在一个文档里就会把段落排到毫无关系的位置（`[server.proxy]` 落到 `[auth]` 后面、`[auth.proxy_trust]` 落到 `[terminal]` 后面）。渲染末尾按最终遍历顺序（原有段序 + 新表 append 在父表末尾）统一重编号，排序依据只剩「先出现的先输出」。
- **模板段序与 `Config` 字段序必须一致**（回归用例 `template_orders_sections_like_the_struct`）。模板里 `system` / `services` 曾被放在文件末尾，而结构体把它们排在 `auth` 之后 —— 于是挂载点段出现在前面、它的说明块留在末尾，隔着 `shares`/`terminal`/`media`/`log` 好几段。旧文件采用逐字匹配的方式把说明块搬回挂载点段之前（`relocate_mount_notes`），匹配不上就原样不动。
- 表数组为空时整段省略；`trusted_ips = []` 必须原样写出；纯量数组摊成单行。
- 与默认值相同的标量不写盘（如 `follow_symlinks = true`），否则每次保存都会凭空多一行；
  改成非默认值时必须落盘，两次保存结果逐字一致（幂等）。

### 7.2 热重载

- 直接用 `notify::recommended_watcher` + 手写 500ms 防抖（`recv_timeout`），不引 `notify-debouncer-full`。`Create` 与 `Modify` 视为内容变更（含 Windows `Modify(Any)`），`Metadata`/`Other` 忽略。
- **macOS 风险**：`notify-debouncer-full` 在 macOS FSEvents 下有丢弃 `Remove` 事件的已知问题。本项目从一开始就走「裸 `notify` + 手写防抖」，不依赖 debouncer，因此该风险不适用；自写防抖的窗口期仍是 500ms，重命名/原子替换会被合并成一次重载。
- 写回前比对内容，不变不写盘；必要时 `AtomicBool` 挂起监听器防死循环。相同日志 1 秒内只输出一次。

### 7.3 设置页

- 分 Tab（通用、媒体、安全、高级）。桌面端左侧竖排导航常驻、移动端横向滑动；每个分区统一「标题 + 说明」卡片规格。FFmpeg 优先级：UI > `ASMODAY_FFMPEG_PATH` > `PATH`。提供状态检测与 `libwebp` 探测。
- 恢复默认分区块重置，绝不碰 SQLite；`[[services]]` 等高级配置不被普通表单覆盖。提供清理缩略图缓存、临时文件、过期分享 tombstone 按钮。
- 危险配置自检：`trust_proxy_headers=true` 且 `trusted_ips` 空 → WARN；`proxy_trust.enabled=true` 且白名单空 → ERROR 拒绝启用；`ASMODAY_RESET_PASSWORD` 常驻但未用 `--reset-password` → WARN；`skip_2fa=true` → WARN；`0.0.0.0` 且未启用 SSL → WARN。

## 8. 服务聚合面板

- 配置驱动，外部服务默认新标签页打开，禁止 iframe。
- 直连模式打开 `target_url`。反代模式链接 `/proxy/{service_id}`，经 Rust `hyper` 代理，校验 `asmoday_session`，注入 `inject_headers`。高级选项仅：剥离路径前缀、重写内部绝对链接、忽略 SSL 证书。

## 9. 日志

- 全部后端日志、WARN、ERROR **纯英文**。用户路径/文件名原样输出。Windows 启动 `SetConsoleOutputCP(65001)`。
- 文件：`data/logs/`，单文件 10MiB × 5 备份，`errors.log` 独立档同样轮转。自研 `src/core/logging.rs`，不依赖 `tracing-appender`。
- 控制台默认 `INFO`，TTY 级别着色。文件默认 `DEBUG`，无颜色。**两条通道的时间都是服务器本地时间**（跟随操作系统时区，不是 UTC），文本行首 `[2026-10-17 09:38:58 +08:00]`——时区必须写进行首，否则时间对不上系统时无从判断是「时区没探到」还是「进程时间错了」；`format = "json"` 时 `ts` 用带偏移的 RFC 3339（`2026-10-17T09:38:58+08:00`），机器解析不丢时区。日志里不写毫秒：排障要看顺序时按行号，不靠时间戳分片。
- 时区探测分两级：先 `localtime_r` 的 `tm_gmtoff`；结果为 0 时再用 `date +%z` 复核（并再试一次清空 `TZ` 的版本）。Android / 静态 musl 没有 tzdata，`localtime_r` 会静默返回 GMT+0，日志整体偏 8 小时——这条兜底是唯一能在那种环境里对齐系统时间的路径。启动时写一行 DEBUG `log timezone: +08:00 (source: libc|date|utc|system)`，出问题直接看来源。
- API 访问日志独立 `api_level`（默认 `info`，`off` 关闭）。记录方法、路径、状态码、耗时、来源 IP。**保留非敏感查询参数（`path`、`action`、`download`），敏感参数（`password`、`token`、`share_secret`）值替换为 `[REDACTED]`**。静态资源不记；**下载页快照轮询不记**（v4.9.35）——浏览器开着 `/downloads` 时每秒 `GET /api/downloads` 拉进度（对齐 AriaNg 默认 1s 轮询），照记等于每秒一条刷屏（2026-11-06 日志审查），豁免只限这个只读快照 GET，任务动作（add / pause / remove / purge，POST/DELETE）与 `/api/downloads/engine` 照常记录；外部 aria2 客户端打的 `/jsonrpc` 不在 `/api/` 前缀下，本来就不记。
- DEBUG 才附带 `文件名:行号`；INFO 及以上不包含。`format = "text" | "json"`，默认 `text`。
- 启动 INFO：版本、PID、配置路径、数据目录、WAL/迁移状态、监听地址、前端 Git Commit / Build Timestamp、启动耗时。退出 INFO：`Received signal, shutting down gracefully...` / `Shutdown complete.`。
- 监听 `0.0.0.0` 且未启用 SSL 输出 WARN。
- **入口地址（v4.9.42 → v4.9.45）**：启动 INFO 打两行，社区同款格式（Vite / Next / Jellyfin）：
  `local:   http://localhost:4242` 与 `network: http://192.168.1.35:4242`。绑
  `0.0.0.0` / `::` 时**必须**给 network 那行——只打 localhost 的话，用户改完监听地址也
  看不出手机该填什么（2026-11-06 反馈）。network 的探测方式是「绑定 `0.0.0.0:0` 后
  UDP connect 一个 TEST-NET 地址（192.0.2.1）再读 `local_addr()`」：只做路由查找、
  不发包，也不用为 `getifaddrs` / `GetAdaptersAddresses` 写两套 unsafe；只监听回环时
  不出这行（那时报任何局域网地址都是假的）。
  URL 用 **OSC 8** 包成终端超链接（`ESC ] 8 ; ; url ST url ESC ] 8 ; ; ST`），
  Windows Terminal / iTerm2 / VS Code / GNOME 终端里 Ctrl/⌘+点击直接打开；IPv6 字面量
  加方括号，`base_url` 已是完整 URL 时原样给，裸 `0.0.0.0:4242` 既打不开也不会被识别成链接。
  **放行判据是能力而不是名单**：非 TTY（重定向/管道/CI）与拿不到 VT 处理的控制台一律
  回落纯文本，Apple Terminal 与 Unix 下的 `TERM=dumb`/空同样回落；其余 TTY 一律放行
  ——不认识 OSC 8 的终端按规范会静默吞掉序列，最差只是不可点，不会打乱屏幕。
  **文件与 JSON 通道在渲染前剥掉 CSI/OSC**：日志文件里不能出现 `\x1b]8;;`。
  启动 DEBUG 记 `console: tty=… vt=… color=… hyperlink=…`，现场判断是被主动关掉还是
  终端不支持。
- **双击 exe 也能进页面（v4.9.45 / v4.9.49）**：Windows 上双击 exe 打开的是经典 conhost，
  它**不实现 OSC 8**——序列被静默吞掉、文本点不动，任何程序都改不了这一点。出路是
  `--open`（或 `ASMODAY_OPEN=1`）：监听成功后延迟 400ms 用系统默认浏览器打开入口地址
  （避开 serve 刚起来那一瞬）；macOS `open`、Linux `xdg-open`。
  Windows 上**优先交回 shell**（`explorer.exe <url>`，失败才退 `cmd /C start`）：
  explorer 是登录用户的普通权限进程，URL 经它转手，浏览器就落在普通权限上。
  v4.9.45 曾用 `start` 直接拉，浏览器继承本进程 token——本进程一旦提权（右键「以管理员
  身份运行」、从提权终端启动），就会撞上「已有一个提权 Edge 实例」，Edge 弹
  「现有实例正在以提升的权限运行，是否用普通权限重启」（2026-11-06 实机反馈）。
- **不再有「首启自动开浏览器」（v4.9.49 撤掉 v4.9.45 的 ②）**：那条隐式行为在双击场景
  下会自己触发，用户只看到控制台莫名弹出浏览器／浏览器弹窗，代价远大于收益。现在
  **只有显式 `--open` / `ASMODAY_OPEN=1` 才会拉浏览器**。地址本来就在横幅（`Open:` /
  `LAN:`）与启动日志（`local:` / `network:`）里，用户自己点或复制即可；横幅在经典
  conhost 里补一行 `(this classic console cannot open links; copy the address above, or start with --open)`
  作兜底说明。
- **控制台不留系统本地化文本（v4.9.42）**：`io::Error` 的 Display 在 Windows 上是系统语言
  （「通常每个套接字地址(协议/网络地址/端口)只允许使用一次」），绑定失败按 `raw_os_error()`
  映射常见码（10048 / 10013 / 10049）自己写英文，`bind_hint()` 同样纯英文。
  控制台与日志宏里不允许出现汉字——中文只在 TOML 注释、代码注释与前端文案里。

## 11. 分享

- `allow_download=false` 不是 DRM。唯一目的：隐藏下载入口、防误触、限制响应头不触发批量下载。
- 图片/视频/音频/PDF：允许 `raw` 流式，强制 `Content-Disposition: inline`。前端不显示下载按钮，禁用图片右键，播放器自定义控制条隐藏原生下载。
- 文本/代码/Markdown/CSV：允许 API 返回内容渲染，隐藏下载与复制按钮。
- 不支持预览的文件：单文件分享 `allow_download=false` 创建时返回 `E_UNSUPPORTED_PREVIEW`；文件夹分享列表返回名称大小但置灰，点击提示不支持预览。
- `allow_download=false` 时任何 `raw?download=1` 返回 `E_FORBIDDEN`。后端不生成 `attachment` 分享链接。
- tombstone：启动时清理 `deleted_at` 超 30 天行；访问命中超 30 天 tombstone 当场物理删除并 404。不引入常驻定时任务。

## 12. WebDAV

- **协议由 `dav-server` 实现，本项目只做「认证 + 挂载点路由 + 安全边界」**（v4.2.0 起）。
  自研那版客户端实测加不上：`/dav`、`/dav/` 虚拟根 404，`PROPFIND` 缺
  `getetag` / `creationdate` / `supportedlock`，目录 href 没有尾斜杠——这些恰好是
  客户端判断「能不能用」的判据。协议边角（多段 Range、`If` 头、ETag 条件请求、
  `PROPPATCH` 207、autoindex、目录补斜杠重定向）全部交给社区实现。
- 方法：`OPTIONS`、`PROPFIND`、`GET`、`HEAD`、`PUT`、`DELETE`、`MKCOL`、`MOVE`、`COPY`、`LOCK`、`UNLOCK`。
- 锁是真锁：`dav-server` 的 `MemLs`（内存表 + 超时），写操作校验 `If` 头，未持锁写返回 423。
- **URL 形态**：`/dav/<mount_id>/<path>`；`/dav` 与 `/dav/` 是虚拟根，
  `PROPFIND` 列出全部挂载点（令牌限定挂载点时只列它可见的），`GET` 回可挂载目录的落地页。
  客户端只需填 `http://host:port/dav/`，不必先知道 `mount_id`。
- 路由用 `nest("/dav")` + 显式 `route("/dav/")`：axum 的 `{*rest}` 通配段匹配不到
  「空剩余路径」，`/dav/` 会直接落进静态回落——这正是「客户端里加不上」的直接原因。
- Basic Auth：优先「用户名 = `token_name`（`UNIQUE`），密码 = `asm_` Token 明文，校验哈希与过期」；
  失败后回退管理员账号 + 登录密码（全量权限，待改密 / 开 2FA 的账号拒绝，见 3.4）。
  只读令牌与只读挂载点：写方法在入口直接 403，且 `OPTIONS` 的 `Allow` 只列读方法
  （`DavMethodSet::WEBDAV_RO`），客户端据此判定「只读共享」。
- 安全边界（`api/webdav.rs` 的 `guard_path` / `guard_destination`）：
  - 逐段拒绝 `.` / `..`；已存在路径 canonicalize 后必须在挂载点内；
    软链接逃逸按 `[system].follow_symlinks` 处理（=false 时 403，=true 时与文件管理口径一致地放行）；
  - `MOVE`/`COPY` 的 `Destination` 头过同一道闸（否则可以用指向挂载点外的软链接写文件）；
  - `.asmoday-part.*` 与系统垃圾（`.DS_Store` / `._*` / `Thumbs.db` 等）：读侧 404、写侧 403，
    由 `CleanFs`（`api/dav_fs.rs`）在 `LocalFs` 外面统一拦——只过滤读不拦写，
    客户端照样能创建垃圾并触发 macOS/Windows 双端同步死循环；
  - 挂载点根不可 DELETE/MOVE。
- Windows 适配（实测踩过）：`MKCOL` 带尾斜杠 dav-server 会 400，转交前去掉；
  重复 `MKCOL` 的 `ERROR_ALREADY_EXISTS`（Win32 183）不在 dav-server 的 unix errno
  映射表里会变 500，`CleanFs` 先探存在性统一回 405。
- Basic Auth 失败计入独立防爆破池（`token_name + IP`），与登录 / 分享互相隔离。
- 子路径部署：`strip_prefix` 与请求 URI 都带 `[server.proxy].base_url` 前缀，
  href 与 `Destination` 才能对上；**不能用 `OriginalUri`**——它由最外层 Router 插入，
  带 `/asmoday`，会令所有请求被误判为虚拟根。

## 17. 部署与编译

- Release profile：`opt-level = "z"`、`lto = true`、`codegen-units = 1`、`panic = "abort"`、`strip = true`。
- 本地 Windows 开发，交叉编译 Linux 使用自编 zigcc shim（改写 `--target`、链接阶段过滤 musl CRT 与 `-lc`、`ZIGCC_TARGET` 切换）。`renameat2` 必须走 `syscall(2)`（x86_64=316 / aarch64=276）。
- GitHub Actions 矩阵（v4.6.2 起）：`windows-latest` + `ubuntu-latest`，产物三件——`asmoday-x86_64-pc-windows-msvc.zip`、`asmoday-x86_64-unknown-linux-musl.tar.gz`、`asmoday-aarch64-unknown-linux-musl.tar.gz`。
  - **不再构建 macOS**：`macos-13` 的 aarch64 与 x86_64 队列常年缺货，两个 job 一卡住整条矩阵就永远 `in_progress`，`needs: build` 的 `release` 永远等不到 —— 表现为「tag 打了、Actions 绿着，Releases 里啥也没有」。去掉 mac 两个目标和 `lipo` 合并的 `macos_universal` job 后，矩阵只剩三个目标，`release` 直接依赖 `build`。macOS 用户源码编译（`cargo build --release`）仍然可用。
  - **并发闸门**：`concurrency: release-${{ github.ref }}` + `cancel-in-progress: true`。同一 tag 改指向后重推时，旧 run 必须让位，否则两个 run 并发写同一份 release，后到的产物覆盖先到的。
  - 其余加固：`--locked` 编译（发版当天不被上游悄悄升版本）、`Swatinem/rust-cache` 按 target 分键、`if-no-files-found: error`（产物或前端 dist 为空直接失败，不发白屏包）、各 job `timeout-minutes`、`overwrite_files: true`（重打同 tag 覆盖同名 release 产物）、`prerelease` 按 tag 是否带 `-` 自动判定。
- **CI 缓存**：为 `rusqlite bundled` 的 ARM64 musl 编译添加 `actions/cache` 缓存 `target/`，否则可能超时。

## 18. UI/UX 关键规范

- 阅读型页面 `max-w-5xl` 居中；工作台型页面 `w-full` 铺满，禁止限制最大宽度。设置页源码模式同一帧移除居中限制，父容器 `h-full flex flex-col`。
- 设置页主内容区 `max-w-5xl`；表单多列 Grid，`md` 断点单列；卡片 `p-6`，间距 `gap-6`；输入/主按钮 `h-10`；只读长文本浅色只读框 + 复制按钮。
- 主题三态 `light/dark/system`，默认 `system`。`<head>` 原生 JS 读 `localStorage` 并设 `data-theme`，监听系统变化。切换入口在右上角用户菜单，设置页通用 Tab 同步。代码编辑器与终端内禁止 transition。
- **骨架屏不是装饰，是版面的占位（v4.6.1）**：
  - **形状必须跟真实内容一致**：相册卡片 = 4:3 封面 + 标题行 + 副标题行；时间线 = 方格；
    影视 = 16:9 + 标题行；音乐 = 40px 封面 + 两行字；影视库还要给页面标题占位。
    形状不对的骨架会在内容到达时「跳一下版」，比没有骨架更难受。
  - **延后 180ms 才出现**（`composables/useDeferredLoading.ts`）：接口快于这个窗口就完全不显示，
    避免闪一下白块。
  - **只做首次加载的占位**：已有数据时的刷新保持旧内容（`albums.length === 0 && skeleton`），
    期间不闪骨架、不闪空态。
  - **重新进入页面不重放首次加载（v4.6.8）**：文件管理、图片库、影视库把最近一次成功的列表记在
    会话内存里（`web/src/lib/view-cache.ts`，键含挂载点 / 路径 / 排序 / 隐藏文件开关），进页面先把
    上一帧贴出来、同时照旧全量重新拉取覆盖；单挂载点的 `/files → /files/:id` 跳转也因此不再盖
    跳转遮罩。**缓存只决定第一帧画什么**，任何判断都用后端返回的数据（设计文档 3.2.1 不放宽）；
    有内容时的刷新走静默模式，失败只轻提示、不清空已显示的内容，进度反馈交给工具栏刷新键的转动
    （`refreshing`），不再拿骨架屏当进度条。文件页骨架同样延后 180ms 才出现。
  - 微光用「文字色 7% 混进底块」，禁止拿 `--border-color` 当高光（深色主题下那是一条更暗的带子）；
    `prefers-reduced-motion` 下关掉动画。
  - 内容接替骨架时套 `.fade-in`（0.22s 上浮淡入）。
- **三分区（图片库 / 影视库 / 音乐库）共用同一个 GalleryView 实例**：`onMounted` 只跑一次，
  所以 `route.meta.mediaTab` 变化时**每个分区都要按需补拉自己的副列表**（相册清单 / 文件夹卡片）。
  漏掉一个的后果是「从影视库切回图片库，相册永远空白」——能否复现只取决于用户先进哪个分区，
  表现为「偶尔」。
- 列表加载失败一律给「重试 / 重新扫描」按钮，不展示误导性的空态；接口报错时不得把已有数据清空
  （`albumsError` 只在没有数据时接管整个区域）。
- 遮罩层打开锁定 `body` 滚动。底部悬浮条 `env(safe-area-inset-bottom)`。移动端软键盘监听 `visualViewport.resize` 重新 `fit()`。
- 文件列表用 `grid`，图标/缩略图 `w-16 h-16` 或 `aspect-square`。排序菜单当前项打勾并显示在工具栏。滚动到底自动加载下一页；切换排序清空列表重新拉取。
- 批量操作结果统一弹窗。失败项优先展示 `error_code` 翻译；`E_BUSY` / `E_CONFLICT` 禁止简单“重试”，提供“忽略并继续”或外部动作指引。前端并发上传池默认 3。
- 移动端长按阈值 500ms，滑动超 10px 取消；触发后忽略 `click`；多选时容器底部加 padding。
- **移动端不是缩小版桌面（v4.6.0）**：窄屏按操作逻辑重排，而不是把桌面布局等比压小。
  - **文件页工具栏拆成两个互不重叠的区（v4.6.5）**：左「导航」（返回上级 + 路径），右「动作」
    （新建 / 上传 + 刷新 / 搜索 / 排序 / 隐藏 / 视图）。导航与动作之间有竖分隔线与 12px 留白，
    动作组之间 16px、主操作按钮之间 8px —— 以前全部挤在一行且路径紧贴上传按钮，用户点路径
    回退时手一滑就点到上传。
  - **窄屏两行**：导航在上、动作在下（动作行内主操作靠左、视图控制靠右）；桌面单行，路径占
    中间弹性宽度。1024–1279 这一档把搜索框收到 160px、排序只留图标（`xl` 起才显示文字），
    否则路径只剩 166px，`storage / pictures` 会被截断。
  - **路径用 `/` 分隔而不是 chevron**：顶栏是「Home > 页面名」的层级，文件页是文件路径，两种
    `>` 叠在一起用户分不清点哪个；**当前目录不可点**（以前点它等于原地刷新一次，是最常见的误触）。
    自带路径条的页面在路由 meta 上标 `hideCrumb`，顶栏只留页面名，不再渲染 `Home >`。
  - 工具栏放不下搜索框 → 换成放大镜开关，展开**独立搜索行**（含「包含子目录」与取消）。
  - 条目右上角常驻「⋯」，唤起 4.4 的底部动作面板；没有它，重命名/分享/属性在手机上无法抵达。
  - 相册 / 音乐列表没有右键可用 → 500ms 长按唤起同一个面板（`composables/useLongPress.ts`，
    位移 >10px 判滚动；长按后补发的那次 click 在捕获阶段被吃掉，否则会点在遮罩上把面板
    刚弹出来就关掉）。
  - 所有弹窗在窄屏贴底（`modal-overlay` + `modal-card`：全宽、顶部圆角 20px、`88dvh` 内可滚、
    底部叠加安全区）；桌面仍是居中卡片。
  - 多选操作栏拆两行：上行「已选 N 项 + 取消」，下行等宽「图标+文字」四个动作（图标单独出现
    时分不清下载和移动）。
  - 触屏可点区不小于 36–40px（`touch-target` / `touch-chip`）；顶栏让出 `safe-area-inset-top`。
- 禁止原生弹窗。冲突、删除确认用封装 Modal。
- 终端外壳跟随主题，渲染区深色，内层 `padding: 8px 12px`，禁止直接贴边铺满视口。
- 源码编辑器 100% 撑满 Flex 容器，外层 `overflow: hidden`，滚动条仅编辑器内部产生。切换可视化/源码 `nextTick` 后通知 CodeMirror 重算尺寸。工具栏吸附顶部，默认开启水平滚动。
