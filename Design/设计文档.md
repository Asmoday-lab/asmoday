# Asmoday (空间执政) 产品与系统设计白皮书

**版本**：v2.9.0（终极全量版：包含跨平台垃圾过滤、EOL保留、终端容错、ThumbHash防爆与全部防坑契约）  
**定位**：专为低功耗 64 位设备（ARM64 / x86_64）设计的、单二进制的个人媒体与设备控制中枢。

---

## 1. 项目概述与核心边界

### 1.1 背景与痛点

传统的自托管（NAS / 软路由 / 开发板）通常采用 `FileBrowser + ttyd + Nginx 反代 + 聚合页` 的拼装架构，导致以下问题：

1. **维护割裂**：新增服务需同步修改 Nginx 配置、聚合页 HTML，操作繁琐。
2. **体验断层**：文件管理与终端相互独立，无法实现“在指定目录一键打开终端”。
3. **安全隐患**：公网暴露风险高，各服务缺乏统一鉴权。
4. **资源浪费**：多进程并行，占用不必要的内存与 CPU。
5. **数据风险**：不同组件对冲突、软链接、路径穿越的处理不一致，容易出现静默覆盖或越权读取。

### 1.2 产品定位

**Asmoday** 是一个前后端分离开发、单体二进制发布的极简控制中枢。它只负责核心的文件、媒体与终端展示，拒绝任何重型功能。为了保证极致的编译与运行效率，**全面放弃 32 位架构（如 ARMv7），只专注于现代 64 位平台（ARM64, x86_64）**。

**当前设计假设（待最终确认）**：v2 默认按“单管理员”模型设计。`users` 表在 v2 中只允许单行记录，初始化后不提供用户管理入口。所有登录用户即管理员，终端为系统级权限。若未来扩展为多用户，必须重新设计挂载点 ACL、终端归属与分享归属，不在 v2 范围内。

### 1.3 核心克制原则与红线

1. **绝不内置多媒体转码**：拒绝在服务端运行 FFmpeg 进行视频转码，仅依赖浏览器客户端播放能力。
2. **绝不内置刮削与 AI**：不联网抓取影视海报，不提取内封字幕，不搞任何语义/人脸识别。
3. **绝不自研同步与 App**：不自建同步协议，强制引导用户使用 WebDAV 或第三方同步工具（如 Syncthing）。
4. **绝不依赖外部 CDN**：前端所有静态资源（包括各种代码高亮语言包、终端库）全量打包进二进制，**拒绝任何形式的公网 CDN 外链**，确保在内网断网环境下的绝对可用性和毫秒级加载速度。
5. **绝不留下免密后门**：严禁在配置文件提供“关闭认证”的开关。忘记密码必须通过 CLI 命令行或物理删除数据重置，确保系统在任何配置文件泄露的情况下都不会直接裸奔。
6. **绝不接管重型任务**：不内置 BT 下载器、不内置在线办公套件，通过“生态推荐页”引导用户搭配外部工具。
7. **绝不接管重型文件操作**：不内置异步任务队列，不支持超大目录/文件的跨挂载点搬运。单次 **copy / move / delete** 操作，文件数 > 100 **或** 总字节 > 2GB，**任一超限即拒绝**，提示“请在终端使用 `cp` / `mv` 完成”。上限统计必须在操作开始前完成，遍历中一旦超限立即中止。`rename / mkdir / touch / stat / hash` 为元数据或只读操作，不受此限。单个文件跨挂载点移动 > 2GB 同样拒绝。
8. **绝不提供回收站**：v2 删除一律物理硬删，代码库不得出现回收站字段、接口、UI。`shares` 的 410 tombstone 仅服务于分享链接，不是文件回收站，不得被复用或扩展为文件软删除。Syncthing 式系统 Trash 集成列入“非目标”，v3 独立设计。
9. **绝不做目录合并式覆盖**：目录冲突时 `on_conflict=overwrite` 直接拒绝（`E_DIR_CONFLICT`），只接受 `rename / skip`。严禁合并目录内容，严禁递归删除目标目录来“覆盖”。
10. **拒绝内置 ACME 证书申请**：严禁在内部实现 Let's Encrypt 自动证书申请。违背单二进制极简原则，且在内网穿透场景下易失败。证书由用户在配置中手动指定，或强制推荐使用 Caddy/Nginx 反代。

### 1.4 AI 防幻觉与版本铁律（最高优先级）

1. **严禁擅自降级依赖**：遇到 API 报错，**绝对不允许**将库降级到旧版本（如把 Video.js 10 降级到 v8）。必须查阅最新版官方文档重构代码。
2. **严禁使用过时的废弃 API**：必须严格遵循新版库的架构（如 Axum 0.7+ 的 `axum::serve`，CodeMirror 6 的模块化 API，Video.js 10 的 Web Components）。
3. **严禁前端硬编码文本**：所有的界面文本、按钮、提示语，**必须**通过 `vue-i18n` 的 `$t('key')` 方式渲染。绝对禁止在 `.vue` 文件或 `.ts` 文件中直接写死中文字符串。
4. **严禁用“先检查再操作”代替原子落盘**：文件写入、重命名、移动的防覆盖必须依赖平台原子 no-replace 操作，不得写成 `exists()` 后再 `rename()`。
5. **严禁对不存在的完整路径直接 `canonicalize`**：目标路径不存在时会 ENOENT。必须 `canonicalize` 父目录并校验父目录归属，再校验文件名。
6. **严禁在列表循环中生成隐藏的 `<video>` 或 `<audio>` DOM**：全局媒体组件必须单实例。
7. **严禁把 ThumbHash 保存为碎文件**：ThumbHash 只有 20-30 字节，作为独立文件落盘会导致 Inode 耗尽。必须存入数据库或作为 API 的 JSON 字段返回。
8. **严禁覆盖用户的 EOL（换行符）**：编辑文本保存时，必须保留原文件是 `LF` 还是 `CRLF`。严禁强制转换为 `\n` 或 `\r\n`。

## 2. 技术架构与选型

### 2.1 总体架构

* **后端**：Rust 语言，基于 `axum` (0.7+) 异步 Web 框架。通过 `rust-embed` 将前端产物打包入单文件。
* **前端**：Vue 3 + Vite + TailwindCSS (v4)。
* **跨平台**：通过 Rust 交叉编译，产出主流 64 位系统（Windows x64、macOS ARM64/x64、Linux x86_64/ARM64）独立的单二进制文件。

### 2.2 核心依赖库与规范

* **Web 框架**：`axum` (0.7+)。**严禁**使用旧版 `axum::Server`，必须用 `axum::serve`。
* **PTY 终端**：`portable-pty`（跨平台拉起真实伪终端）。
* **系统目录获取**：`dirs`（用于跨平台获取主目录 `~`）。
* **数据库**：`rusqlite`（自带 `bundled` 特性，免系统依赖），**系统启动时必须开启 WAL 模式**（执行 `PRAGMA journal_mode=WAL;`）。
* **配置解析**：`toml` 库（替代 YAML，提供强类型与显式语法）。保存时必须基于 TOML AST 做局部合并，禁止全量重写。
* **文件监听**：`notify`（配置热重载）。
* **日志轮转**：`tracing-appender`。
* **网络代理**：`hyper` / `reqwest`（用于内部网关透传）。
* **前端终端**：`xterm.js` + `xterm-addon-fit`。
* **前端编辑器**：`CodeMirror 6`。**严禁**使用 v5 的 `fromTextArea` 或全局 `CodeMirror` 对象，必须按需引入 `@codemirror/state`, `@codemirror/view` 及具体语言包。
* **前端播放器**：`Video.js 10`。**严禁**使用 v8 的 `videojs()` 函数 API，必须使用基于 Web Components 的 `@videojs/html` 自定义元素（如 `<video-player>`）。
* **前端多语言**：`vue-i18n` (v9+)。用于全局文本管理。
* **前端 Markdown**：`marked` + `DOMPurify`，按需动态导入。
* **前端 CSV**：轻量解析器，按需动态导入，强制截断。
* **CSS 框架**：`TailwindCSS v4`。通过 Vite 插件配置，废弃 `tailwind.config.js`，统一在 CSS 中使用 `@import "tailwindcss"`。

### 2.3 前端资源加载与防白屏策略

* **Vite 代码分割 (Code Splitting)**：前端在引入 `CodeMirror` 语言包、`Video.js`、`xterm.js`、`marked`（Markdown 解析）等重型组件时，全面使用 ES Module 的 `import()` 动态导入语法。
* **无感内嵌**：Vite 打包出的所有 chunk 文件，均被 `rust-embed` 吸入二进制文件中。坚决不向用户提供“自定义 CDN 源”选项。
* **静态资源缓存 (Cache-Control)**：
  * 带 Hash 的静态文件（如 `main.a1b2.js`、`index-xxx.css`）设置长达一年的强缓存。
  * **`index.html` 必须设置 `Cache-Control: no-cache`**，防止前端更新后用户浏览器加载旧代码导致白屏。
* **主题防白屏**：由原生 JS 在 `<head>` 中直接读 `localStorage` 并修改 `<html>` 的 `data-theme` 属性，早于 Vue 挂载执行。

### 2.4 SPA 单页应用路由 Fallback 规范

* **强制规则**：所有 `/api/*` 与 `/dav/*` 路由之外的无匹配请求，如果后端找不到对应的静态资源文件，**且**请求满足以下任一条件时才 Fallback 返回内嵌的 `index.html`：
  * 请求路径无文件扩展名；
  * 请求头 `Accept` 包含 `text/html`。
* **例外一**：`/api/*` 与 `/dav/*` 的路由在找不到资源或报错时返回标准的 JSON 或 WebDAV XML 错误，不得 Fallback。
* **例外二**：带文件扩展名的静态资源请求（如 `/assets/main.abc.js`、`/favicon.ico`）若找不到，**直接返回 404**，绝不 Fallback 为 HTML，避免浏览器报 MIME 错误难以排查。
* **`base_url` 子路径**：所有 Fallback 与静态资源匹配均需先剥离 `base_url` 前缀；Vite `base` 配置必须与之一致。

## 3. 详细功能模块设计与工程细节

### 3.1 身份认证、安全与初始化 (Auth & Security)

#### 3.1.1 初次运行初始化策略与监听安全

* **默认路径（交互式向导）**：首次通过浏览器访问时，强制进入极简初始化页面，引导用户自行设置管理员账号与高强度密码。初始化完成前，除初始化接口外所有 API 返回 503。
* **自动化路径（日志一次性密码）**：在纯 CLI 或容器化脚本部署时（使用 `--init` 参数启动），程序自动生成高强度的随机密码并打印至控制台日志中。用户首次登录后强制要求修改密码。
* **`users` 表约束**：v2 只允许单行记录，初始化后禁止新增用户。若检测到多行记录，启动时记 ERROR 并只使用 id 最小的记录，不自动删除。
* **未初始化严防死守（公网暴露防护）**：无论监听地址是 `0.0.0.0` 还是 `127.0.0.1`，在首次初始化完成之前，除初始化接口外，**所有对外 API 与 WebDAV 接口必须返回 `503 Service Unavailable`**，严防未鉴权状态下被局域网蠕虫或扫描器直接接管。

#### 3.1.2 密码遗忘与重置机制（防后门设计）

* **严禁**在配置文件（`config.toml`）中提供“无密码/关闭认证”的静态开关。
* 重置密码必须通过系统级操作证明权限：
  * CLI `--reset-password`：交互式输入新密码。
  * 环境变量 `ASMODAY_RESET_PASSWORD`：**仅在使用 `--reset-password` 启动时生效一次**。生效后写入数据库标记 `password_reset_pending=false`，同一变量再次出现时拒绝生效并记 WARN。日志只打印“已重置”，不打印密码。文档要求用户重置后立即删除该变量。
* 重置成功后，所有现有会话立即失效（会话表或签名密钥轮换）。
* **2FA 忘记的兜底**：CLI `--reset-2fa` 清除 `totp_secret` 并关闭 2FA，要求同时输入当前密码或走 `--reset-password` 流程，防止可用性死锁。

#### 3.1.3 会话管理

* 登录后下发 `HttpOnly` Cookie，属性：
  * `SameSite=Lax`；
  * `Secure` 仅在请求经 HTTPS（或 `X-Forwarded-Proto=https` 且源 IP 命中 `trusted_ips`）时设置；
  * `Path` 必须与 `base_url` 一致，`base_url` 为空时用 `/`。
* 会话过期：默认 7 天，滑动续期（每次请求刷新过期时间，但不超过绝对上限 30 天）。
* 密码修改、2FA 开关、`--reset-password` 后，所有旧会话立即失效。
* 登出接口清除 Cookie 并作废服务端会话。
* 全站 API 与 WebSocket 必须经 Auth 中间件拦截。
* **CSRF 防护**：Cookie 认证下的所有写操作（POST/PUT/DELETE/PATCH）必须校验 `Origin` 或 `Referer` 与请求 Host 一致；`SameSite=Lax` 作为第二道防线。`base_url` 子路径部署时，Origin 校验必须剥离前缀后比较。

#### 3.1.4 双重认证 (2FA)

* 可选开启 TOTP。开启时生成 10 个一次性恢复码，仅存哈希，展示一次。
* 关闭 2FA 需输入当前密码 + 有效 TOTP 或恢复码。
* 登录时 TOTP 错误计入防爆破计数器。

#### 3.1.5 防爆破机制与频控隔离

* 基于内存的 IP 计数器，连续 5 次密码错误封禁该 IP 15 分钟。
* **IP 来源判定**：仅当请求源 IP 命中 `server.proxy.trusted_ips` 时才采信 `X-Forwarded-For` / `X-Real-IP`；否则使用 socket 地址。
* **独立频控池（极重要）**：主登录、分享页密码尝试、WebDAV Basic Auth 验证，必须使用**互相隔离**的防爆破池。严禁共享计数器，防止攻击者利用分享链接或 WebDAV 爆破来封禁管理员 IP。
* 计数维度：IP + 用户名组合计数，同时维护纯 IP 计数防止用户名枚举。TOTP 错误计入同一主登录池计数器。
* 白名单 IP 不计数。重启后计数器丢失，可接受。防爆破缓存必须后台定时 GC，防止内存无限泄漏。

#### 3.1.6 访问令牌体系（API / WebDAV）

* 严禁使用主密码挂载 WebDAV 或调用 API。支持生成带前缀（如 `asm_`）的 Token，可设置“有效时间”与“只读/读写”权限，数据库仅存哈希值。
* Token 创建时明文只展示一次；列表只展示前缀与后 4 位；支持吊销。
* Token 可用于：图床直链、分享直链、API 调用、**WebDAV 挂载**。

#### 3.1.7 反向代理兼容性

* 支持信任 `X-Forwarded-For` / `X-Real-IP`（结合 `trusted_ips` 白名单），确保获取真实 IP。
* 支持 `X-Forwarded-Proto` 和 `X-Forwarded-Host`，确保生成的动态 URL 协议正确。
* 支持 `X-Forwarded-Prefix` 与 `base_url` 子路径部署，前端 Router、后端路由、Cookie Path、WebSocket URL、静态资源 URL、分享链接、重定向 `Location` 必须全部自动处理路径前缀。
* 未命中 `trusted_ips` 的请求，所有 `X-Forwarded-*` 头一律忽略。

#### 3.1.8 双向 SSO 架构

* **“座上宾”模式（被外部接入）**：信任反向代理传递的 Header（如 `X-Forwarded-User`），通过白名单限制来源，实现外部 IdP 免密跳转。
  * **强制约束**：`proxy_trust.enabled=true` 时，**仅当请求源 IP 命中 `proxy_trust.trusted_ips` 才采信 Header**；白名单为空则拒绝启用并在启动日志报 ERROR。
  * Header 用户不存在时**拒绝登录**，不自动建号。
  * 是否跳过 2FA：默认**仍要求 2FA**；若配置 `skip_2fa=true`，启动日志必须打 WARN。
* **“大内总管”模式（代理外部服务）**：反代时支持 `Header 注入`；或通过 `Cookie 作用域重写`，隔离多服务 Session。

#### 3.1.9 安全纵深与 XSS 防范

* 前端绝不使用 `v-html` 渲染不可信内容；Markdown 渲染必须经 `DOMPurify`。
* 后端保存文件名时，严格过滤危险字符，并强制执行**路径穿越校验**。
* 图床/分享直链必须校验 Token 有效性。
* **默认安全响应头**：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Permissions-Policy` 收紧、HTTPS 下 `Strict-Transport-Security`。CSP 必须兼容 Markdown 渲染与 PDF iframe，至少禁止 `unsafe-eval`，`frame-ancestors` 按需配置。

### 3.2 文件管理 (Files - 极简无树设计)

#### 3.2.1 视图布局、工具栏与文件过滤

* **彻底放弃传统的左侧常驻目录树**，最大化释放横向空间。
* **多平台系统垃圾文件强制过滤规则（后端硬编码，无条件生效）**：
  * **最高优先级**：无论前端是否传了 `show_hidden=true`，后端在读取目录（`GET /api/files/list`）、媒体库扫描、以及 WebDAV `PROPFIND` 时，都必须直接忽略并过滤掉以下垃圾文件。
  * **强制过滤矩阵（绝不返回给前端）**：
    1.  **精确匹配**：`desktop.ini`, `Thumbs.db`, `ehthumbs.db`, `.DS_Store`, `lost+found`。
    2.  **前缀匹配**：以 `~$` 开头（Office 临时文件）、以 `._` 开头（macOS AppleDouble 元数据文件）。
    3.  **系统目录（精确匹配）**：`.Trashes`, `.Spotlight-V100`, `.fseventsd`, `$RECYCLE.BIN`, `System Volume Information`。
  * **普通隐藏文件**：除了上述黑名单外，其他以 `.` 开头的普通文件（如 `.env`, `.git`），受前端 `show_hidden` 开关控制。
* **挂载点动态判断（核心路由逻辑）**：
  * 每次访问 `/files` 路由时，前端必须拉取 `GET /api/files/mounts` 获取最新列表（禁止本地缓存）。
  * **零挂载点**：展示全局空状态页，引导用户去配置。
  * **单挂载点（且在线）**：使用 `router.replace` 直接重定向到 `/files/:mountId/`，跳过卡片页，直达根目录。必须使用 `replace` 防止用户点返回时陷入死循环。
  * **单挂载点（且离线）**：不跳转，停留在 `/files` 展示离线提示卡片。
  * **多挂载点**：展示卡片平铺列表。
* **主视图（强制仅限两种）**：
  * 严禁提供“大/中/小图标”、“平铺”、“内容”等多余视图。Web 端仅提供“网格视图（Grid）”与“列表视图（List）”。
  * **网格视图**：自适应列数（CSS Grid），图片/视频展示缩略图，其他展示大图标，下方跟单行截断的文件名。必须有内边距（如 `p-3`），悬停时浮现“更多”按钮。
  * **列表视图**：必须包含表头（名称、大小、修改时间）。名称列占据主要空间，大小与时间列固定宽度（如 `w-24`, `w-40`）且右对齐。
* **辅助面板**：
  * **右侧属性面板**：点击单个文件时滑出，展示图标/预览、完整名称、路径、大小、修改时间、MIME 类型等。绝对不显示服务器敏感路径（如 `C:\Users\xxx`），只显示相对路径或挂载点名称。
* **顶部工具栏强制元素**（从左到右）：刷新、新建文件夹/文件、上传、搜索框、排序菜单、视图切换按钮组。
* **偏好持久化**：用户切换视图和排序方式后，必须写入 `localStorage`，刷新页面后保持。
* **面包屑导航（Breadcrumb）语义**：
  * **多挂载点模式**：`[🏠 挂载点列表] / [挂载点名称] / 目录A / 目录B`。点击前两级均可回到 `/files` 卡片页。
  * **单挂载点模式**：`[🏠 挂载点名称] / 目录A / 目录B`。点击第一级回到该挂载点的根目录。

#### 3.2.2 文件预览矩阵与复用机制

* **严禁重复造轮子**：文件管理中的双击预览行为，**严禁**单独手写 `<img>` 或 `<video>` 弹窗。必须调用全局的 `MediaLightbox` 组件与全局媒体播放状态（Pinia）。
* **传参规范**：双击图片时，前端应收集当前目录下的所有同类型图片，构成一个数组，调用 `MediaLightbox.open(images, currentIndex)`，从而在文件管理中也能享受相册级别的“左右切换”体验。
* **纯文本/代码 (txt, js, rs, py, toml 等)**：双击无缝切换为 `CodeMirror 6` 编辑器。
* **Markdown (.md)**：双击默认进入**渲染预览模式**（按需 `import()` 引入 `marked` + `DOMPurify` 防 XSS）。顶部提供“切换源码”按钮进入编辑器。
* **音视频 (mp4, mp3 等)**：拉起全局媒体播放器组件。浏览器不支持解码的格式必须捕获 `error` 事件并提示下载。
* **PDF 文档**：直接使用浏览器原生 `<iframe src="raw_url">` 渲染，零体积开销。移动端 Safari 若无法内嵌，降级为“在新标签页打开”。
* **表格数据 (.csv)**：按需引入极轻量解析器，渲染为只读表格。**强制限制：文件大小超 5MB 或行数超 1000 行时，截断展示并提示下载**。
* **重型文档 (Office docx/xlsx/pptx, CAD, 压缩包等)**：**坚决不引入任何本地解析库**。弹窗提示“为保证系统轻量，暂不支持在线预览该格式，请下载后查看。”，直接触发下载。

#### 3.2.2.1 文本编辑器换行符与编码规范（防跨平台崩溃）

* **换行符（EOL）自动探测与保留（极度重要）**：
  * 后端在读取文件内容时，必须分析文件流，判断其使用的是 `LF`（Linux/macOS）还是 `CRLF`（Windows）。
  * 返回给前端的 JSON 需包含：`eol_type: "lf" | "crlf"`。
  * 前端 CodeMirror 在加载时，必须保留原有的换行符风格。
  * 保存时，必须原样写回。**严禁**前端把所有文件统一强转为 `\n` 或 `\r\n`，这会导致 Linux 的 Shell 脚本在 Windows 被编辑后彻底失效（经典的 `^M` 错误）。
* **状态栏 UI 提示**：
  * 编辑器底部状态栏必须明确展示当前文件的 `编码格式` 与 `换行符格式`（如：`UTF-8`, `LF`）。
  * 点击该状态标签，应弹出一个下拉菜单，允许用户手动切换为 `CRLF` 或 `LF` 进行转换。
* **文件编码与 BOM 处理（防乱码）**：
  * **读取**：默认按 `UTF-8` 读取。如果读取失败，尝试探测 `GBK`。如果文件开头包含 UTF-8 BOM，必须剥离并在元数据中记录 `has_bom: true`。
  * **保存**：如果原文件包含 BOM，保存时必须将 BOM 原样加回。如果原文件没有 BOM，绝对不允许私自加上 BOM（会导致 Node.js、JSON、Shell 脚本解析崩溃）。

#### 3.2.3 大文件流式传输与防 OOM

* **上传**：必须使用流式处理，**严禁将整个文件读入内存**。接收分块时直接流式落盘。单文件上传上限由配置项 `upload_max_size_mb` 控制（默认 0 表示不限制）。上传前检查目标挂载点剩余空间。
* **下载/播放**：必须支持 HTTP Range（断点续传），使用 `tokio::io::copy` 流式响应。支持单段 Range；多段 Range 返回 416 或降级为全量。必须支持 `HEAD`。响应头包含 `ETag`、`Last-Modified`、`Accept-Ranges: bytes`。中文文件名使用 RFC 5987 编码。
* **上传同名冲突**：沿用文件变更的 `on_conflict` 三选一，默认拒绝。

#### 3.2.4 大目录性能防卡死

* 后端针对目录**强制固定排序 + 游标分页**：目录优先、名称自然排序、大小写不敏感。禁止使用 offset 分页。
* 单目录扫描上限 10000 条，超出截断并返回 `truncated: true`。
* 前端配合游标加载或使用**虚拟列表（Virtual DOM）**，只渲染视口内的文件 DOM。
* 单个文件 `stat` 失败不能导致整页 500，逐项容错并标记 `stat_error`。

#### 3.2.5 右键菜单

集成“下载”、“在此终端中打开”（仅目录）、“分享”、“复制图床直链”、“重命名”、“移动”、“复制”、“删除”、“属性”等高频操作。只读挂载点下变更项全部置灰并带 Tooltip“该挂载点为只读”。

#### 3.2.6 文件变更操作规范

**通用前提**：所有变更接口必须校验 `mount_id` 与 `path` 的归属关系，`path` 经 `canonicalize` 后必须仍在挂载点 `canonical_root` 之下；前端传入路径一律不可信。只读挂载点（`readonly = true`）后端直接返回 `E_READONLY`，前端依据 `list` 接口返回的 `readonly` 标志置灰全部变更入口。

**挂载点根**：启动时对每个挂载点根执行一次 `canonicalize`，存为 `canonical_root`，后续所有校验以此为准。

**路径校验**：对不存在目标的路径（新建、复制目标），**canonicalize 父目录**并校验其在 `canonical_root` 下，再校验文件名字段不含路径分隔符、不为 `.`/`..`、不含 NUL。**禁止对不存在的完整路径直接 `canonicalize`**。

##### 3.2.6.1 新建 / 重命名

* 支持新建文件夹与空文件。
* 名称校验：非法字符 `/\:*?"<>|`、控制字符、结尾空格或点（Windows）、Windows 保留名（`CON/PRN/AUX/NUL/COM1-9/LPT1-9`）、`.` 与 `..`、路径分隔符。
* 大小写不敏感文件系统上 `a.txt → A.txt` 视为合法重命名；Unicode 按 NFC 归一化后比较。
* 目标已存在一律拒绝，**绝不静默覆盖**。数据库路径更新必须使用操作后 `lstat` 得到的**实际名称**，不得用请求中的字符串。

##### 3.2.6.2 移动 / 复制

* 同挂载点移动使用原子 `rename`；同挂载点复制走流式 `tokio::io::copy`。
* 跨挂载点（`dest_mount_id != mount_id`）必须降级为：记录源 `size + mtime` → 流式复制到 `目标名.asmoday-part.<8位随机>` → 比对 `size + mtime` → 一致则用平台 no-replace rename 改为正式文件 → 移动场景再删源。任一步失败保留 `.asmoday-part` 并返回失败，**绝不留下看似正常的半成品**。
* 复制/移动前检查目标挂载点剩余空间（`statvfs`），不足直接拒绝并提示缺口。
* 目标在源目录自身之下时拒绝（防目录套娃）。
* 符号链接默认不跟随，复制/移动链接本身，删除只删链接。
* 覆盖冲突必须弹窗提供“覆盖 / 重命名 / 跳过”，批量场景必须提供“对剩余全部应用”，由前端解析为具体 `on_conflict` 值传给后端，后端不接受 `ask`。

**冲突检测与原子落盘**：后端预检查仅用于提前统计与友好提示，**不构成防覆盖保证**。最终落盘必须使用平台原子 no-replace 操作，失败即返回 `E_CONFLICT`，由前端按 `on_conflict` 重试。

**目录冲突**：`on_conflict=overwrite` 仅对文件生效。目标为已存在目录时，`overwrite` 降级为拒绝（`E_DIR_CONFLICT`），只接受 `rename / skip`。**严禁合并目录内容**。

##### 3.2.6.3 自动命名（`on_conflict=rename`）

* 格式 `基础名 (n).扩展名`，`n` 从 1 递增至 999，超出返回 `E_CONFLICT`。
* 扩展名按最后一个点切割；`file.tar.gz` → 基础名 `file.tar`，扩展名 `.gz`，即 `file.tar (1).gz`。
* 隐藏文件 `.env` 视为无扩展名 → `.env (1)`；`README` → `README (1)`；**不产生尾部点**。
* 加后缀后单段名不得超过文件系统上限（255 字节），基础名按 UTF-8 字符边界截断。
* 批量操作时后端维护一个**跨整个批次共享**的已占用名称 Set，键做 lowercase 归一化。
* 最终落盘用原子 `create_new` 或 no-replace rename 占位，占位失败回退下一个编号，最多重试 10 次。

##### 3.2.6.4 `.asmoday-part` 临时文件

* 命名 `原名.asmoday-part.<8位[a-z0-9]随机码>`，CSPRNG 生成。
* 列表接口默认过滤，`show_hidden` 也不显示；不可预览/下载/分享/哈希。
* 重试复制时生成新随机码，不覆盖旧 `.part`。
* 启动时按 `*.asmoday-part.[a-z0-9]{8}` 精确匹配无差别清理并记日志。
* 清理动作不得阻塞启动，放在后台 `spawn_blocking` 中执行。
* 该命名为保留模式，用户不应创建。

##### 3.2.6.5 删除

* 物理硬删，不做回收站。
* 删除单个目录：请求体带 `confirm_name`，后端比对 `basename(path) == confirm_name`（trim 前后空格，大小写精确匹配），不匹配返回 `E_NAME_MISMATCH`。
* 批量删除：先调 `POST /api/files/delete-token`，后端校验挂载点归属后返回 60 秒一次性 token，绑定「会话 + mount_id + paths 集合哈希」。真实删除时 `paths[]` 必须与 token 绑定集合完全一致。
* 删除前统计项数与总大小并在确认弹窗展示；超过 1000 项额外提示“目录较大”。
* Windows 上文件被占用导致删除失败必须捕获并提示“文件被占用”。
* 批量删除逐项返回结果，不做原子回滚。

##### 3.2.6.6 多选下载

* 不做服务端 ZIP 打包，前端逐个触发浏览器下载。
* 选中项 > 10 时提示“浏览器将并发下载多个文件，可能被拦截”，需用户确认。

##### 3.2.6.7 数据库联动

* **一致性原则**：**文件系统是文件真相，数据库是元数据真相。** 文件系统成功、数据库更新失败时不回滚文件系统，记 ERROR 日志，靠惰性修复兜底。
* **重命名/移动**：同步更新 `favorites / play_history / shares` 中以旧路径为前缀的全部记录；更新 `shares` 时若目标路径已存在分享记录，拒绝本次移动并提示冲突。
* **删除**：级联清理 `favorites / play_history`；`shares` 记录**软删**（置 `deleted_at`），访问返回 **410 Gone**。
* **跨挂载点移动**：视为“新路径写入 + 旧路径删除”，**播放进度与收藏不保留**。

##### 3.2.6.8 操作后状态

* 任何变更完成后，前端必须重置分页游标并重新拉取当前目录；若当前所在目录被删除或移动，前端回到父级并提示。

#### 3.2.7 软链接与路径安全

* **列表与属性**：使用 `symlink_metadata`（lstat），不跟随；symlink 显示为独立类型并带链接图标。
* **预览/下载/分享/哈希**：lstat 为 symlink 时，解析 target 并 `canonicalize`，不在 `canonical_root` 下则返回 `E_SYMLINK_ESCAPE`（403）。
* **复制**：复制链接本身（读 target 字符串创建新 symlink），但**解析 target 后不在 `canonical_root` 下则拒绝复制该项**。
* **移动**：移动链接本身，原子 rename。
* **删除**：`remove_file` 删除链接本身，不跟随。

#### 3.2.8 并发控制

* **锁粒度**：操作涉及的源路径、目标路径、目标父目录全部加 per-path 内存锁；多把锁按规范化路径字典序获取，防死锁。
* **锁等待策略**：**立即失败**，返回 `E_BUSY`，不排队。
* **执行顺序**：加锁 → 文件系统操作 → 数据库更新 → 释放锁。

### 3.3 终端联动 (Terminal)

#### 3.3.1 跨平台 Shell 与默认主目录解析（高优防坑）

* **禁止前端传递 `~`**：前端在未指定具体目录时，`path` 参数传空字符串或省略。
* **后端兜底解析**：Rust 后端接收到空 `path` 时，必须调用 `dirs::home_dir()` 获取真实主目录。
* **Shell 唤醒策略**：
  * Unix/Linux：读取 `$SHELL` 环境变量，回退至 `bash`。
  * Windows：默认拉起 `powershell.exe`（或使用 `portable-pty` 默认支持的 ConPTY）。
* **路径分隔符转换**：若前端传入 POSIX 风格的路径，后端需使用 `PathBuf::from()` 自动转成 Windows 原生反斜杠路径。

#### 3.3.2 PTY 直通与连接数限制

* 真正的系统底层 Shell，支持运行 Vim、Top 等全屏应用。
* 后端必须维护 PTY 连接池，**限制单用户最大并发的 PTY 会话数（默认 10 个，可配置）**。超限时新连接返回错误并提示关闭旧会话。

#### 3.3.3 断线保活（WSS Reconnect）

* 后端维护 PTY 进程池。当 WebSocket 断开时，**PTY 进程延迟 3 分钟再销毁**。
* 前端重连时，带上 `SessionID`，后端直接把缓冲区数据推给前端，无缝恢复现场。
* **输出缓冲上限（防内存打爆）**：每会话维护环形缓冲，上限 1MB；超限丢弃最旧数据并在重连时标记“部分输出已截断”。
* **WebSocket 安全**：必须校验 `Origin` 与登录会话；`session_id` 使用 CSPRNG 生成。
* **进程清理**：服务重启时杀 PTY 进程组，不留孤儿进程。

#### 3.3.4 移动端键盘适配

* PC 端自动隐藏虚拟键盘。
* 移动端复刻 Termux 的两行布局，支持粘性 `CTRL` 和 `ALT` 键。
* 键盘区域必须加 `padding-bottom: env(safe-area-inset-bottom)`。

#### 3.3.5 终端主题与配色策略（强制深色）

* **强制深色渲染区**：为了保证 ANSI 颜色的绝对可读性，`xterm.js` 的渲染区域**严禁跟随全局浅色主题**，必须始终保持深色背景与亮色文字。
* **ANSI 调色板**：必须为 `xterm.js` 配置一套专为深色背景优化的 ANSI 调色板。

#### 3.3.6 终端环境容错与平台差异规范（防脏环境崩溃）

* **环境变量全量继承**：Rust 后端拉起 PTY 时，必须继承当前 Asmoday 进程的完整环境变量（`env`）。严禁清空或篡改用户的 `PATH`、`HOME` 等核心变量。
* **启动报错原样透传**：终端启动时，用户系统产生的 stderr 报错信息，必须**全量透传给前端 xterm.js**。严禁后端吞掉初始化报错。
* **图形化纯净模式（NoProfile 逃生舱）**：
  * 在终端 Tab 栏或设置中，提供“以纯净模式启动”的按钮。
  * Windows 下，启动 PowerShell 时附加 `-NoProfile` 参数。
  * Linux 下，启动 Bash 时附加 `--noprofile --norc` 参数。
* **Windows 编码强制统一（UTF-8）**：
  * 拉起 Windows PowerShell / CMD 时，后端必须优先发送 `chcp 65001` 指令，确保终端输出与前端 xterm.js 的 UTF-8 编码完全对齐。
* **历史记录隔离**：Web 终端不应污染或强依赖于宿主机的本地历史文件。历史记录由前端 xterm.js 与后端 Session 自行维护。

### 3.4 媒体画廊与缓存生命周期 (Gallery)

#### 3.4.1 缩略图生成防雪崩机制

* 引入信号量限制并发数（最多 2-4 张），超出的请求返回占位图。
* 同一缩略图的并发请求必须去重（single-flight 锁）。
* 生成超时 30 秒，超时返回占位图并记 WARN。
* 任务队列上限 100，超出直接返回占位图。

#### 3.4.2 缩略图多格式自适应与 FFmpeg 热加载

* **存储优化**：后台生成缩略图/视频首帧时，**优先编码为 WebP 格式**（利用 FFmpeg 的 `libwebp`）。
* **强制降级机制**：捕获 FFmpeg 错误。若环境不支持 WebP，自动降级回退到 JPEG。
* **动态状态，拒绝静态化**：后端严禁使用静态变量（如 `OnceCell`）缓存 FFmpeg 路径。必须使用 `Arc<RwLock<Option<FfmpegConfig>>>` 管理实时状态。
* **运行时配置生效**：当用户保存了新的 FFmpeg 路径或触发热重载时，后端必须立即在后台执行 `ffmpeg -version` 探活。探活成功更新状态；失败则保留旧配置并记日志。
* **优雅的无图降级**：如果 FFmpeg 未配置或探活失败，接口直接返回 HTTP `404`。前端渲染静态占位图。
* **前端按需重试**：对于降级为占位图的视频，影视库 UI 需提供“重试生成”入口。

#### 3.4.2.1 批量重建缩略图（防 CPU 打爆）

* **异步队列处理**：设置页提供“重新生成所有缺失的缩略图”按钮。后端使用单线程后台队列处理，接口调用后立即返回，前端轮询进度。
* **进度查询**：提供 `GET /api/system/thumbnails/rebuild/status`，返回 `{ total, completed, failed }`。

#### 3.4.3 缩略图缓存键与生命周期管理

* **缓存键**：`mount_id + path + mtime + size` 的哈希。
* **存储**：`data/thumbnails/`，多级哈希散列。只存实体缩略图（.webp/.jpg）。**ThumbHash 绝不落盘为文件，必须存数据库或内存。**
* **LRU 淘汰**：根据 `config.toml` 中的容量阈值和天数自动淘汰。
* **清理按钮**：设置页提供“清理缓存”按钮。

#### 3.4.4 照片相册 (Photos) 净化规则

* **严禁展示系统/无用目录**：相册视图不能展示挂载点名称或“根目录”卡片。前端需对文件夹进行扁平化穿透。
* **剔除无图文件夹**：后端必须过滤掉内部没有任何图片文件的文件夹。
* **文件夹封面**：必须取该文件夹内最新的一张图片的缩略图作为封面。
* **交互区分**：点击相册进入下一级；点击图片触发全局 `MediaLightbox`。

#### 3.4.5 影视库 (Cinema) 封面兜底机制

* **占位图防塌陷**：影视卡片容器必须固定 `aspect-video` 比例，内部 `object-cover`。
* **无预览图降级**：如果没有预览图，必须降级展示纯 CSS/SVG 绘制的默认播放器占位图。
* **播放器选择**：按需动态引入 `Video.js 10`。支持外挂字幕。

#### 3.4.6 音乐库 (Music)

* 读取内嵌 ID3 标签。解析 `.lrc` 歌词滚动高亮。
* **全局悬浮播放条**：跨路由持久存在。包含封面、歌名、播放模式、切歌、进度条。点击播放列表从侧边或底部滑出抽屉。
* **全局音量记忆机制（防爆音）**：初始音量强制 **35%**，用户调整后写入 `localStorage`。静音时记住原音量，取消静音恢复。

#### 3.4.7 媒体文件容错与兜底

* 损坏文件处理：前端捕获 `error` 事件，展示默认损坏占位图。
* ID3 标签与封面兜底：若无 ID3 标签，提取文件名；无封面使用本地占位图，严禁发起外部网络请求。
* 外挂字幕匹配与编码：仅匹配同目录同主文件名，强制进行编码探测（GBK 转 UTF-8），失败静默。

### 3.5 Web UI 配置管理与设置页 (Config Management)

* **彻底抛弃 YAML**：采用 **TOML**。
* **双模编辑**：可视化表单 + 源码模式（调用内置 `CodeMirror 6`）。保存后利用 `notify` 库触发热重载。
* **双模保存的合并规则（强制）**：
  * 源码模式语法错误时**拒绝保存**。
  * 可视化表单保存时**必须基于 TOML AST 做局部合并**，绝不覆盖高级配置。
  * 保存失败必须回滚到旧配置并提示。
* **设置页精细化规范**：
  * **页面布局**：按功能分 Tab（通用、媒体、安全、高级）。
  * **FFmpeg 路径优先级**：UI 手动指定 > 环境变量 > 系统 `PATH`。
  * **恢复默认配置策略**：**严禁**“一键清空所有数据”。分区块重置，绝不覆盖 `config.toml` 中的高级配置。
  * **清理入口**：提供“清理缩略图缓存”“清理临时文件”“清理过期分享 tombstone”按钮。

### 3.6 服务聚合面板 (Service Hub)

* **配置驱动**：支持在 `config.toml` 或 UI 中定义外部服务卡片。
* **智能反向代理**：内置 `hyper` 自动处理 `Host`、`WebSocket Upgrade`，剥离 `X-Frame-Options`。
* **安全边界**：
  * 只有管理员可改 `services`。`target_url` 必须校验协议。
  * 响应头过滤列表：`Set-Cookie` 作用域重写、`Location` 重写。
  * 代理超时、头部大小、响应体大小必须有上限。

### 3.7 系统日志与防撑爆策略

* **输出目标**：日志写入 `data/logs/`。必须使用轮转库，单文件最大 10MB，保留 5 个备份。
* **日志脱敏**：密码、Token、Cookie 等一律不得出现在日志中。
* **全英文输出**：后端所有系统日志、WARN、ERROR 必须使用纯英文。
* **日志分级与格式**：
  * 控制台：默认 `INFO`，本地时区。
  * 文件：默认 `DEBUG`，RFC 3339 UTC 格式。
* **启动日志强制项**：版本号、PID、配置文件路径（绝对路径）、数据库状态、监听地址、前端构建版本（Git Commit Hash）、启动总耗时。
* **异常与降级告警**：`.part` 文件清理、危险配置自检未通过，必须输出 `[WARN]` 或 `[ERROR]`。

### 3.8 多语言国际化支持 (i18n)

* 内置中英语言包（分模块存储）。后端返回标准英文错误码。
* 用户选择存入 `localStorage`，首次访问通过 `navigator.language` 识别。
* 所有界面文本必须走 `vue-i18n`，严禁硬编码。
* **日志与 API 错误的分离原则**：后端不吐自然语言，返回 JSON 的 `message` 仅供开发者调试（强制英文）。

### 3.9 分享访问与 `allow_download` 语义边界

* **诚实声明**：`allow_download=false` **不是 DRM**。该字段的唯一目的是：隐藏下载入口，并限制 HTTP 响应头不触发批量下载。
* **按文件类型的处理矩阵**：
  * 图片/视频/音频/PDF 预览：允许 `raw` 流式请求，强制返回 `Content-Disposition: inline`。
  * 不支持预览的文件：若 `allow_download=false`，单文件分享直接拒绝创建；文件夹分享列表置灰。
* **API 强制拦截**：如果 `allow_download=false`，任何请求 `raw` 接口且带有 `?download=1` 参数的请求，必须返回 `E_FORBIDDEN`。

### 3.10 WebDAV 服务端支持

* **基础协议**：实现 `OPTIONS`、`PROPFIND`、`GET`、`HEAD`、`PUT`、`DELETE`、`MKCOL`、`MOVE`、`COPY`、`LOCK`、`UNLOCK`。
* **认证机制**：Basic Auth，密码为 `asm_` 开头的 Token。必须校验 Token 过期与只读权限。
* **路径与安全**：必须复用 `path_guard` 的 `canonicalize` 校验，禁止 `%2e%2e` 逃逸。
* **流式上传与下载**：`PUT` 必须流式落盘；`GET` 必须支持 Range。
* **PROPFIND 响应优化**：必须限制单次返回的目录深度，并强制分页或截断大目录。
* **WebDAV 防跨平台污染（强制）**：`PROPFIND` 必须复用 `3.2.1` 中的垃圾文件过滤规则。拦截 `._` 开头的文件和 `.DS_Store`。
* **限流与防爆破**：WebDAV Basic Auth 认证失败计入独立的防爆破池。

## 4. 数据库与配置结构

### 4.1 数据库设计 (SQLite)

* **【强制要求】开启 WAL 模式**：启动时执行 `PRAGMA journal_mode=WAL;`。
* **【强制要求】设置 `PRAGMA busy_timeout=5000;`**。
* **迁移策略**：使用 `PRAGMA user_version` 记录 schema 版本，逐级迁移。
* **数据库文件权限**：Unix 下权限 0600。

```sql
-- 1. 用户表（v2 只允许单行，初始化后禁止新增）
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    totp_secret TEXT,
    is_totp_enabled BOOLEAN NOT NULL DEFAULT 0,
    totp_recovery_codes TEXT,
    created_at DATETIME NOT NULL
);

-- 2. 访问令牌表（图床直链 / API Token / WebDAV 挂载）
CREATE TABLE access_tokens (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,
    token_name TEXT NOT NULL,
    token_hash TEXT UNIQUE NOT NULL,
    is_readonly BOOLEAN NOT NULL DEFAULT 1,
    expires_at DATETIME,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 3. 分享记录表（支持 tombstone：deleted_at 非空表示文件已删）
CREATE TABLE shares (
    token TEXT PRIMARY KEY,
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    is_folder BOOLEAN NOT NULL,
    password_hash TEXT,
    allow_download BOOLEAN NOT NULL DEFAULT 1,
    expires_at INTEGER,
    created_at INTEGER NOT NULL,
    deleted_at INTEGER
);

-- 4. 收藏记录（mount_id + file_path 复合主键，支持多挂载点）
CREATE TABLE favorites (
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    created_at INTEGER NOT NULL,
    PRIMARY KEY (mount_id, file_path)
);

-- 5. 播放历史（mount_id + file_path 复合主键）
CREATE TABLE play_history (
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    last_played_at INTEGER NOT NULL,
    progress INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (mount_id, file_path)
);
```

### 4.2 核心配置文件 (`config.toml`)

```toml
[server]
# 监听地址。默认为 "0.0.0.0"（方便局域网访问及 Docker 映射）。
# 若仅本机使用或已前置 Nginx/Caddy 反代，建议改为 "127.0.0.1"。
host = "0.0.0.0"
port = 4242

[server.ssl]
enabled = false
cert_path = ""
key_path = ""

[server.proxy]
trust_proxy_headers = true
trusted_ips = ["127.0.0.1", "172.16.0.0/12"]
base_url = ""

[auth]
local_enabled = true

[auth.proxy_trust]
enabled = false
user_header = "Remote-User"
trusted_ips = ["127.0.0.1"]
skip_2fa = false

[media]
thumb_cache_max_size_mb = 1024
thumb_cache_max_age_days = 90
ffmpeg_path = ""
upload_max_size_mb = 0

# 挂载点示例（readonly 为 true 时前端置灰全部变更入口，后端拦截写操作）
# [[system.mounts]]
# name = "Local Storage"
# path = "/mnt/nas"
# readonly = false

# 外部服务示例
# [[services]]
# id = "light"
# name = "卧室灯"
# icon = "lightbulb"
# type = "external"
# target_url = "http://192.168.1.100:80"
# strip_prefix = false
# rewrite_absolute = false
# ignore_ssl = false
# inject_headers = { X-Custom = "value" }
```

**危险配置自检（启动时执行，只打 WARN 不阻止启动）**：

* `[server.proxy].trust_proxy_headers = true` 且 `trusted_ips` 为空 → WARN。
* `[auth.proxy_trust].enabled = true` 且 `trusted_ips` 为空 → ERROR，并拒绝启用 proxy_trust。
* 检测到环境变量 `ASMODAY_RESET_PASSWORD` 但未使用 `--reset-password` 启动 → WARN。
* `[auth.proxy_trust].skip_2fa = true` → WARN。
* `[server].host = "0.0.0.0"` 且 `[server.ssl].enabled = false` → WARN。

* `-c, --config <PATH>`：指定配置文件路径。

## 6. API 接口契约

### 6.1 文件浏览与流式传输

```text
GET  /api/files/mounts
     → { mounts: [{ id, name, path, readonly, online }] }

GET  /api/files/list?mount_id=&path=&cursor=&show_hidden=false
     → { items: [{ name, path, is_dir, is_symlink, size, mtime, mime, readonly, stat_error? }],
         next_cursor: string | null,
         truncated: boolean,
         readonly: boolean }

GET  /api/files/raw?mount_id=&path=
     → 流式返回，支持单段 Range、HEAD、ETag、Last-Modified

POST /api/files/upload
     → multipart 流式接收，支持 on_conflict 参数

GET  /api/files/thumb?mount_id=&path=
     → 返回缩略图（优先 WebP，降级 JPEG），缺失返回占位图
```

### 6.2 文件变更操作

全部需登录 + 校验 `mount_id` 归属 + 防 `../` 越权 + 只读挂载点拦截。

```text
POST /api/files/mkdir
     { mount_id, path, name }

POST /api/files/touch
     { mount_id, path, name }

POST /api/files/rename
     { mount_id, path, new_name }

POST /api/files/move
     { mount_id, paths[], dest_mount_id, dest_path, on_conflict }

POST /api/files/copy
     { mount_id, paths[], dest_mount_id, dest_path, on_conflict }

POST /api/files/delete-token
     { mount_id, paths[] }
     → { token, expires_in: 60 }

POST /api/files/delete
     { mount_id, paths[], confirm_name? | confirm_token? }

GET  /api/files/stat?mount_id=&path=
     → 只读展示 size / mtime / 权限位 / owner / mime / 真实路径 / inode

POST /api/files/hash
     { mount_id, path }
     → 仅对 < 64MB 文件按需计算，并发哈希数限 2，超出返回 E_BUSY
```

**约束**：

* `on_conflict` 枚举：`overwrite | rename | skip`，后端不接受 `ask`。
* `paths[]` 上限 100，总字节上限 2GB。
* 批量接口返回逐项结果，部分成功不做整体回滚。

### 6.3 配置管理与系统状态

```text
GET  /api/config
POST /api/config
GET  /api/config/raw
POST /api/config/raw
     → 保存后触发热重载；语法错误拒绝保存

GET  /api/system/ffmpeg-status
     → { available, path, webp_support }

GET  /api/system/health
     → { status, version, uptime }

POST /api/system/cleanup/thumbnails
POST /api/system/cleanup/parts
POST /api/system/cleanup/shares

POST /api/system/thumbnails/rebuild
     → 触发后台队列，返回 { status: "started" }

GET  /api/system/thumbnails/rebuild/status
     → 返回 { is_running: boolean, total: number, completed: number, failed: number }
```

### 6.4 终端 WebSocket

```text
WS /api/terminal/ws?mount_id=&path=&cols=80&rows=24&session_id=xxx
```

* `path` 为空默认 `~`（后端 `dirs::home_dir()` 解析）。
* 必须校验 Origin、登录会话、`session_id` 归属。
* 单用户并发 PTY 上限 10，超限拒绝。

### 6.5 认证与分享

```text
POST /api/auth/login
POST /api/auth/logout
POST /api/auth/2fa/verify
GET  /api/auth/session

POST /api/shares
     { mount_id, path, password?, allow_download, expires_at? }
     → { token, url }

GET  /api/shares/:token
     → 404 不存在；410 文件已删除；403 密码错误；200 正常

POST /api/shares/:token/verify
     { password }

GET  /api/shares/:token/raw?path=xxx&download=0
     → 若分享配置 allow_download=false 且 download=1，返回 403 E_FORBIDDEN。
     → 否则流式返回，Content-Disposition 强制 inline。
```

### 6.6 WebDAV 路由

```text
OPTIONS  /dav/:mount_id/*
PROPFIND /dav/:mount_id/*
GET      /dav/:mount_id/*
PUT      /dav/:mount_id/*
DELETE   /dav/:mount_id/*
MKCOL    /dav/:mount_id/*
MOVE     /dav/:mount_id/*
COPY     /dav/:mount_id/*
LOCK     /dav/:mount_id/*
UNLOCK   /dav/:mount_id/*
```

* 需使用 Basic Auth，Token 校验通过后方可访问。
* 后端必须根据 Token `is_readonly` 严格拦截写方法。
* 路径需经 `path_guard` 解码校验，防逃逸。

## 8. UI/UX 交互设计规范

### 8.1 布局与响应式

* **侧边栏**：PC 端固定 240px，移动端抽屉。主工作区独立滚动，毛玻璃面板。
* **底部悬浮条**：音乐播放器与移动端操作栏必须加 `env(safe-area-inset-bottom)`。
* **抽屉/灯箱打开时**：锁定 `body` 滚动，防滚动穿透。
* **高亮逻辑**：无论文件管理模块处于卡片页还是具体的目录中，左侧侧边栏的“文件管理”图标必须始终保持高亮。
* **防闪烁**：从 `/files` 跳转到单挂载点时，需展示全屏的极简 Loading（如毛玻璃遮罩+转圈），确保跳转无白屏闪烁。

### 8.1.1 页面级布局范式（阅读型 vs 工作台型）

* **阅读型页面（如设置的可视化表单、关于页）**：内容区应当限制最大宽度（如 `max-w-5xl`）并居中，防止大屏下输入框过宽导致阅读疲劳。内容可随视口高度自然滚动。
* **工作台型页面（如源码模式、文件列表、终端）**：
  * **绝对禁止限制最大宽度**。内容区必须 `w-full` 铺满可用空间。
  * **动态布局切换**：当用户在设置页从“可视化表单”切换至“源码模式”时，外层容器的 `max-w-*` 居中限制必须在同一帧内被移除，父容器切换为 `h-full flex flex-col`。
  * 必须高度撑满视口：容器高度设置为 `calc(100vh - Header高度 - Tab高度 - 工具栏高度)`，页面内部禁止出现全局滚动条，滚动仅发生在内部组件。
* **侧边栏与主内容区**：主内容区必须是一个独立的 `Flex` 容器（`flex-col`），头部固定不滚动，主体区域 `flex-1` 且 `overflow-hidden`。

### 8.1.2 设置页（表单类）布局与尺寸规范（防“小家子气”）

* **最大宽度解禁**：设置页的主内容区（Card 容器）必须放宽至 `max-w-5xl`（约 1024px）。坚决禁止使用 `max-w-2xl`。
* **表单网格化（Grid）**：表单项较多时（如修改密码的三连框），在大屏下必须使用 Grid 并排展示（如 3 列），在 `md` 断点下自动换行为单列。
* **卡片内边距**：每一个设置区块卡片必须包含充足的内边距，统一使用 `p-6`。卡片之间的垂直间距统一使用 `gap-6`。
* **输入与操作区高度**：输入框、主按钮高度必须统一为 `h-10`。
* **只读字段与复制**：对于 WebDAV 地址等只读长文本，必须包裹在浅色背景（`bg-muted`）的只读框内，右侧固定配备一个清晰的“复制”图标按钮。

### 8.2 主题系统与切换入口规范

* **实现机制**：使用全局 CSS 变量（`:root` 与 `[data-theme="light"]`）实现无刷新级主题切换。
* **状态管理**：全局必须维护三种状态：`light`、`dark`、`system`。默认值必须为 `system`。
* **防白屏逻辑**：原生 JS 在 `<head>` 读取偏好，如果是 `system` 则判断系统偏好，并立刻在 `<html>` 上设置 `data-theme`。
* **监听系统变化**：若当前偏好为 `system`，必须监听系统深浅色变化并动态修改。
* **主题切换按钮位置规范（强制）**：
  * **PC 端**：固定于左侧侧边栏的最底部。图标为太阳/月亮的切换。点击循环切换三种状态。
  * **移动端**：放置在顶部导航栏的右侧区域。
  * **设置页同步**：在“系统设置 - 通用”中也保留一个主题选择下拉框。
* **平滑过渡**：全局 `body` 及卡片需带有 `transition`。**严禁在代码编辑器和终端内应用 transition**。

### 8.3 边缘状态处理

* 加载骨架、空状态引导、无缩略图遮罩、403 无权限空状态、挂载点离线置灰、只读挂载点变更按钮置灰带 Tooltip。

### 8.4 【AI 极易翻车】视觉与交互防坑规范

1. **横竖屏视频自适应（严禁暴力裁剪）**：播放器 `<video>` 必须 `object-fit: contain`。监听 `loadedmetadata` 动态调整容器比例。
2. **图片容器与媒体网格**：必须用固定比例并 `object-cover`。瀑布流用 ThumbHash 占位。
3. **Xterm.js 终端初始化排版**：必须在 DOM 渲染完毕后调用 `fit()`，窗口 `resize` 时也要调用。
4. **文本溢出与长路径处理**：超长文本必须使用 `truncate` 或 `break-all`。
5. **弹窗/抽屉/灯箱的滚动穿透**：打开任何遮罩层，必须锁定底层 `body` 滚动。
6. **移动端安全区适配（Safe Area）**：底部悬浮条、虚拟键盘必须加 `padding-bottom`。
7. **音乐悬浮播放条的层级与适配**：`z-index` 极高，抽屉滑出需适配双端。
8. **文件预览的防崩溃处理**：Markdown 必须过 `DOMPurify`；CSV 必须做体积行数截断；隐藏文件需捕获错误用默认图标占位；无法预览的文件提示框要精美。
9. **全局媒体组件的内存与生命周期管理**：图片灯箱和视频播放器作为单实例（Teleport 到 body）。关闭视频预览时，**必须**手动销毁 `<video>` 元素（`pause(); src=''; load();`）。
10. **禁止原生弹窗**：冲突提示、删除确认等一律使用封装的 Modal 组件。
11. **移动端软键盘适配**：必须监听 `window.visualViewport` 的 `resize` 事件，重新调用 `xterm.js` 的 `fit()`。

### 8.4.1 源码编辑器（CodeMirror 6）防翻车规范

1. **禁用固定宽高，必须 100% 撑满**：必须使用 `width: 100%; height: 100%` 搭配外层 Flex 容器撑满剩余空间。
2. **禁止双层滚动条**：外层的页面必须 `overflow: hidden`，滚动条只能由编辑器内部产生。
3. **源码模式切换重排**：在可视化表单和源码模式之间切换时，必须使用 `nextTick`，并通知 CodeMirror 重新计算尺寸。
4. **行号与工具栏**：工具栏必须固定吸附在编辑器上方。
5. **杜绝横向憋屈**：代码区域默认开启水平滚动，绝不强制折行导致缩进错乱。

### 8.4.2 列表与数据排版规范（针对 Token 列表等）

* **表头与对齐**：必须使用标准表格样式，表头与数据列严格对齐。
* **行高与间距**：列表行高统一，至少在 `h-12` 以上。
* **危险操作视觉隔离**：删除按钮必须在视觉上与正常文本保持足够距离，并带有 `hover:text-red-500`。
* **操作区对齐**：表单行内的元素必须使用 Flex 布局并带有 `gap-4`。

### 8.4.3 提示文案与代码块排版

* **弱化长文**：说明文案使用 `text-sm text-muted-foreground`，行高 `leading-relaxed`。
* **代码/命令提示**：涉及终端命令，必须包裹在 `<code>` 标签中，使用等宽字体，并带有浅色背景。

### 8.4.4 终端 UI 容器协调规范（消除割裂感）

1. **禁止直接贴边**：终端渲染区域绝对不能直接作为页面的根节点铺满整个视口。必须包裹在带有圆角的容器内。
2. **外层卡片缓冲**：在浅色主题下，终端外部的主内容区必须有浅色背景，终端外壳四周需有 Padding 和阴影。
3. **外壳跟随主题**：终端顶部的标签栏、功能按钮以及底部的状态栏，**必须跟随全局主题**。只有中间的渲染区域是纯黑的。
4. **Xterm 内部 Padding**：内层 DOM 必须通过 CSS 注入 `padding: 8px 12px;`。

### 8.4.5 文件列表 UI 渲染防坑（极度重要）

1. **禁止使用 Flex 替代 Grid**：必须使用 `grid` 布局。
2. **图标/缩略图尺寸标准化**：必须通过 `w-16 h-16` 或 `aspect-square` 等比例放大。严禁使用 24x24 的小图标充当网格视图。
3. **排序状态明确**：排序菜单的当前选中项必须打勾，并在工具栏显示当前的排序方式。
4. **分页加载无感化**：滚动到底部必须自动加载下一页，且底部必须有 Loading 骨架屏。变更排序方式时，必须清空列表并重新拉取。

### 8.5 文件变更操作的 UI 与内存防坑

1. **禁止原生弹窗**：一律使用封装的 Modal 组件。
2. **进度反馈按操作类型区分**：
   * 单文件上传：使用 `onprogress` 展示真实百分比进度条。
   * 单文件下载：交由浏览器原生下载管理器。
   * 批量 copy / move / delete：采用不确定进度（骨架屏 + 转圈 + 禁用按钮）。
3. **跨设备防崩**：必须判断 `dest_mount_id == mount_id`，不同则走流式复制。
4. **分页失效**：变更后重置游标并重新拉取。
5. **移动端**：长按菜单与滚动冲突需处理。
6. **只读挂载点**：变更按钮置灰并带 Tooltip。
7. **批量冲突**：必须提供“对剩余全部应用”选项。
8. **操作结果汇总**：批量操作完成后统一弹结果汇总，失败项提供重试入口。
9. **重复提交防护**：操作期间按钮禁用，遇到 `E_BUSY` 提示“文件正在被其他操作占用”。
10. **前端并发上传排队限制**：前端多文件上传必须实现**并发池（默认 3 个）**。超出的文件在内存中排队（展示为灰色等待状态），前一个完成后再发起下一个请求。

### 8.6 移动端手势与长按菜单防坑规范

1. **长按判定与防冲突**：
   * 必须设置 `user-select: none; -webkit-touch-callout: none;`。
   * 长按触发阈值为 **500ms**。若在 500ms 内手指滑动超过 **10px**，立刻取消长按计时器。
   * 长按触发后，必须拦截并忽略紧随其后的 `click` / `touchend` 事件。
2. **多选与底部操作栏**：
   * 进入多选模式时，底部滑出操作栏。操作栏必须加 `padding-bottom`。
   * 列表容器底部必须动态增加 padding，防止最后几个文件被操作栏永久遮挡。

### 8.7 语言切换交互规范

* 设置中支持中英切换，即时生效无需刷新。

## 9. 部署与编译策略

### 9.1 极致体积裁剪

```toml
[profile.release]
opt-level = "z"
lto = true
codegen-units = 1
panic = "abort"
strip = true
```

### 9.2 目标编译矩阵

1. Linux ARM64: `aarch64-unknown-linux-musl`
2. Linux x86_64: `x86_64-unknown-linux-musl`
3. Windows x64: `x86_64-pc-windows-msvc`
4. macOS ARM64: `aarch64-apple-darwin`
5. macOS x64: `x86_64-apple-darwin`

**编译期验证项**：

* `renameat2` 在 musl 静态链接下的可用性。
* `portable-pty` 在目标平台拉起 shell 的兼容性。
* `rusqlite bundled` 在各平台编译通过。

### 9.3 危险配置自检（启动时执行）

* 各种危险组合打 WARN 或 ERROR，自检结果写入日志并在设置页展示警告条。

### 9.4 已知限制（写入文档）

* 单管理员场景下 TOCTOU 不额外防护。
* v2 不支持断点续传、异步任务、回收站。
* 浏览器解码能力决定可播放格式。
* `allow_download=false` 不防抓包。
* WebDAV 的 `LOCK` 为伪锁。
