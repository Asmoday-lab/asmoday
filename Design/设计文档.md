# Asmoday 产品与系统设计文档（定稿版 v4.3.1）

**定位**：专为低功耗 64 位设备（ARM64 / x86_64）设计的、单二进制的个人媒体与设备控制中枢。前后端分离开发，单体二进制发布。默认单管理员模型。

**本版修订（v4.3.1）**：媒体库也吃上目录快照缓存（6.5），两万张图的库翻页从整树重扫变成读库；查询串布尔参数统一宽松解析。

**前版修订（v4.3.0）**：递归搜索加目录快照缓存（4.7），5 万条目从 406 ms 降到 60 ms 量级且跨重启有效；只为命中的条目付 `lstat`。

**前版修订（v4.2.6）**：搜索改成递归 + 栈游标分页（4.6）；修「虚拟列表外面放哨兵只会续一页」的无限滚动缺陷。

**前版修订**：会话改为**自研**（`core/auth.rs`，不再用 `tower-sessions`）—— 滑动续期、30 天绝对上限、敏感操作二次验证时间戳都要求直接读写 `sessions` 行，store 抽象反而要包一层；标注 `notify` 在 macOS 的 `Remove` 事件风险；锁定 Video.js 10.0.0 且禁止跟随 `latest`；补充 `rusqlite bundled` 的 CI 缓存要求；注明 `axum 0.8` 花括号路由语法。

## 1. 核心红线（不可协商）

1. 不内置多媒体转码，仅依赖浏览器解码。
2. 不内置刮削、AI、同步、App、BT 下载、在线办公。
3. 不依赖外部 CDN，前端静态资源全量打包进二进制。
4. 不提供关闭认证的配置开关。忘记密码仅通过 CLI 或删除数据重置。
5. 不提供回收站。删除一律物理硬删。`shares` 的 410 tombstone 仅服务分享链接。
6. 单次 `copy / move`：**选中条目数** > 100 **或** 递归总字节 > 2GB（任一超限即拒绝，引导至终端用 `cp`/`mv`）。阈值可配（`[server.limits]`，0 = 不限）。两条判定口径必须分清：
   - 条目数只数**用户选中的条目**，不数目录里套了多少文件 —— 选中一个装一万张照片的目录算 1 项；
   - 字节数才递归统计（上限靠它兜住），且**同挂载点内的移动不做统计**（原子 `rename` 不搬数据、不占空间），复制与跨挂载点移动才统计;
   - `delete` 只校验本批选中条目数，绝不为了拒绝先去 `remove_dir_all` 前扫全树（删除本身是 O(1) 元数据操作）；
   - `rename / mkdir / touch / stat / hash` 不受此限。
7. 目录冲突时 `on_conflict=overwrite` 直接拒绝（`E_DIR_CONFLICT`），只接受 `rename / skip`。严禁合并目录内容。
8. 不内置 ACME。证书由用户手动指定或前置 Caddy/Nginx。
9. 禁止 iframe 内嵌第三方外部服务。本地 PDF 的 `<iframe src="raw_url">` 预览不受此限。
10. 严禁降级依赖。必须使用本文锁定的版本与 API。
11. 严禁前端硬编码界面文本，一律 `vue-i18n`。
12. 严禁“先检查再操作”代替原子落盘。防覆盖依赖平台原子 no-replace 操作。
13. 严禁对不存在的完整路径直接 `canonicalize`。必须 `canonicalize` 父目录并校验归属。
14. 严禁在列表循环中生成隐藏的 `<video>` / `<audio>`。全局媒体组件单实例。
15. 严禁将 ThumbHash 保存为碎文件。必须存入 SQLite。
16. 严禁覆盖用户 EOL。保存时原样写回 `LF` / `CRLF`。
17. 严禁使用仅支持反序列化的 TOML 库重写配置。必须 `toml_edit` AST 局部修改。
18. 严禁向宿主机全局环境变量注入污染。额外变量在 `CommandBuilder` 中临时注入。
19. 终端必须进入交互式登录模式，打包 Nerd Font 与标准 ANSI 色板。

## 2. 技术架构与锁定依赖

### 2.1 总体架构

- **后端**：Rust，`axum = "0.8"`，`axum::serve`。`rust-embed` 打包前端。
- **前端**：Vue 3 + Vite + TailwindCSS v4（`@tailwindcss/vite`，CSS 中 `@import "tailwindcss"`，无 `tailwind.config.js`）。
- **跨平台**：Windows x64、macOS Universal 2、Linux x86_64/ARM64 musl，单二进制。

### 2.2 锁定依赖

| 用途 | 依赖 | 版本/要求 |
|---|---|---|
| Web 框架 | `axum` | `0.8`，严禁 `axum::Server`。路由必须用 `{param}` / `{*wildcard}` 语法 |
| 会话 | 自研（`core/auth.rs` + `sessions` 表） | **不引入 `tower-sessions`**：滑动续期 / 绝对上限 / `verified_at`（二次验证）都要直接改行，store 抽象只会挡路 |
| 密码哈希 | `argon2` | Argon2id，`m=19456 KiB, t=2, p=1`（OWASP 2025 最低） |
| Token/恢复码 | `sha2` / `hmac` | SHA-256/HMAC + 常量时间比较 |
| PTY | `portable-pty` | 必须实现 5.3 的 Windows ConPTY 缓解 |
| 数据库 | `rusqlite`（`bundled`） | 启动执行 `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000;`。CI 必须缓存 `target/`，否则 ARM64 musl 的 bundled 编译可能超时 |
| 配置 | `toml_edit` | AST 局部修改，源码模式禁止格式化 |
| 文件监听 | `notify`（**不用** `notify-debouncer-full`） | 自己写 500ms 防抖（`RELOAD_DEBOUNCE` + `recv_timeout`）；见 7.2 的 macOS `Remove` 风险 |

| 前端终端 | `xterm.js` + `xterm-addon-fit` | 必须打包 JetBrainsMono Nerd Font woff2 |
| 编辑器 | CodeMirror 6 | 按需引入 `@codemirror/state`, `@codemirror/view` 及语言包 |
| 播放器 | Video.js | **`10.0.0` GA**，`@videojs/html` Web Components，严禁 v8 API；禁止 `latest` 或未锁定的 `^10.x` |
| i18n | `vue-i18n` | v9+，**必须 `createI18n({ legacy: false })`** |
| Markdown | `marked` + `DOMPurify` | 动态 `import()` |
| CSV | 轻量解析器 | 动态 `import()`，5MB/1000 行截断 |
| 传输层压缩 | `tower-http` | `compression-br` + `compression-gzip`，判定见 2.4 |

| 单实例锁 | `std::fs::File::try_lock` | Rust 1.89 稳定；Unix `flock`、Windows `LockFileEx`。**不要再用 SQLite 排他锁**（`BEGIN EXCLUSIVE` 在回滚日志模式下只拿 RESERVED，实测挡不住第二个实例） |
| WebDAV 协议 | `dav-server`（`localfs` feature） | RFC 4918 全套实现，见 12。**不手写协议**：`PROPFIND` 属性、`If` 头、多段 Range 这些边角错一个客户端就加不上 |
| schema 版本 | `rusqlite_migration`（`1.3`，兼容 rusqlite 0.32） | `PRAGMA user_version` 记进度，见 13。加列只追加 `M::up`，**不要回头改 v1** |

### 2.3 前端资源与 SPA Fallback

- 带 Hash 静态文件：`Cache-Control: immutable`，一年。
- `index.html`：`Cache-Control: no-cache`。
- Fallback 仅当请求无文件扩展名 **且** `Accept` 含 `text/html`，且路径不在 `/api/*`、`/dav/*`、`/proxy/*` 下。带扩展名静态资源缺失直接 404。
- `base_url` 前缀在路由、Cookie Path、WebSocket URL、静态资源、分享链接、重定向中统一剥离/拼接。

### 2.4 传输层压缩

- 统一在响应最外层挂 `tower-http` 的 `CompressionLayer`（br 优先、gzip 兜底）。
  **不手写 `Content-Encoding`**：分块编码、`Vary: accept-encoding`、移除 `Content-Length`、
  协商顺序这些细节社区实现已经兜住，自己写漏一个就是线上事故。
- 判定用**白名单**而不是 `DefaultPredicate`：后者只排除图片 / gRPC / SSE，剩下的什么都压，
  `video/mp4`、`application/zip` 会被白白过一遍 CPU（还可能变大）。白名单只放
  `text/*`、JSON、JS、XML、SVG、wasm。
- 三条硬性排除：`206 Partial Content`（`/api/files/raw` 的字节区间按未压缩文件算，压完
  `Content-Range` 失真、视频拖动花屏）、已带 `Content-Encoding` 的响应、
  `Cache-Control: no-transform` 的响应。小于 1 KiB 的也不压。

## 3. 认证、会话与安全

### 3.1 初始化

- 首次启动生成一次性**初始化令牌**，打印至控制台。初始化页面必须携带；缺失或错误返回 403。初始化接口限流 5 次/分钟/IP。未初始化前除初始化接口外全部 503。
- `--init` 自动生成随机密码打印日志，首次登录强制改密。
- `users` 表只允许单行。多行时启动记 ERROR，只使用 id 最小记录。

### 3.2 密码与重置

- 密码 Argon2id，参数见 2.2。
- `--reset-password` 交互式重置；`ASMODAY_RESET_PASSWORD` 仅在配合 `--reset-password` 时一次性生效，生效后写 `must_change_password=1`（登录后强制改密），同变量再次出现拒绝并 WARN。日志不打印密码。
- `--reset-2fa` 清除 `totp_secret` 并关闭 2FA，需当前密码或走重置流程。
- 重置成功后删除该用户全部服务端会话（`DELETE FROM sessions WHERE user_id = ?`）。表里没有 `session_version`：删行即失效，逻辑更短也没有「忘了递增值」的坑。

### 3.3 会话（自研 `sessions` 表）

- 表结构由 `core/auth.rs` 的 `SCHEMA` 建（不再由第三方 store 建表）：`token`（PK）、`user_id`、`created_at`、`expires_at`。Cookie 里放的 `token` 就是主键。`HttpOnly`、`SameSite=Lax`、`Secure` 仅 HTTPS 或可信 `X-Forwarded-Proto=https`、`Path` 与 `base_url` 一致。
- 滑动续期：闲置 7 天过期，绝对上限 30 天（`created_at + 30d`，续期不得越过）。登录与 2FA 通过后轮换 `token`。
- ~~`verified_at` 二次验证时间闸门~~：**v4.4.1 移除**——敏感操作（终端 WS、令牌增删、配置写入、备份下载）不再要求「5 分钟内输过密码」，会话防线回到登录本身。列保留只为存量库平滑升级，代码不再读写。
- 登出删除服务端会话行。改密、2FA 开关、`--reset-password` 后删除该用户全部会话。
- **CSRF**：Cookie 认证的写操作（POST/PUT/DELETE/PATCH），若 `Origin` 与 `Referer` **均缺失，直接拒绝**；至少一个与 Host 同源则放行。`Authorization: Bearer asm_...` 请求豁免 CSRF Origin 校验。
- **WebSocket**：`/api/terminal/ws` 无条件校验 Origin 与 Host 同源；无 Origin 的非浏览器客户端放行。

### 3.4 Bearer Token 认证

- Auth 中间件优先检查 `Authorization: Bearer`。命中则按 `access_tokens` 校验哈希与过期，映射 `is_readonly` 为请求级权限。未命中回退会话 Cookie。
- WebDAV Basic Auth 复用同一 Token 校验：用户名 = `token_name`，密码 = `asm_` 明文。`access_tokens.token_name` 必须 `UNIQUE`。
- **管理员密码直连（v4.4.0）**：Token 校验失败后回退校验 `users` 表（用户名 + 登录密码，Argon2 + 进程内缓存），
  解决「首次部署无令牌可用」的冷启动问题。放行 = 全量权限（读写、全部挂载点）；`must_change_password`
  与 TOTP 已开启的账号拒绝（Basic Auth 表达不了第二因子）。缓存键是「用户名+密码」的 SHA-1（不落明文），
  值存验证时的 Argon2 哈希快照——改密后即时失效。

### 3.5 2FA

- TOTP 可选。开启时生成 10 个恢复码，仅存哈希，展示一次。**每个恢复码验证成功后立即从存储移除**。关闭 2FA 需当前密码 + TOTP 或未使用恢复码。

### 3.6 防爆破

- 独立池：主登录按 `IP + username` + 纯 IP；分享按 `share_token + IP`；WebDAV 按 `token_name + IP`。成功认证重置对应计数。白名单 IP 仅豁免主登录。计数器后台定时 GC。

### 3.7 代理与 SSO

- `X-Forwarded-*` 仅当源 IP 命中 `trusted_ips` 时采信。
- `proxy_trust.enabled=true` 时，仅当源 IP 命中 `trusted_ips` 才采信 Header；白名单为空拒绝启用并 ERROR。Header 用户名必须等于 `users.username`，否则拒绝登录。`skip_2fa=true` 启动 WARN。
- 本站会话 Cookie 绝不下发给上游；上游同名 `Set-Cookie` 丢弃。

### 3.8 安全响应头

- 默认：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、收紧 `Permissions-Policy`、HTTPS 下 HSTS。CSP 禁止 `unsafe-eval`，`frame-ancestors` 按需。

## 4. 文件管理

### 4.1 视图与过滤

- 仅网格视图与列表视图。偏好写 `localStorage`。
- 后端硬编码过滤垃圾文件（列表、媒体扫描、WebDAV PROPFIND 均生效）：精确匹配 `desktop.ini`、`Thumbs.db`、`.DS_Store`、`lost+found`、`.Trashes`、`.Spotlight-V100`、`.fseventsd`、`$RECYCLE.BIN`、`System Volume Information`；前缀 `~$`、`._`；后缀/包含 `*.crdownload`、`*.part`、`*.!ut`、`*.tmp`。普通隐藏文件受 `show_hidden` 控制。
- 路由：每次 `/files` 拉取 `/api/files/mounts`。零挂载点空状态；单挂载点在线 `router.replace` 至 `/files/:mountId/`；单挂载点离线停留卡片；多挂载点卡片列表。
- 面包屑：多挂载点 `[🏠] / 挂载点 / 目录`；单挂载点 `[🏠 挂载点] / 目录`。

### 4.2 预览矩阵

- 图片/视频/音频：全局 `MediaLightbox` / 全局播放器，单实例。图片收集同目录同类型数组，支持左右切换。
- 文本/代码：CodeMirror 6。Markdown 默认渲染预览（`marked` + `DOMPurify`），可切换源码。PDF `<iframe src="raw_url">`。CSV 超 5MB 或 1000 行截断。Office/CAD/压缩包提示下载。
- 编辑器：后端返回 `eol_type: "lf"|"crlf"`、`has_bom`。保存原样写回 EOL 与 BOM。状态栏展示编码与 EOL，可手动切换。读取默认 UTF-8，失败尝试 GBK，UTF-8 BOM 剥离并记录。
- 语言自动识别：按扩展名映射，无后缀/特殊后缀正则兜底，未知降级纯文本。语言包动态 `import()`。顶部下拉框可手动切换。
- **编辑器整屏接管（v4.4.5）**：点开文件即铺满整个浏览器（`Teleport` 到 `body` 的
  `fixed inset-0`），侧边栏与顶栏全部让位——代码编辑器挤在 240px 侧边栏 + 工具栏右侧的
  窄条里，行一长就得横向滚动，手机上更是只剩两三行。选 `Teleport` 而不是就地 `fixed`：
  文件页在 `#app-scroll` 里，路由过渡期祖先带 `transform`，就地 `fixed` 会变成相对祖先
  定位而错位。列表不卸载，关掉编辑器立刻回到原目录与滚动位置，不重新拉一遍。
- 顶栏顺序与我们其他页一致：关闭（×）→ 文件名（未保存加点）→ 字号步进器
  （`− 14px +`，点中间回默认，值存 `asmoday.editor.fontSize`）→ 语言下拉 → 保存（带 `Ctrl+S`）。
  窄屏只留关闭 / 文件名 / 语言 / 图标版保存，字号控件隐藏（默认 13px）。下方一行是
  虚拟路径面包屑（挂载点名 › 目录 › 文件名，可横向滚动），与列表面包屑同一口径，
  绝不摊开真实盘符路径。
- 保存前关闭不再用原生 `confirm`：弹「取消 / 保存更改 / 放弃修改」三选一。
  原生只有两态，想「存一下就关」得先取消再存再关，而且样式在移动端完全不可控。
  `closeEditor()` 因此变成 `async`，调用方（换目录、开预览、面包屑、路由守卫）
  一律 `await` 结果——用户点取消或保存失败就中止后续动作，不再「关了编辑器却换了目录」。

### 4.3 流式传输与性能

- 上传流式落盘，单文件上限 `upload_max_size_mb`，上传前检查剩余空间。上传同名冲突沿用 `on_conflict`。
- 下载/播放支持 Range、HEAD、`ETag`、`Last-Modified`、`Accept-Ranges: bytes`。中文文件名 RFC 5987。
- **下载必须走 `?download=1`（v4.4.9）**：`raw` 带这个参数时回 `Content-Disposition: attachment`
  （`filename` ASCII 兜底 + `filename*=UTF-8''…`）与 `application/octet-stream` + `nosniff`。
  以前前后端都用 `window.open(raw)`，浏览器会就地渲染：TOML / 日志变成一页乱码（
  `mime_guess` 给 `text/plain` 但不带 charset，中文 Windows 按 GBK 解码），目录则直接报错。
  非下载的文本响应统一补 `charset=utf-8`。
- **目录下载 = store 模式流式 ZIP（v4.4.9）**：`/api/files/archive` 不压缩、不落临时文件，
  边读边发（数据描述符承载 CRC 与长度，只读一遍文件）。媒体库里 99% 是已压缩的
  JPEG / WebP / MP4，deflate 只换来 CPU 与等待。两条硬边界：单文件 ≥4GiB 与条目数 >65535
  直接拒绝（不实现 Zip64），提示单独下载。不跟随软链接——指向 `/` 的链接会把整机塞进 zip。
- **稳定排序键 + 游标分页**，禁止 offset。游标键：名称 `(name, path)`、时间 `(mtime, path)`、大小 `(size, path)`。切换排序清空列表重新请求。
- **目录没有扫描上限**（v4.2.4）：文件管理要和本地管理器一样能翻到最后一条，任何排序下 `total` 都等于目录真实条数。性能靠两件事而不是截断：排序键并发补全（24 路，等价于把「串行两万次 stat」压到百毫秒级）、条目容器只留 `i64` 排序键（不再为每条常驻一整个 `Metadata`）。`truncated` 字段随上限一起移除。
- **键盘与拖拽**（v4.2.4）：`F2` 重命名、`Delete` 删除（均复用已有弹窗，不新增 UI）、`Ctrl/⌘ + C/X/V` 内部剪贴板、`Ctrl/⌘ + A` 全选、`Shift + 点击` 范围选择、`Esc` 逐层关闭弹层；把条目拖到文件夹 = 移动，按住 `Alt` 拖 = 复制。快捷操作一律先按 `skip` 落盘，命中同名再回退到移动/复制对话框让用户明确选择——**绝不静默覆盖**。焦点在输入框/富文本里时不抢键，移动端不挂键盘（长按多选保持原样）。
- 单个 `stat` 失败逐项容错，标记 `stat_error`。

### 4.4 右键菜单与路径

- 全局 `ContextMenu` 复用于文件、相册、影视库、音乐列表。菜单含下载（文件与目录都支持）、在此终端中打开、分享、复制直链、重命名、移动、复制、删除、属性。
- **v4.4.9 移除「复制相对/绝对路径」**：复制一串路径在浏览器里没有下游（要路径的场景直接走「在此终端中打开」），
  只保留有实际用途的「复制图床直链」。`relativePathOf` / `copyPath` 一并删掉，不留死代码。
- 复制绝对路径：`/api/files/stat` 的 `real_absolute_path`（`canonicalize` 结果）。仅管理员控制台可用；分享访客 API 不返回物理路径字段。
- 只读挂载点变更项置灰并 Tooltip。

### 4.5 变更操作

- 通用：校验 `mount_id` 与 `path` 归属；`path` canonicalize 后必须在挂载点 `canonical_root` 下。只读返回 `E_READONLY`。挂载点根启动时 canonicalize 存 `canonical_root`。不存在目标 canonicalize 父目录并校验。
- 新建/重命名：名称校验非法字符、控制字符、结尾空格/点、Windows 保留名、`.`/`..`。目标存在一律拒绝。
- 移动/复制：同挂载点移动原子 `rename`；复制流式 `tokio::io::copy`。跨挂载点：流式复制到 `原名.asmoday-part.<8位[a-z0-9]随机码>` → 比对字节数（可选 SHA-256，仅 <100MiB）→ 原子改名 → 移动删源。源删除失败返回 `E_SOURCE_DELETE_FAILED`，UI 提示手动清理。目标空间不足拒绝。目录冲突 `overwrite` 拒绝（`E_DIR_CONFLICT`）。
- 自动命名：`基础名 (n).扩展名`，n 从 1 到 999，超出 `E_CONFLICT_RETRY_EXHAUSTED`。
- `.asmoday-part` 临时文件：列表默认过滤，不可预览/下载，启动时清理。
- **应用数据目录是「保留目录」**：`data/`（SQLite / 日志 / 缩略图缓存）在启动时登记，列表不返回、
  `/api/files/*` 与 WebDAV 一律 403（`E_FORBIDDEN`），媒体扫描与搜索跳过。默认「未配置挂载点时挂 cwd」
  + 「数据目录 `cwd/data`」天生重叠，不拦的话缩略图缓存会作为普通图片被再次缩略图，产物写回同一目录、
  下一轮又成为新的「图片」，按宽度倍数指数增殖。显式把数据目录挂出来时该挂载点整体不可见，启动日志 WARN 提示。
- 删除：物理硬删。单目录需 `confirm_name`；批量需 `delete-token`。删除后级联清理 `favorites / play_history`；`shares` 软删，访问返回 410。
- 并发：按规范化路径字典序获取 per-path 内存锁，冲突立即 `E_BUSY`，不排队。
- 软链接：链接类条目（符号链接 + Windows junction / 挂载点重解析点）统一识别，
  `tokio::fs::metadata` 跟随判定目标类型，返回 `is_symlink`、`target_is_dir`、`symlink_target`。
  **逃逸策略由 `[system].follow_symlinks` 决定**（默认 `true`，与 FileBrowser 行为一致）：
  - `true`：挂载点内的链接指向挂载点外时照常浏览 / 预览 / 上传 / 改名，**寻址始终以链接路径为前缀**
    （接口返回的路径不替换成目标真实路径，否则下一次请求会带着挂载点外的绝对路径回来被拒绝）；
    列表不再标断链。**直接传挂载点外的绝对路径依旧 403** —— 放开的只有「链接解析」，不是「任意路径」，
    判定条件是「路径字面上在挂载点内 + 沿途至少有一段是链接」；
  - `false`：维持严格边界，target canonicalize 不在 `canonical_root` 下返回 `E_SYMLINK_ESCAPE`
    （跨挂载点链接同样拒绝），列表按断链置灰。
- 复制软链接不跟随（复制的是链接本身）；`follow_symlinks=false` 时拒绝复制指向挂载点外的链接
  （避免把这个「洞」搬到新位置）。删除只删链接本身，绝不递归删目标。
- 挂载点热移除：前端中断请求，重定向 `/files` 提示。离线直达子目录阻断回卡片页。

### 4.6 搜索（v4.2.6）

- `GET /api/files/search?q=&path=&recursive=&limit=&cursor=`：文件名**包含**匹配（大小写不敏感），
  `recursive=false`（默认）只搜当前目录第一层，`true` 搜整棵子树。**没有结果条数上限**，
  只有「单页多少条」（`limit` 默认 200、上限 1000）与「单页扫描预算」（50 000 条目）。
- **确定序 DFS + 栈游标**：每层目录内按「目录优先 + 名称升序」排序（`readdir` 顺序不可依赖），
  深度优先遍历；游标记录 `[(目录相对路径, 下一个待访问条目名), …]`，base64url(JSON) 交给前端。
  续页只重开栈里的那几个目录，代价与页数近似无关；目录中途增删最多重复一条（前端按路径去重），
  不会像 offset 分页那样整体错位。坏游标按「从头开始」处理，不报错。
- **扫描预算不是截断**：一页访问满 `budget` 条就把游标交出去，前端看到的是「继续加载」，
  而不是「只搜到这里」——十万条目的极窄关键词也能逐页翻到底。
- 跳过口径与列表完全一致（共用一个 `skip_listing_name`）：`.asmoday-part*`、系统垃圾、
  应用数据目录一律不出现；但**搜索不理会 `show_hidden`**（用户敲了关键词就是明确想看）。
- 链接目录默认不递归（与列表「指向目录的链接不冒充目录」同口径）；`follow_symlinks=true` 时才进，
  用 `canonicalize` 结果去重防环，另有 `MAX_DEPTH = 32` 兜底。无权限目录直接跳过，不让整次搜索失败。
- 响应带 `scanned`（本页扫过多少条）、`has_more`、`next_cursor`，每条命中带 `rel`（相对搜索根的
  POSIX 路径）——结果可能来自任意子目录，不标出来用户不知道它藏在哪。
- **前端触底判定在虚拟列表内部**：`VirtualList` / `VirtualGrid` 自己就是滚动容器
  （`h-full overflow-y-auto`），放在它们外面的 1px sentinel 永远处于可见状态，
  `IntersectionObserver` 只会在首屏响一次（1000 条以上的目录翻到第二页就停）。
  现在组件自己在 `scroll` 里判断「距底 < 240px」并 emit `bottom`（同一底部窗口去重），
  追加后重新打量一次，一页填不满视口会自动补下一页。搜索结果复用同一条通道。

### 4.7 目录快照缓存（v4.3.0）

递归搜索原来每走一层都要 `readdir`，五万条目的树翻一页就要几百毫秒，翻到底等于把整棵树
重读几遍。这里加一层**目录快照缓存**（`core/dir_cache.rs`，落在同一个 SQLite 里）：

- 表 `dir_snapshots(path PRIMARY KEY, stamp, entries BLOB, entry_count, used_at)`：
  一个目录一行，`entries` 是自定义紧凑二进制（12 字节/条，5 万条约 600 KB），
  只有 `name` 与 `kind`（文件 / 目录 / 链接）。命中时继续用这套顺序，不再重排。
- **判定靠目录 mtime**：目录内容的名字集合只在创建 / 删除 / 改名时变化，这三种操作都会推进
  父目录 mtime；mtime 对得上就说明名字集合没变（大小 / mtime 这类「原地会变」的字段一律不入缓存，
  命中条目要展示时现 `lstat`）。
- **只收留「落定」的目录**：目录 mtime 距现在不足 **2 秒**一律不入库。时间戳分辨率是系统时钟粒度
  （Windows 约 15.6 ms），留 2 秒余量才能保证「入缓存之后发生的任何变化」得到一个**严格更大**的
  mtime，从而失配重扫——同一 tick 内的两次操作不会被误判成「没变过」。正在上传 / 解压的目录
  本来也一直在变，不缓存它们正好。
- 缓存是**尽力而为**：任何 SQLite 错误都当 miss，库被删、表被改、路径换挂载点，最坏退回
  「每次 readdir」，绝不让搜索失败。`MAX_DIRS = 4096` 按 `used_at`（+ rowid 兜底，同一秒内也能
  分出先后）做 LRU 裁剪。
- 实测（5 万文件 / 201 目录 / 关键词只命中 10 条，release）：首次 406 ms（建缓存），
  之后 57–77 ms（含**重启进程后**的首次，缓存是持久的），约 5–7×。
- 顺带一处与缓存无关的优化：**只为命中的条目付一次 `lstat`**。`readdir` 自带名字与类型，
  大小只有要展示的那几条才有意义——原来十万条目录要打十万次 `stat` 只为显示一个 size。
- 媒体库是同一套思路的**第二张表**（`media_snapshots`，条目多带 `size` / `mtime`），
  见 6.5。

### 4.8 系统返回键与浮层层级（v4.4.4）

编辑器、灯箱、预览面板、确认弹窗都不在路由里，此前按 Android 物理返回 / 浏览器后退 /
移动端边缘手势 = **直接离开当前页面**：有未保存修改也只是静默丢弃，用户可能只想关掉
一个大图或一个编辑器，却把整个目录位置一起退掉了。Esc 早有分层关闭（`closeTopLayer`），
系统返回却没有对应物，两条入口的行为必须对齐。

实现（`web/src/composables/useBackClose.ts`）：

- **一层浮层 = 一条历史记录**。浮层打开时压一条**同 URL** 的哨兵记录
  （`history.pushState`，state 里打 `__asmodayBack` 标记，同时保留 vue-router 的
  `position` / `scroll` 字段），不随层数增长——多层并存也只有一条。
- **popstate 先关最上层**：收到返回后关掉 `layers` 栈顶，若还有层开着就重新支起哨兵，
  逐层退出；全部关完才把返回让给路由。
- **UI 自己关掉时退哨兵**：若哨兵仍停在当前历史位置就 `history.back()` 把它消费掉，
  保证历史深度始终等于「用户感知的层数」，不留按了没反应的空步。
- **取消要重新武装**：`close()` 可能被用户取消（「有未保存的修改，确定关闭？」点取消），
  这时浮层仍开着，必须等一轮响应式更新后重新支起哨兵，否则下一次返回就漏到路由层。
- **不改 URL**：文件管理把目录同步进 URL（4.1 / 3.2.1），给浮层染色会污染深链接与刷新语义。

接入点：文件管理的编辑器 / 预览 / 全部弹窗（`closeOverlayForBack`，**编辑器排在弹窗之前**——
返回键的意图是退出编辑，而 Esc 在 CodeMirror 里有补全等自身用途，不能顺手关编辑器）、
全局灯箱、相册详情与视频全屏、移动端侧边栏抽屉与账号菜单。

另外两道兜底：`onBeforeRouteLeave` 拦「有未保存修改时点侧边栏 / 面包屑离开」，
`beforeunload` 拦刷新 / 关标签页（现代浏览器只认有无未保存编辑，不展示自定义文案）。

v4.4.5 起，这层关闭确认从原生 `confirm` 换成站内三选一弹窗（取消 / 保存更改 / 放弃修改，
见 4.2）。它是浮层栈之上的一层：Esc 与系统返回都按「取消」处理，关掉弹窗后编辑器仍在，
哨兵照旧重新武装——不会出现「按返回等于连编辑器一起关掉」的意外。

## 5. 终端

### 5.1 Shell 探测

- 禁止前端传 `~`。`dirs::home_dir()` 获取主目录；前端合法挂载路径则设为 cwd。
- 优先级：`[terminal].shell` > `$SHELL` > 平台回退。Termux：`$PREFIX/bin/zsh` → `$PREFIX/bin/bash` → `/system/bin/sh`（严禁硬编码 `/bin/bash`）。Linux：`/bin/zsh` → `/bin/bash` → `/bin/sh`。macOS：`/bin/zsh` → `/bin/bash`。Windows：`pwsh.exe` → `powershell.exe` → `cmd.exe`。
- `[terminal].args` 配置则完全覆盖。未配置时强制追加交互/登录参数：Linux/macOS `-l` 或 `-i`；Windows PowerShell `-NoExit`。严禁裸 Shell 名。
- 继承 `std::env::vars()`。`CommandBuilder` 临时注入 `TERM=xterm-256color`、`COLORTERM=truecolor`。Windows 优先发送 `chcp 65001`。

### 5.2 PTY 与尺寸

- 尺寸钳制：列 `max(20, min(val, 500))`，行 `max(5, min(val, 200))`，严禁 0 或负数。
  行下限必须是 5 而不是 20：手机横屏分屏、桌面窄侧栏真的会只剩五六行，按 20 夹会把 PTY 撑到比画布还高（表现为光标跑到可视区外）。列下限 20 是 80 列宽度的四分之一，再窄 TUI 也没法用。
- 单用户并发上限默认 10（`[terminal].max_sessions`）。超限拒绝时前端提供“查看活动会话列表”和“强制关闭”入口。
- 断线 PTY 延迟 3 分钟销毁（`[terminal].idle_kill_seconds`）。环形缓冲 1MB，超出丢最旧。

### 5.3 Windows ConPTY 死锁缓解（强制）

- `openpty()` 后立即向输入管道写入 `ESC[1;1R`（仅 `#[cfg(windows)]`）。
- 拆除顺序：drop writer → drain reader（500ms）→ 后台线程 drop master（`recv_timeout` 2s）。
- `openpty` 加 5 秒超时。

### 5.4 前端渲染

- xterm.js 渲染区强制深色，不跟随全局浅色主题。标准 16 色 ANSI（VS Code 暗色系），`background: '#1e1e1e'`, `red: '#cd3131'`, `green: '#0dbc79'`, `blue: '#2472c8'`, `brightGreen: '#23d18b'` 等。
- `fontFamily: '"JetBrainsMono Nerd Font", monospace'`。
- `attachCustomKeyEventHandler` 拦截 `Tab`，发送 `\t` 并 `return false`。
- `nextTick` 后 `fitAddon.fit()`；`ResizeObserver` 监听容器；移动端监听 `window.visualViewport` 的 `resize` 重新 `fit()`。
- 外壳卡片跟随全局主题，渲染区内层 `padding: 8px 12px`。禁止直接贴边铺满视口。

#### 5.4.1 移动端触屏（v4.4.3）

- **触屏滚动自己换算**：xterm 6 把滚动交给内部虚拟滚动条（`SmoothScrollableElement`），只认滚轮事件，触摸拖动没有任何路径能驱动它。画布上挂 `touchstart/touchmove/touchend`（`touchmove` 必须 `passive: false`），按 `单行像素 = .xterm-screen 高度 / rows` 把位移折成行数：
  - 普通缓冲区 → `term.scrollLines()`（公开 API，ydisp 与滚动条同步）；
  - 备用缓冲区（vim / htop）→ 合成 `WheelEvent` 丢给 `term.element`，由 xterm 自己决定发方向键还是走鼠标上报。
  - 手指离开后按最后的速度做指数衰减惯性（`FRICTION = 0.94`，每帧按实际 `dt` 折算）。
  - `touch-action: none`（仅 `pointer: coarse`）：不声明的话浏览器先自己滚一段，`touchmove` 就再也拦不住了。
- **快捷键条在文档流里**：曾是 `absolute bottom-0`，而 `section` 没有定位祖先 → 实际是相对初始包含块（视口）定位，软键盘一弹出就被压在下面。现在是 `flex` 子项（`shrink-0`，高 72 + `safe-area-inset-bottom`），终端区 `flex-1` 自动让位。
- **软键盘遮挡 = `padding-bottom`**：键盘只缩 `visualViewport`（布局视口与 `100dvh` 都不变），所以 `useKeyboardInset` 持续测「section 底边 − 可视区下沿」，把差值补成 `padding-bottom`（`>100px` 才算键盘，挡掉 Safari 地址栏收放的抖动；双指缩放直接归零）。键盘收起后归零。
- **按键不抢焦点**：触屏点 `<button>` 会把焦点从 xterm 的隐藏 textarea 抢走，输入法当场收起。快捷键条全部改成 `@pointerdown.prevent`（动作也在 pointerdown 里执行，不等 click），按键前若焦点在终端内则按完补一次 `focus({preventScroll: true})` —— `preventScroll` 是因为 textarea 被 xterm 放在 `left: -9999em`，不拦的话浏览器会为「露出焦点」把整页横向滚一下。
- **不自动聚焦**：`pointer: coarse` 下不主动 `term.focus()`。iOS 对脚本 focus 不弹键盘、Android 会弹，一进页面就顶掉半屏且行为随平台而异，统一交给用户点。

### 5.5 历史与容错

- 严禁写入系统 `AppData` 或 `~/.bash_history`。强制将 `PSReadLine` 历史路径指向 `data/terminal_history/`。前端不弹权限 Toast。
- Profile 错误原样透传，不中断环境变量注入。提供“纯净模式（NoProfile）”逃生舱：Windows `-NoProfile`，Linux `--noprofile --norc`。
- PTY 探活超时或异常退出，前端提示并提供“以纯净模式重启”。

## 6. 媒体画廊

### 6.1 缩略图

- 信号量并发上限按 CPU 数自适应（2–8），拿不到许可 1.5 秒内回占位图，不排队；同一源文件另有
  per-key 异步锁，320 / 960 两个宽度同时请求只解码一次。
- `mtime` 距今 <1 分钟且体积 ≥4MiB 时跳过缩略图。
- 优先 WebP，降级 JPEG。FFmpeg 路径 `Arc<RwLock>` 热重载与探活；未配置返回 404 占位图。
- **缓存布局（v4.4.9，FileBrowser master 的做法）**：`<cache>/<sha1(path)[..2]>/<sha1(path)>/<指纹>-<width>-<codec>`，
  指纹 = `v<版本>-<长度十六进制>-<mtime 秒十六进制>`。四条硬约束：
  - **指纹进文件名，不再有 stamp 文件**：命中与否只看文件在不在，不存在「戳写了图没写」的窗口；
  - 改图 = 指纹变 = 新文件，同目录里旧指纹的文件由 `prune_stale` 写后顺手删掉（不同步留孤儿）；
  - 缓存名**不带图片扩展名**（`v3-1b956-6ae446c8-320-jpg`）：即使缓存目录被误暴露，
    媒体扫描 / 列表也不会把它当图片再缩略图一遍；
  - 落盘走「同目录临时文件（`.tmp-*`）+ rename」原子替换，且**不在响应链路上**——
    字节已经在手上了就先回客户端，写盘交给后台线程（FileBrowser 的 `createPreview` 同思路）。
- **浏览器侧**：缩略图 URL 带 `r=<渲染版本>` + `v=<源文件 mtime>`。`v` 与当前 mtime 一致时
  响应 `Cache-Control: private, max-age=31536000, immutable`（URL 变即内容变，浏览器不必回头问）；
  不一致（老链接、文件刚改）回 `private, no-cache` + `ETag`，每次校验但命中只花一次 304。
  **这条是「改了缩略图规则浏览器还抱着旧图」的唯一解**——只改服务端缓存键没用，URL 不变浏览器永远不会重新请求。
- 删除 / 改名 / 移动源文件时按路径 `purge` 整个缓存单元并删除对应 ThumbHash 行
  （FileBrowser 的 `delThumbs` 同语义），不留只能等 LRU 的孤儿。
- 淘汰单位是「一个源文件的缓存单元目录」：按过期天数（`thumb_cache_max_age_days`）与 LRU 容量
  （`thumb_cache_max_size_mb`）整目录删除；升级时旧版扁平布局（`<hash>-320.webp` / `<sha>.th`）一次性清空。
- ThumbHash（20–30 字节字符串）存入 SQLite `thumb_hashes` 表，键为路径 sha1（**稳定，不随编辑次数增长**），
  列表 API 从数据库读取。

- 相册：卡片网格展示直接含图片的目录（含挂载根），剔除无图文件夹。数量只数第一层，点进去也只列第一层。封面取该文件夹最新图片缩略图。

### 6.3 灯箱

- 渐进式加载：先展示已有缩略图占位，后台加载原图平滑替换。严禁黑屏。
  - 占位层 `object-scale-down`（**只缩不放**）：`object-contain` 会把小图放大成比原图大一圈的模糊块，
    原图淡入后撤下时露出边框；容器用 `bg-black/90 backdrop-blur-xl`（v4.4.7，Telegram 式半透明 +
    背景模糊，隐约透出下面页面），进场一次性 180ms 淡入——**不能包 `<Transition>`**：
    关闭时 items 已被清空，离场帧里 `item` 是 null，模板满屏的 `item.name` 会炸。
  - 缩略图生成的 `render_thumbnail` 也按原图长边封顶，`image.thumbnail` 不再把小图放大。
  - 原图 `@load` 后占位层 `opacity-0` 淡出（300 ms 与原图淡入同步），最终画面只剩原图本身。
  - **原图 `@load` 必须守卫 `event.target === imgEl`（v4.4.7）**：`:key` 换了元素，快速翻页时
    旧图的 load 会晚到——不守卫就把 `ready` 写成新 path，还没解码完的新原图被提前淡入，
    画面闪一帧空白。
- 静默预加载上一张/下一张：**原图和 960 打底图都要预**（v4.4.7）——打底 URL（960）与网格的
  320/480 不同源，只预原图的话翻页瞬间连打底都没就绪，整屏黑一下。图片 `z-index` 高于遮罩。
  换条目时 `zoom.reset(true)` 瞬时复位（跳过 220ms 回中动画），旧画面不趁着换图动一下。
- **媒体是主角，UI 是浮层（v4.4.6）**：交互骨架对齐 Telegram，工程细节参考 FileBrowser
  `views/files/Preview.vue`。舞台 `absolute inset-0` 铺满视口，顶栏与缩略图条 `absolute`
  浮在画面上（带渐变压暗），媒体不再被 48px 顶栏 + 76px 底条挤掉一百多像素。
  闲置 2.6 秒自动隐去，鼠标移动 / 滚轮 / 任意按键 / 触摸立刻唤回；指针停在顶栏或底条上、
  信息层或右键菜单打开时不隐（`holding`），离开时重新计时。
- **顶栏**：左 `×` → 文件名 → 计数 chip → 下载 / 新窗打开 / 分享 / 信息。触屏没有右键菜单，
  这些动作必须上工具栏；右键菜单保留（复制直链只在菜单里）。
- **图片缩放（`composables/useImageZoom.ts`）**：滚轮以光标为锚点缩放（1.12 步进，1–4 倍，
  放大后光标下那一点不动）、放大后拖动平移（按媒体布局尺寸夹取）、双击 1↔2、双指捏合；
  未放大时左右滑切图、下滑关闭（阈值 60 / 110 px，未到阈值回弹）。
  变换写成 `translate3d(x, y, 0) scale(s)`，translate 在缩放前作用，所以 x/y 是屏幕像素，
  夹取范围是 `尺寸 × (s - 1) / 2`；锚点换算用「内容坐标不变」推导，
  **不能拿 `getBoundingClientRect()` 当参照**——那个矩形本身带着位移，越缩放越偏。
- **缩放胶囊（v4.4.7）**：图片模式常驻底部居中（未放大 100% 淡显、放大后变亮），点一下复位，
  不随 chrome 隐藏。stage 内控件（左右箭头、缩放胶囊）在 `onTap` 里按
  `closest('button, a')` 豁免——它们的 `pointerup` 先于自身 `click` 冒泡到 stage，
  不豁免就会被「点黑边关闭」当场关掉灯箱，按钮永远收不到 click（v4.4.6 上下页失效的真凶）。
- **双击与长按（v4.4.8）**：`dblclick` 同样要按 `closest('button, a')` 豁免——连点两次
  「下一张」会在按钮上凑出一次 dblclick，冒泡到 stage 就把刚翻过去的那张放大到 200%。
  键盘 auto-repeat 分两类：离散动作（Esc / 空格 / k / 0 / ±）**只认首次按下**（按住空格会在
  播放与暂停之间狂闪、按住 + 会顶到上限），翻页允许连发但节流到 ~110ms 一次（原速 30ms
  翻页时解码跟不上，观感是一串跳帧）。
- **缩略图缓存格式版本（v4.4.9）**：版本号同时进缓存文件名（`v3-…`）和前端 URL（`r=v3`）。
  v4.4.2 之前 `render_thumbnail` 会把小于请求宽度的图放大（300×200 生成成 960 宽），灯箱用
  960 缩略图打底时画面先按放大版铺开、原图一到又缩回去——就是「打开预览先大后小」。
  两条一起改才治本：服务端换名让旧图不再命中，前端换 URL 让浏览器不再拿自己的旧副本
  （响应头以前是 `max-age=86400`，URL 不变就一天不会重新请求）。视频海报用自己的版本号
  `p1`，不跟着图片升版，避免几千个视频白跑一遍 FFmpeg。
- **打底与原图共用一套布局（v4.4.9）**：两层都是 `size-full object-contain`——几何只由
  宽高比决定，缩略图和原图宽高比相同 ⇒ 渲染矩形完全重合，交叉淡入只变清晰度、不变尺寸。
  旧实现打底用 `object-scale-down`（按缩略图自身像素渲染）、原图用 `max-w/h-full + contain`
  （按可用框渲染），两套模型像素尺寸一不等就必然跳。「先大后小」是这两条原因叠加的结果。
  同时去掉实时 `backdrop-blur`：它每帧重算整个视口背后的内容，1080p 翻页明显掉帧，
  观感上就是「糊一下／闪一下」，比不糊更糟。
- **视频铺满**：`MediaPlayer` 新增 `fill`（容器不再按比例收窄，`object-contain` 吃掉黑边）与
  `showClose`（灯箱自己有工具栏，不再出现第二个 ✕）。视频不给缩略图条——Video.js 控制条就在
  视口底部，两条会叠在一起。`←/→` 在视频上做 ±5 秒快进而不是切条目
  （FileBrowser 特意做了这个放行），空格 / `k` 播放暂停。
- 信息层就地展开（尺寸 / 时长 / 体积 / 修改时间），`LightboxItem` 的 `size` / `modified` 由调用方带进来；
  图片尺寸取 `naturalWidth/Height`，视频取 `loadedmetadata`。

### 6.4 影视与音乐

- 影视库固定 16:9，无图占位。动态引入 Video.js 10。`<video>` `object-fit: contain`，监听 `loadedmetadata` 调整容器比例。关闭时 `pause(); src=''; load();`。
- **影视库与图片库同构（v4.4.8）**：此前影视库是在前端拿「已加载那几页里每个视频的 `folder`」
  现场分区，而图片库走 `/api/media/albums?kind=image`（后端统一算「直接含图片的目录」、count 只数
  第一层）——同一棵树，图片是一张卡片，视频却按完整相对路径各占一区，深目录还会把同一部剧拆成
  好几段。现在影视库同样走 `albums?kind=video` 出文件夹卡片（封面取册内最新视频首帧），点进去用
  `browse?kind=video&depth=0` 列本层影片；卡片抽成 `components/VideoCard.vue`，两层渲染共用一份模板。
- 音乐库解析音频标签（ID3v2 / FLAC / MP4 / Ogg，`lofty`）与 LRC。底部全局悬浮播放条（不播放不显示）。默认音量 35%，写 `localStorage`。
- **播放条版式（v4.4.8）**：桌面是居中浮动条（宽 70%，min 660 / max 1180，圆角 + 阴影），
  三栏布局——左曲目、中控件、右工具；播放键必须落在条的几何中心，进度条在控件正下方。
  移动端不做浮动：铺满底部单行（封面 / 曲目 / 上一首 / 播放 / 下一首 / 关闭），进度用顶端
  2px 线表示，不额外占高度。歌词面板与播放列表向上让出浮动条的高度。

### 6.5 索引与分页（v4.2.5）

- 媒体列表与相册清单都走**游标分页**：`limit` 默认 300、上限 1000，`cursor` 记的是上一页最后一条的
  `(mtime, 展示路径)`。与文件管理同一套 keyset 口径——排序稳定（mtime 降序 + 路径升序兜底），
  扫描期间新增/删除文件也不会让下一页重复或漏项。
- **没有扫描上限**：原来的 `SCAN_LIMIT`（媒体 4000 / 相册 20000）与 `truncated` 字段一并删除，
  多大的库都能翻到最后一条；响应里的 `total` 与 `counts`（image / video / audio）是真实总数，
  前端「已加载 N / 共 M」直接用它们，不需要等全部翻完。
- 扫描分两段：第一段只 `readdir` + 分类 + 一次 `metadata`（`RawMedia`）；第二段只对**当前页**做
  「贵」的事——音频 ID3 解析、视频外挂字幕探测、图片 ThumbHash 批量查询。原来这些对目录里每一条
  都执行，几千首歌的库首屏要开几千个文件句柄。
- 前端触底续接：媒体库是普通滚动容器，列表末尾放一个 1px sentinel + `IntersectionObserver`
  （`rootMargin: 800px` 预取一屏），按当前视图决定续哪条流（媒体列表 / 相册卡片 / 册内图片），
  追加时按路径去重。**文件管理与搜索结果不走哨兵**：那两处是虚拟列表，哨兵在容器外永远可见，
  判定必须落在组件自己的滚动事件上（见 4.6 最后一条）。
- **目录快照缓存（v4.3.1）**：`media_snapshots` 表，一个目录一行，条目带
  `name / kind / size / mtime`（约 32 字节/条）。命中判定与搜索同一套——目录 mtime 对得上就用，
  且只收留「mtime 至少 2 秒前」的目录。命中时**零 `readdir`、零逐条 `stat`**（只剩目录自己那一次，
  用来取 stamp），翻页不再从根目录重走整棵树。
- 能缓存 `size` / `mtime` 的前提与搜索是同一个：目录内容的**名字集合**只在创建 / 删除 / 改名时变，
  这三件事都会推进父目录 mtime。
- **唯一漏网的是「原地覆盖」**：同名替换、编辑器保存这类写不改变名字集合，目录 mtime 不动，
  缓存里就还是旧的体积与时间（排序会停在老位置）。两条补充：应用自己的覆盖写
  （`/api/files/upload` 同名覆盖、`/api/files/write`）落盘后**主动 `forget` 该目录**；
  其余情况（外部程序原地改写同一文件）由前端「重新扫描」按钮带 `?refresh=1` 强制穿透 ——
  穿透之后照样写回，下一次又走缓存。用「写 .tmp 再 rename」的外部工具会推进目录 mtime，自动失效。
  这是「一次 `stat`/目录」换「零次 `stat`/条目」的必然取舍，宁可写清楚也不假装没有。
- 结果集与整树重扫**完全一致**：单测与基准都断言冷/热的 `total`、`counts`、`scanned` 三者相等；
  `scanned` 仍按「读到的目录项数」计，命中缓存时也是同一个数（快照里存的是完整条目，不是过滤后的）。
- `refresh` 是真的穿透而不是「清库」：所有目录照常重扫并写回，多页连续翻页时前缀页也会被刷新，
  不会出现「第一页新、第二页旧」。
- 查询串里的布尔值统一走 `api::boolish`（`1/0`、`true/false`、`yes/no`、`on/off` 都认）：
  `Option<bool>` 直接反序列化遇到 `?refresh=1` 会让**整条查询串**解析失败，报一个跟参数无关的 400。

## 7. 配置管理

### 7.1 TOML 编辑

- 可视化表单使用 `toml_edit` AST 仅替换目标 Value，保留注释、空行、顺序。源码模式直接写盘，仅语法校验，禁止格式化或 AST 重写。
- 表数组为空时整段省略；`trusted_ips = []` 必须原样写出；纯量数组摊成单行。
- 与默认值相同的标量不写盘（如 `follow_symlinks = true`），否则每次保存都会凭空多一行；
  改成非默认值时必须落盘，两次保存结果逐字一致（幂等）。

### 7.2 热重载

- 直接用 `notify::recommended_watcher` + 手写 500ms 防抖（`recv_timeout`），不引 `notify-debouncer-full`。`Create` 与 `Modify` 视为内容变更（含 Windows `Modify(Any)`），`Metadata`/`Other` 忽略。
- **macOS 风险**：`notify-debouncer-full` 在 macOS FSEvents 下有丢弃 `Remove` 事件的已知问题。本项目从一开始就走「裸 `notify` + 手写防抖」，不依赖 debouncer，因此该风险不适用；自写防抖的窗口期仍是 500ms，重命名/原子替换会被合并成一次重载。
- 写回前比对内容，不变不写盘；必要时 `AtomicBool` 挂起监听器防死循环。相同日志 1 秒内只输出一次。

### 7.3 设置页

- 分 Tab（通用、媒体、安全、高级）。FFmpeg 优先级：UI > `ASMODAY_FFMPEG_PATH` > `PATH`。提供状态检测与 `libwebp` 探测。
- 恢复默认分区块重置，绝不碰 SQLite；`[[services]]` 等高级配置不被普通表单覆盖。提供清理缩略图缓存、临时文件、过期分享 tombstone 按钮。
- 危险配置自检：`trust_proxy_headers=true` 且 `trusted_ips` 空 → WARN；`proxy_trust.enabled=true` 且白名单空 → ERROR 拒绝启用；`ASMODAY_RESET_PASSWORD` 常驻但未用 `--reset-password` → WARN；`skip_2fa=true` → WARN；`0.0.0.0` 且未启用 SSL → WARN。

## 9. 日志

- 全部后端日志、WARN、ERROR **纯英文**。用户路径/文件名原样输出。Windows 启动 `SetConsoleOutputCP(65001)`。
- 文件：`data/logs/`，单文件 10MiB × 5 备份，`errors.log` 独立档同样轮转。自研 `src/core/logging.rs`，不依赖 `tracing-appender`。
- 控制台默认 `INFO`，本地时区，TTY 级别着色。文件默认 `DEBUG`，RFC 3339 UTC，无颜色。
- API 访问日志独立 `api_level`（默认 `info`，`off` 关闭）。记录方法、路径、状态码、耗时、来源 IP。**保留非敏感查询参数（`path`、`action`、`download`），敏感参数（`password`、`token`、`share_secret`）值替换为 `[REDACTED]`**。静态资源不记。
- DEBUG 才附带 `文件名:行号`；INFO 及以上不包含。`format = "text" | "json"`，默认 `text`。
- 启动 INFO：版本、PID、配置路径、数据目录、WAL/迁移状态、监听地址、前端 Git Commit / Build Timestamp、启动耗时。退出 INFO：`Received signal, shutting down gracefully...` / `Shutdown complete.`。
- 监听 `0.0.0.0` 且未启用 SSL 输出 WARN。

## 11. 分享

- `allow_download=false` 不是 DRM。唯一目的：隐藏下载入口、防误触、限制响应头不触发批量下载。
- 图片/视频/音频/PDF：允许 `raw` 流式，强制 `Content-Disposition: inline`。前端不显示下载按钮，禁用图片右键，播放器自定义控制条隐藏原生下载。
- 文本/代码/Markdown/CSV：允许 API 返回内容渲染，隐藏下载与复制按钮。
- 不支持预览的文件：单文件分享 `allow_download=false` 创建时返回 `E_UNSUPPORTED_PREVIEW`；文件夹分享列表返回名称大小但置灰，点击提示不支持预览。
- `allow_download=false` 时任何 `raw?download=1` 返回 `E_FORBIDDEN`。后端不生成 `attachment` 分享链接。
- tombstone：启动时清理 `deleted_at` 超 30 天行；访问命中超 30 天 tombstone 当场物理删除并 404。不引入常驻定时任务。

## 12. WebDAV

- **协议由 `dav-server` 实现，本项目只做「认证 + 挂载点路由 + 安全边界」**（v4.2.0 起）。
  自研那版客户端实测加不上：`/dav`、`/dav/` 虚拟根 404，`PROPFIND` 缺
  `getetag` / `creationdate` / `supportedlock`，目录 href 没有尾斜杠——这些恰好是
  客户端判断「能不能用」的判据。协议边角（多段 Range、`If` 头、ETag 条件请求、
  `PROPPATCH` 207、autoindex、目录补斜杠重定向）全部交给社区实现。
- 方法：`OPTIONS`、`PROPFIND`、`GET`、`HEAD`、`PUT`、`DELETE`、`MKCOL`、`MOVE`、`COPY`、`LOCK`、`UNLOCK`。
- 锁是真锁：`dav-server` 的 `MemLs`（内存表 + 超时），写操作校验 `If` 头，未持锁写返回 423。
- **URL 形态**：`/dav/<mount_id>/<path>`；`/dav` 与 `/dav/` 是虚拟根，
  `PROPFIND` 列出全部挂载点（令牌限定挂载点时只列它可见的），`GET` 回可挂载目录的落地页。
  客户端只需填 `http://host:port/dav/`，不必先知道 `mount_id`。
- 路由用 `nest("/dav")` + 显式 `route("/dav/")`：axum 的 `{*rest}` 通配段匹配不到
  「空剩余路径」，`/dav/` 会直接落进静态回落——这正是「客户端里加不上」的直接原因。
- Basic Auth：优先「用户名 = `token_name`（`UNIQUE`），密码 = `asm_` Token 明文，校验哈希与过期」；
  失败后回退管理员账号 + 登录密码（全量权限，待改密 / 开 2FA 的账号拒绝，见 3.4）。
  只读令牌与只读挂载点：写方法在入口直接 403，且 `OPTIONS` 的 `Allow` 只列读方法
  （`DavMethodSet::WEBDAV_RO`），客户端据此判定「只读共享」。
- 安全边界（`api/webdav.rs` 的 `guard_path` / `guard_destination`）：
  - 逐段拒绝 `.` / `..`；已存在路径 canonicalize 后必须在挂载点内；
    软链接逃逸按 `[system].follow_symlinks` 处理（=false 时 403，=true 时与文件管理口径一致地放行）；
  - `MOVE`/`COPY` 的 `Destination` 头过同一道闸（否则可以用指向挂载点外的软链接写文件）；
  - `.asmoday-part.*` 与系统垃圾（`.DS_Store` / `._*` / `Thumbs.db` 等）：读侧 404、写侧 403，
    由 `CleanFs`（`api/dav_fs.rs`）在 `LocalFs` 外面统一拦——只过滤读不拦写，
    客户端照样能创建垃圾并触发 macOS/Windows 双端同步死循环；
  - 挂载点根不可 DELETE/MOVE。
- Windows 适配（实测踩过）：`MKCOL` 带尾斜杠 dav-server 会 400，转交前去掉；
  重复 `MKCOL` 的 `ERROR_ALREADY_EXISTS`（Win32 183）不在 dav-server 的 unix errno
  映射表里会变 500，`CleanFs` 先探存在性统一回 405。
- Basic Auth 失败计入独立防爆破池（`token_name + IP`），与登录 / 分享互相隔离。
- 子路径部署：`strip_prefix` 与请求 URI 都带 `[server.proxy].base_url` 前缀，
  href 与 `Destination` 才能对上；**不能用 `OriginalUri`**——它由最外层 Router 插入，
  带 `/asmoday`，会令所有请求被误判为虚拟根。

## 13. 数据库 Schema

```sql
PRAGMA journal_mode=WAL;
PRAGMA busy_timeout=5000;

CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    totp_secret TEXT,
    is_totp_enabled BOOLEAN NOT NULL DEFAULT 0,
    totp_recovery_codes TEXT,
    must_change_password BOOLEAN NOT NULL DEFAULT 0,
    created_at DATETIME

-- 会话表由 core/auth.rs 的 SCHEMA 建（自研，不用 tower-sessions）。
-- 存量库补列在迁移 v1 的钩子里做（`ALTER TABLE ADD COLUMN`，先查列再执行）；新增列只追加 `M::up`。

CREATE TABLE access_tokens (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,
    token_name TEXT NOT NULL UNIQUE,
    token_hash TEXT UNIQUE NOT NULL,
    is_readonly BOOLEAN NOT NULL DEFAULT 1,
    expires_at DATETIME,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE TABLE shares (
    token TEXT PRIMARY KEY,
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    is_folder BOOLEAN NOT NULL,
    password_hash TEXT,
    allow_download BOOLEAN NOT NULL DEFAULT 1,
    expires_at INTEGER,
    created_at INTEGER NOT NULL,
    deleted_at INTEGER
);
CREATE INDEX idx_shares_deleted_at ON shares(deleted_at);

CREATE TABLE favorites (
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    created_at INTEGER NOT NULL,
    PRIMARY KEY (mount_id, file_path)
);

CREATE TABLE play_history (
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    last_played_at INTEGER NOT NULL,
    progress INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (mount_id, file_path)
);

CREATE TABLE thumb_metadata (
    mount_id TEXT NOT NULL,
    file_path TEXT NOT NULL,
    mtime INTEGER NOT NULL,
    size INTEGER NOT NULL,
    thumb_hash TEXT,
    cache_key TEXT NOT NULL UNIQUE,
    updated_at INTEGER NOT NULL,
    PRIMARY KEY (mount_id, file_path)
);

-- 目录快照缓存（4.7）。纯加速用的旁路数据，清空不影响任何功能，故不设外键。
-- entries 是自定义二进制：[版本 u8][条数 u32]{kind u8, 名长 u16, 名字字节}…
CREATE TABLE dir_snapshots (
    path TEXT PRIMARY KEY,          -- normalize_display 后的绝对路径
    stamp INTEGER NOT NULL,         -- 目录 mtime（Unix 纳秒），对不上就是 miss
    entries BLOB NOT NULL,
    entry_count INTEGER NOT NULL,
    used_at INTEGER NOT NULL        -- LRU 裁剪依据
);
CREATE INDEX idx_dir_snapshots_used_at ON dir_snapshots(used_at);

-- 媒体库快照（6.5）。与 dir_snapshots 同构、不同格式（条目多带 size / mtime），
-- 刻意分开两张表：两种 blob 互相喂给对方都会解码失败，混存只会更难排查
CREATE TABLE media_snapshots (
    path TEXT PRIMARY KEY,
    stamp INTEGER NOT NULL,
    entries BLOB NOT NULL,
    entry_count INTEGER NOT NULL,
    used_at INTEGER NOT NULL
);
CREATE INDEX idx_media_snapshots_used_at ON media_snapshots(used_at);
```

- 迁移：`rusqlite_migration` 管理，`PRAGMA user_version` 记录进度，每步只跑一次，失败拒绝启动并提示备份。
  - v1 = 基线（全部 `CREATE TABLE IF NOT EXISTS`）+ 缺列补齐的钩子：新库与存量库（user_version 同为 0）走同一段；
  - v2 = `favorites` / `play_history` 主键升级为 `(mount_id, file_path)`；
  - v3 = 目录快照缓存表 `dir_snapshots`（4.7）；
  - v4 = 媒体库快照表 `media_snapshots`（6.5）；
  - 以后加列加表**只往后追加** `M::up(...)`，不要回头改 v1——已升级的库不会重跑它；
  - 钩子已运行在事务内，**不要**在迁移 SQL 里写 `BEGIN`/`COMMIT`（嵌套事务直接报错）。
- Unix 下 `data/asmoday.db` 权限 0600。备份提示使用 `sqlite3 .backup` 或先 checkpoint。

- 遮罩层打开锁定 `body` 滚动。底部悬浮条 `env(safe-area-inset-bottom)`。移动端软键盘监听 `visualViewport.resize` 重新 `fit()`。
- 文件列表用 `grid`，图标/缩略图 `w-16 h-16` 或 `aspect-square`。排序菜单当前项打勾并显示在工具栏。滚动到底自动加载下一页；切换排序清空列表重新拉取。
- 批量操作结果统一弹窗。失败项优先展示 `error_code` 翻译；`E_BUSY` / `E_CONFLICT` 禁止简单“重试”，提供“忽略并继续”或外部动作指引。前端并发上传池默认 3。
- 移动端长按阈值 500ms，滑动超 10px 取消；触发后忽略 `click`；多选时容器底部加 padding。
- 禁止原生弹窗。冲突、删除确认用封装 Modal。
- 终端外壳跟随主题，渲染区深色，内层 `padding: 8px 12px`，禁止直接贴边铺满视口。
- 源码编辑器 100% 撑满 Flex 容器，外层 `overflow: hidden`，滚动条仅编辑器内部产生。切换可视化/源码 `nextTick` 后通知 CodeMirror 重算尺寸。工具栏吸附顶部，默认开启水平滚动。
