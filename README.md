Asmoday is a lightweight self-hosted panel that bundles **file management**, a **web terminal**, **photo / video / music libraries**, a **download engine**, **share links** and **WebDAV** into a single executable. The backend is Rust (axum), the frontend is Vue 3, and all frontend assets are embedded into the binary at build time — at runtime it only needs one SQLite file.

It is built for the "own machine + browser" setup: a NAS, a Raspberry Pi, a mini PC, an old laptop, or the Windows desktop you already use. No Node runtime, no database server, no external CDN.

## Features

- 📂 **File management** — multiple mounts (individually read-only), grid and list views, drag-and-drop upload (large files are chunked with resumable transfers), batch copy/move/delete, ZIP download for a whole folder or a multi-selection, recursive search.
- ✏️ **Built-in editor** — CodeMirror 6 with syntax highlighting, Markdown preview, read-only CSV and PDF previews; line endings (LF / CRLF) and encoding are written back unchanged.
- 🖥️ **Web terminal** — a real PTY via `portable-pty`, multiple tabs, sessions that survive disconnects, an on-screen key bar on phones, and "Open terminal here" from the file manager.
- 🖼️ **Photo library** — Immich-style day timeline (justified rows that keep every aspect ratio, year scrubber) plus a folder wall, ThumbHash placeholders, slideshow and favorites.
- 🎬 **Cinema library** — the same day timeline for all videos, folder cards, resume from the last position, external subtitles (`.srt` converted to WebVTT on the fly, or `.vtt`), Video.js with a native-player switch.
- 🎵 **Music library** — ID3v2 / FLAC / MP4 / Ogg tags and LRC lyrics, a persistent bottom player bar, list loop / single loop / shuffle.
- 🔗 **Share links** — unguessable links for files or folders, with password, expiry date, download toggle and Referer allowlist.
- ⬇️ **Download engine** — its own page beside Files and the media library: add links, magnets or `.torrent` files, pause / resume, and pick save directories from your mount points. Settings are an in-page view rather than a dialog, so leaving with unsaved edits asks first, and the system back key returns to the task list instead of jumping out of the page. The RPC secret is generated by the server and stored in the database — viewed and rotated right there, never hand-edited. Save directories and BT trackers apply immediately; engine parameters need a restart and the page says so.
- 🔌 **aria2-compatible RPC** — `/jsonrpc`, point AriaNg or Aria2 Explorer at it with that secret: multi-connection HTTP with resume, and BitTorrent (magnet, `.torrent`, DHT, PEX, seeding). Cookies and referrers handed over by the browser extension reach every segment and every redirect hop. **No separate aria2 install.**
- 🗄️ **WebDAV** — the full method set with real locks, and token-only authentication (username = token name, password = the `asm_…` token), optionally scoped to one mount, read-only or expiring. Works with phone sync apps, Cyberduck, rclone and system file managers.
- 🔒 **Security** — Argon2id hashing, passwords limited to printable ASCII (8–128 chars, no spaces), TOTP two-step sign-in (a single field that becomes a 6-digit code box once 2FA is on, plus one-time recovery codes for a lost device), sliding sessions, three independent rate-limit pools (login / share / WebDAV), path traversal protection and hardened response headers.
- 🌗 **Interface** — Tailwind CSS v4 glass surfaces, dark and light themes, Chinese and English, responsive down to phones.
- 🧩 **Service hub** — `[[services]]` entries put other self-hosted apps on the home page through the built-in reverse proxy, with optional header injection.
- 🧭 **Ecosystem guide** — an offline page listing clients that are known to work here (Syncthing / PhotoSync / FolderSync, AriaNg, RaiDrive / Cyberduck / WinSCP, Caddy / Tailscale, PicGo / Typora / Obsidian), each linking to its official site.
- 🪶 **Lightweight** — one executable including the UI and the download engine, no runtime dependencies, happy to stay running.

## Quick start

### Download and run

Grab the archive for your platform from [Releases](https://github.com/Asmoday-lab/asmoday/releases):

| Platform | Artifact |
| --- | --- |
| Windows x64 | `asmoday-x86_64-pc-windows-msvc.zip` |
| Linux x64 | `asmoday-x86_64-unknown-linux-musl.tar.gz` |
| Linux arm64 | `asmoday-aarch64-unknown-linux-musl.tar.gz` |

```bash
# Linux / macOS
tar -xzf asmoday-*.tar.gz && chmod +x asmoday
./asmoday

# Windows: extract and double-click asmoday.exe, or run it from a shell
asmoday.exe
```

Open `http://127.0.0.1:4242`, sign in with the **one-time password printed in the console** (no username anywhere in the web UI), then set your real password in the prompt that appears. The banner also prints the address as a terminal hyperlink — Ctrl/⌘+click it in Windows Terminal, iTerm2 or the VS Code terminal; the legacy console you get by double-clicking the exe cannot open links — copy that address into your browser. With `host = "0.0.0.0"` the startup log also prints a second `network:` line with the LAN address other devices should use. Missed the password? As long as no real password has been set yet, restarting the process **issues a fresh one** (the old one stops working) and prints the banner again.

The first start writes `config.toml` and `data/` into the current directory. With no mount configured, the working directory is used as a fallback root; to manage other disks, add a mount under Settings → Advanced or edit the config:

```toml
[[system.mounts]]
path = "D:/Media"        # on Linux, e.g. /mnt/media; the same path cannot be mounted twice
readonly = false         # read-only mounts reject every write

[[system.mounts]]
name = "Backup"          # optional: defaults to the last path segment ("Media" here)
path = "E:/Media"
readonly = true
```

> macOS has no prebuilt package — build from source (see [Development](#development)).

### Build from source

Requires Rust 1.99+, Node.js 20+ and pnpm:

```bash
cd web && pnpm install && pnpm run build && cd ..
cargo build --release          # output: target/release/asmoday
```

### Docker

```bash
docker compose up -d --build     # config, database, thumbnail cache and downloads live in the asmoday-data volume
docker compose logs -f asmoday   # the first-run one-time password is printed here, once
```

Without compose:

```bash
docker build -t asmoday .
docker run -d --name asmoday \
  -p 4242:4242 -p 6881:6881 -p 6881:6881/udp \
  -v asmoday-data:/data \
  asmoday
```

The image ships `ASMODAY_HOST=auto`: it tries the IPv6 dual-stack socket first and falls back to `0.0.0.0` when the environment has no IPv6 (Docker's default bridge is IPv4-only). Do not hardcode `::` there -- the process cannot bind at all; `0.0.0.0` on the other hand loses IPv6 on a dual-stack host.

- Ports: `4242` web UI / API, `6881` BitTorrent TCP + UDP
- Volume: `/data` holds `config.toml`, `asmoday.db`, `thumbnails/` and `downloads/`
- Alpine runtime, static musl binary, non-root (uid 10001), healthcheck included
- The first build recompiles the whole dependency tree against musl (10+ minutes); later builds reuse the BuildKit cache
- Releases publish multi-arch images at `ghcr.io/<owner>/asmoday:<tag>` (amd64 + arm64)

### Run under systemd (Linux)

```ini
[Unit]
Description=Asmoday
After=network.target

[Service]
User=asmoday
WorkingDirectory=/opt/asmoday
ExecStart=/opt/asmoday/asmoday -c /opt/asmoday/config.toml -d /opt/asmoday/data
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

### Behind a reverse proxy (optional)

```caddyfile
asmoday.example.com {
    reverse_proxy 127.0.0.1:4242
}
```

When running behind HTTPS, set `[server].host` to `127.0.0.1` and enable `[server.proxy].trust_proxy_headers` with a `trusted_ips` list as needed. For a sub-path deployment (e.g. `https://example.com/asmoday`) set `base_url`. Asmoday does not implement ACME — use your own certificate or let Caddy / Nginx handle it.

## Configuration

Configuration is TOML. Resolution order: `-c` flag → `ASMODAY_CONFIG_PATH` → `config.toml` in the working directory; the data directory is `-d` flag → `ASMODAY_DATA_DIR` → `data/` in the working directory. The settings page offers a form view and a raw source view; saving keeps comments and existing ordering.

| Section | Purpose |
| --- | --- |
| `[server]` | Listen address and port, TLS, proxy compatibility, batch limits |
| `[auth]` | Local login switch, proxy trust (SSO) |
| `[system]` | Mounts (`[[system.mounts]]`), symlink policy |
| `[media]` | Thumbnail cache size and idle retention, FFmpeg path, upload size limit, upload chunk size |
| `[terminal]` | Custom shell and args, idle keep-alive, concurrent sessions |
| `[log]` | Console and file levels, access log, text or JSON output |
| `[[services]]` | External services on the home page and their proxy options |

```toml
[server]
host = "127.0.0.1"          # loopback by default; 0.0.0.0 / :: for LAN access
port = 4242

[media]
ffmpeg_path = ""            # empty = detect from PATH; used only for video first frames
thumb_cache_max_size_mb = 1024

[[system.mounts]]
name = "Media"
path = "/mnt/media"
readonly = false

[[services]]
id = "grafana"              # permanent URL: /proxy/grafana/ — pick a readable one
name = "Monitoring"
icon = "gear"               # pick it in the UI; empty or unknown falls back to a default
target_url = "http://192.168.1.50:3000"
inject_headers = { X-WEBAUTH-USER = "admin" }
```

Environment variables (take precedence over the config file):

| Variable | Purpose |
| --- | --- |
| `ASMODAY_CONFIG_PATH` | Config file path |
| `ASMODAY_DATA_DIR` | Data directory |
| `ASMODAY_HOST` / `ASMODAY_PORT` | Listen address and port |
| `ASMODAY_FFMPEG_PATH` | FFmpeg path |
| `ASMODAY_RESET_PASSWORD` | Non-interactive reset with `--reset-password` (remove it afterwards) |

## CLI

| Command | Description |
| --- | --- |
| `asmoday --init` | Write the default config file and exit; no server, no database, no credentials (start normally to get the one-time admin password) |
| `asmoday --reset-password` | Reset the admin password, print a one-time new one |
| `asmoday --reset-2fa` | Clear the TOTP secret and disable 2FA (requires the current password) |
| `asmoday --check-config` | Validate the config and exit without starting the server |
| `asmoday --backup ./asmoday-backup.db` | Write a consistent database copy and exit (works while running) |
| `asmoday -c ./config.toml -d ./data -p 4242 -H 0.0.0.0` | Custom config, data directory, port and address |

## WebDAV

Add the server in your file manager, Cyberduck, rclone or a phone sync app:

- URL: `http://<host>:4242/dav/` (`/dav/` lists the mounts visible to the credentials)
- Username: the **token name**; password: the `asm_…` token itself. Create tokens under Settings → Security — each can be tied to a single mount, set read-only, given an expiry date and revoked at any time.
- The admin login password is **not** accepted over WebDAV. A client that used it before will get `401` until you create a token.
- Methods: `OPTIONS`, `PROPFIND`, `GET`, `HEAD`, `PUT`, `DELETE`, `MKCOL`, `MOVE`, `COPY`, `LOCK`, `UNLOCK`

## FAQ

**I forgot my password.**
Run `asmoday --reset-password` on the server — there is no passwordless backdoor in the config. Lost your TOTP device? `asmoday --reset-2fa`.

**My WebDAV client suddenly returns `401`.**
WebDAV accepts tokens only. Create one under Settings → Security, set the client's username to the token name and the password to the `asm_…` token. The admin login password is rejected by design, and deleting or expiring a token cuts existing clients off immediately.

**Other devices on my LAN cannot connect.**
The default listens on loopback only (`[server].host = "127.0.0.1"`). Set it to `0.0.0.0` (or `::`) and allow the port in the firewall; keep `127.0.0.1` behind a reverse proxy.

**The port is already in use.**
Override it with `asmoday -p 8080`, or change `[server].port`.

**A video will not play.**
Playback is decoded by the browser; there is no transcoding. Whether HEVC / AV1 works depends on the browser and the system decoders.

**Thumbnails stay as placeholders.**
Video covers need an external FFmpeg — set `ffmpeg_path` or put `ffmpeg` on `PATH`. Image thumbnails do not need it.

**Copy or move says it exceeds the limit.**
The default cap is 100 selected items and 2 GiB per operation, adjustable under `[server.limits]`. Larger jobs belong in the terminal with `cp` / `mv`.

**Where is my data, and how do I back it up?**
Everything lives in the data directory: `data/asmoday.db` (account, sessions, shares, index), `data/logs/`, `data/thumbnails/`. Use `asmoday --backup` or the settings page for a consistent copy while running.

**Multiple users? Can I undo a delete?**
No multi-user support: one admin account per instance. Deletes are physical and there is no recycle bin. Deleted shares keep a 30-day tombstone so old links return `410`.

## Tech stack

| Layer | Technology |
| --- | --- |
| Backend | Rust 2024, axum 0.8, tokio, rusqlite (bundled, WAL) |
| Terminal | portable-pty + xterm.js (ConPTY mitigation, keep-alive) |
| Media | External FFmpeg (frame grabs only), lofty (audio tags), Video.js |
| WebDAV | dav-server (protocol) + custom auth and boundary checks |
| Frontend | Vue 3.5, Vite, Tailwind CSS v4, CodeMirror 6, vue-i18n |
| Packaging | rust-embed for the UI; GitHub Actions builds three targets |

## Development

```bash
# Frontend (hot reload)
cd web && pnpm install && pnpm run dev     # http://localhost:5173

# Backend
cargo run                                   # http://127.0.0.1:4242

# Release build (embeds web/dist)
cd web && pnpm run build && cd .. && cargo build --release
```

Test flow (gate levels, probe suite, data/artifact rules) is kept with the local
design notes and is not part of the repository.

Before submitting, run the same gates CI uses:

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cd web && pnpm exec vue-tsc -b && pnpm run build
```

Layout:

```
src/            Rust backend (api/ routes and handlers, core/ config, auth, filesystem, logging)
web/            Vue 3 frontend (views/, components/, locales/)
.github/        release workflow (triggered by v* tags)
```

## Contributing

Issues and pull requests are welcome. Before you open one:

1. Discuss larger changes in an issue first, so nobody wastes work;
2. Pass the gates above and add tests for new behaviour;
3. Keep UI strings in `vue-i18n` — no hardcoded Chinese or English in components;
4. Use `type(scope): summary` commit messages, e.g. `fix(player): correct bar height`.
